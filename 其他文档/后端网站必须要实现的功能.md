**完整链路请求：**  SpringBoot 接收请求 → 参数校验 → 登录鉴权 (JWT) →会话管理 → 业务逻辑 → 调用数据库 → 返回结果，全局异常处理→ 返回前端渲染

**完整响应链条**：

```
前端请求
  → Nginx 反向代理 + 跨域处理
  → 过滤器链：字符编码 → CORS → 请求体重复读
  → 拦截器：JWT 鉴权 → Redis 校验 Token 有效性 → 获取当前用户
  → AOP 切面：操作日志记录 → 接口限流校验 → 幂等令牌校验
  → Controller 层：参数校验（@Valid） → 接收请求 → 调用 Service
  → Service 层：业务逻辑处理 → 事务控制 → 读写 Redis 缓存 → MySQL
  → Mapper 层：MyBatis-Plus 操作 MySQL → 数据返回
  → 结果封装：统一 Result<T> 包装 → 异常统一捕获转换
  → 响应返回前端
```

## 一、基础框架 & 请求处理（必做）

1. **HTTP 接口接收请求**（RestController）

2. **入参校验**：`@Valid`、非空、长度、格式校验，拦截非法参数

3. 全局异常处理

   ```
   @RestControllerAdvice
   ```

   - 业务异常、系统异常、LLM 调用异常统一捕获
   - 统一返回格式：`{code,msg,data}`，不要直接抛堆栈给前端

4. **跨域 CORS 配置**，适配 Vue/React 前端

5. 接口日志拦截器

   - 记录：用户 ID、请求 URL、入参、响应、耗时、IP

6. 接口限流防刷

   - 按用户 / IP 限流，尤其 LLM 接口，防止恶意调用消耗 token；Sentinel / Redis + AOP

7. **全局异常处理**：统一异常捕获、统一错误码、统一返回体

   - 异常分层：参数校验异常、业务异常、权限异常、第三方调用异常、系统未知异常
   - 统一错误码：按模块定义错误码（如 10xxx 用户模块、20xxx 订单模块），附带错误信息与解决方案提示
   - 实现方式：`@RestControllerAdvice` + 自定义业务异常类 `BusinessException`
   - 异常日志：完整打印异常栈 + 请求链路 ID，方便排查

8. **统一返回封装**（你项目里`ApiResponse`就是这个）、全局参数解析

9. **分页、排序通用组件**

10. **字典管理**：系统字典、业务字典（状态码、枚举映射，前后端统一）

11. **定时任务调度**：任务新增、启停、执行日志、失败重试

12. **文件通用服务**：文件上传、下载、预览

13. **国际化多语言（可选，看业务）**

## 四、业务逻辑层（以你的 LLM 对话网站举例）

**Controller：接收前端请求，做参数接收、调用 Service、组装返回结果，不写复杂业务。**

 **Service：专门写业务规则、流程、业务计算，是整个系统的核心 接口。** 

**Serviceimpl 实现功能**

 **Mapper：只负责和数据库打交道，只做增删改查，不写业务。**

1. **业务流程编排（最核心）**

   ```
   1. 根据用户名查询用户（调用 mapper）
   2. 判断用户是否存在、账号是否被禁用
   3. BCrypt 校验密码
   4. 生成 token 存入 Redis
   5. 记录登录日志
   
   > 
   > 这一串判断、先后顺序，全部写在 Service，Controller 只调用一行 `userService.login()`。
   
   以你的**LLM 对话 RAG 系统**举例，对话的 Service 内部要完成：
   
   1. 校验该用户是否有权限使用大模型
   2. 查询数据库，读取该会话历史消息
   3. 做上下文裁剪，防止 token 超长
   4. 调用 FlagEmbedding 向量化用户提问
   5. 调用向量库检索知识库片段
   6. 把检索结果 + 用户历史 + Prompt 模板组装完整提示词
   7. 调用外部 LLM 接口（SSE 流式调用）
   8. 保存提问和回答记录到数据库
   9. 统计 token 消耗计数
   
   👉 一整套业务流程全部放在 Service。
   ```

2. **业务规则、各种判断校验**  

   > 注意：简单参数校验放在 Controller 用 @Valid；**业务规则校验写 Service**

   例子：

   - 用户修改密码：校验旧密码是否正确，新密码不能和旧密码一样
   - LLM 对话：判断用户今日调用次数是否已经超限
   - 知识库：文档数量是否超出该用户最大限额，不允许上传 0 字节文件
   - 删除会话：判断这个会话是不是属于当前登录用户，不能越权删除别人会话

3.  **事务控制 `@Transactional`** 

   多个数据库操作需要**要么全部成功，要么全部回滚**，注解加在 Service 方法上。 例：新建对话会话，同时插入会话主表 + 插入第一条消息记录；一旦失败全部回滚。

4. **调用外部资源**

- 调用第三方 LLM API
- 调用向量数据库 (Milvus)
- 调用 MinIO/OSS 文件存储
- 调用 Redis 操作缓存
- 调用其他微服务接口

> Controller 原则上不直接访问 Redis、不直接调第三方 API，交给 Service 处理。

5. **数据组装、转换、业务计算** 

   - 从 Mapper 拿到数据库 PO 对象，做业务处理，组装成 VO/DTO 返回给 Controller
   - 统计计算：统计用户 token 消耗、统计对话数量
   - 数据处理：文档文本切割、Prompt 拼接、上下文窗口裁剪

6. **调用其他 Service**

   业务之间互相调用，例如：对话业务需要记录审计日志，就调用 `operateLogService.saveLog()`。

7. **处理业务异常**

   抛出业务自定义异常（如：`UserDisableException`、`ApiQuotaExceedException`），由全局异常处理器捕获返回前端错误信息。

8. **异步任务、定时任务业务**

## 六、安全模块（生产环境必须）

1. **登录安全防护**

- 登录失败限流、账号锁定（暴力破解防护）

- 验证码（图形 / 短信 / 邮箱）、验证码防刷

2. **输入校验 & 注入防护**

- SQL 注入防护、XSS 跨站脚本过滤、请求参数统一校验、特殊字符过滤

- **CSRF 跨站请求伪造防护**
- **IP 访问控制**：黑白名单、后台管理接口 IP 限制
- **敏感操作二次校验**

- 删除、修改密码、资金、批量数据变更，需要验证码 / 身份二次确认

3. **日志审计安全**

- 安全审计日志：登录、登出、权限变更、敏感数据访问、删除操作，日志不可篡改，禁止日志打印密码、密钥等敏感信息

- AES、签名密钥统一管理，禁止硬编码密钥；密钥轮换机制

- 文件类型校验、文件大小限制、木马检测、禁止执行脚本文件、上传路径隔离

- 接口 HTTPS 强制（你只做了 AES 业务加密，底层传输还是要 HTTPS）
- 密码策略（密码复杂度、密码过期、历史密码复用禁止）

4. **全局水印、接口操作水印** 
5. **审计日志**
6. **安全防护**
   - WAF 防火墙 — SQL注入/XSS/CC防护
   - DDoS 防护 — 流量清洗/高防IP
   - 数据加密 — 传输加密/存储加密/字段加密
   - 密钥管理 — KMS/密钥轮换/硬件加密机

# 加密算法

# 企业级项目完整加密 & 哈希算法清单

> 企业项目不会只用某一个算法，**不同场景使用不同算法**，包含：密码存储、传输加密、接口签名、敏感数据存储、文件摘要、密钥派生；区分互联网通用版 + 国内国密合规版本。

## 1. 用户密码存储（单向 KDF 哈希，最重要）

> 不可逆，绝对不能用对称 / 非对称

- **通用推荐：Argon2id 优先，备选 BCrypt**
- 合规环境：PBKDF2‑HMAC‑SHA256（FIPS 要求时）

表格

| 场景         | 算法              | 数据库字段     |
| ------------ | ----------------- | -------------- |
| 账号密码哈希 | Argon2id / BCrypt | `varchar(128)` |

> ❌禁止：MD5、SHA256 直接哈希、AES、RSA 存密码。

## 2. 数据完整性、文件摘要、Token 摘要（普通哈希）

用来校验有没有被篡改，不做加密。

- **SHA‑256（SHA2‑256）** 主流
- SHA‑512 大摘要场景

> MD5、SHA1 全部淘汰，禁止企业使用。

用途：

1. 文件上传后，计算 SHA256 摘要，校验文件完整性；
2. 请求参数摘要；
3. JWT 内部哈希；
4. 敏感数据做摘要留存。

> 国密替代：**SM3**

## 3. 对称加密：业务敏感数据落库加密（可逆）

> 用于数据库里面敏感字段加密存储：手机号、身份证、证件号、隐私信息。**不是密码！密码走 Argon2id。**

- 国际通用：**AES‑256‑GCM**（GCM 模式，同时加密 + 完整性校验，优先 GCM，不要 ECB）
- 国内国密合规：**SM4**

用途：

- 用户身份证、真实姓名、银行卡等隐私字段数据库加密存储；
- 配置文件密钥加密；
- 数字信封内部加密业务报文。

> 注意：密钥不要硬编码代码，使用密钥管理服务 KMS。

## 4. 非对称加密 & 数字签名

> 公私钥，不加密大报文；主要做**签名验签、密钥交换**

1. ECC‑secp256r1 (ECDSA ES256)

    ✅现代首选，密钥短小性能高

   - JWT 令牌签名；开放平台 OpenAPI 接口签名；

2. RSA‑4096（兼容性强老系统）

   - 加密传输 AES 密钥（数字信封）；对外对接老旧第三方系统。

> RSA‑1024、2048 逐步淘汰。

1. 国密替代：**SM2**

> 重要区分：

- **加密：公钥加密，私钥解密（数字信封，传递 AES 密钥）**
- **签名：私钥签名，公钥验签（接口防篡改，身份认证）**

## 5. HTTPS 传输链路加密

这是网络层，不需要业务代码手写算法：

- TLS1.3，优先 ECC 密码套件，禁止 TLS1.0/1.1。

> 作用：浏览器到后端网络传输全部加密，防止抓包窃取。

## 📦两套完整组合方案

### 方案一：普通互联网企业（无强制国密）

表格

| 业务场景                 | 采用算法                |
| ------------------------ | ----------------------- |
| 用户密码存储             | Argon2id（备选 BCrypt） |
| 摘要、完整性校验         | SHA‑256                 |
| 数据库敏感字段加密 (AES) | AES‑256‑GCM             |
| JWT、开放 API 签名       | ECDSA ES256(ECC)        |
| 第三方对接数字信封       | RSA‑4096                |
| 网络传输                 | TLS1.3                  |

### 方案二：国内政务、金融，需要国密合规

表格

| 业务场景         | 国密算法        | 对应国际算法 |
| ---------------- | --------------- | ------------ |
| 密码存储         | PBKDF2‑HMAC‑SM3 | Argon2id     |
| 摘要校验         | SM3             | SHA‑256      |
| 敏感数据对称加密 | SM4             | AES‑256‑GCM  |
| 签名、非对称     | SM2             | ECC/RSA      |

## 企业项目各个业务环节完整流程示例

1. **用户注册** 密码 → Argon2id 单向哈希 → 存入数据库，原始密码丢弃。身份证隐私字段 AES‑256‑GCM 加密入库。
2. **HTTPS 传输** 浏览器 <TLS1.3> 网关，网络全部加密。
3. **开放 API 对外提供接口** 业务参数，服务端用私钥 ECDSA 签名；客户拿公钥验签，防篡改。
4. **内部传输大段敏感报文** 生成随机 AES 密钥加密报文；RSA 公钥加密 AES 密钥（数字信封）一起传输。
5. **文件上传** 文件计算 SHA‑256 摘要保存，用于校验文件是否被篡改。

## ❌企业项目常见错误避坑

1. 密码使用 AES/RSA 加密存储：密钥泄露，全部用户泄露；**密码必须单向 KDF 哈希**。
2. AES 使用 ECB 模式：不安全，必须 GCM/CBC；GCM 优先。
3. 使用 MD5/SHA1 做摘要，已经被破解。
4. RSA 加密大业务报文：RSA 只加密密钥，大内容交给 AES。
5. 私钥硬编码在代码、配置文件，上线泄露。企业应当接入 KMS 密钥管理服务保管密钥。

## 补充：KDF 密钥派生函数额外用途

除了存密码，还可以用 PBKDF2，由用户输入口令，派生 AES 加密密钥，用于客户端本地加密文件。

### 极简记忆

1. **存密码 → Argon2id / BCrypt（哈希‑KDF）**
2. **隐私数据加密（可解密读出） → AES‑256‑GCM（对称）**
3. **签名、交换密钥 → ECC / RSA（非对称）**
4. **校验文件、防篡改摘要 → SHA‑256（哈希）**
5. **网络传输 → TLS1.3**

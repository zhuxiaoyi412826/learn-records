## 链路

请求经拦截器 JWT 鉴权、Controller 做 DTO 参数校验，失败则全局异常返回 VO；校验通过进入 ServiceImpl，事务内保存用户提问、Redis 缓存会话，调用 LLM 并存储 AI 回复，Controller 组装 VO 返回，全局异常兜底。

> 接收请求 → 拦截器执行登录鉴权 (JWT)（鉴权失败抛异常，全局异常直接返回 VO，不进入 Service）→ Controller 接收 DTO 入参 → DTO 参数校验（校验失败抛异常，全局异常直接返回 VO，不进入 Service）→ ServiceImpl 业务实现 → DO 实体数据处理 → Mapper 操作 MySQL 保存用户提问对话记录（开启事务）→ Redis 缓存会话信息 → 业务逻辑处理（组装对话上下文）→ 调用 LLM（LLM 调用失败抛出业务异常，全局异常兜底）→ Mapper 操作 MySQL 保存 AI 回复对话记录（事务提交）→ Service 返回业务数据 → Controller 组装 VO 出参返回结果，全局异常兜底

# 项目三层缓存

> 通俗：**本地堆缓存 → 分布式 Redis 缓存 → 数据库 DB** 访问顺序：先查本地缓存 → 没有查 Redis → 没有查 DB，查到后回写缓存。 你这个 AI 聊天骨架也可以套用这套模型。

| 层级                       | 缓存位置          | 存储介质               | 特点                                                 | 适用场景                                              |
| -------------------------- | ----------------- | ---------------------- | ---------------------------------------------------- | ----------------------------------------------------- |
| **一级缓存（本地缓存）**   | 应用 JVM 堆内存， | Caffeine / Guava Cache | 进程内，速度最快；**服务重启丢失；多实例数据不一致** | 热点小数据：配置、字典、提示词模板、会话基础元信息    |
| **二级缓存（分布式缓存）** | Redis             | 内存数据库，网络 IO    | 多实例共享；持久化可选；有过期时间；网络开销         | 会话上下文、用户 token、热点业务数据、AI 聊天会话历史 |
| **三级缓存（数据库）**     | MySQL/PG          | 磁盘持久化             | 持久化，数据可靠；查询最慢；有事务                   | 原始业务数据，会话记录、消息明细，兜底存储            |

------

**完整查询流程（读流程）**

1. 请求进来，

   先查一级本地缓存 (Caffeine)

   - 命中：直接返回结果
   - 未命中：去查二级 Redis 缓存

2. 查询

   二级 Redis 缓存

   - 命中：返回数据，同时回写到一级本地缓存（可选）
   - 未命中：查询三级数据库 DB

3. 查询

   三级数据库

   - DB 查到数据：写入 Redis 二级缓存，可选写入一级本地缓存，返回结果
   - DB 查不到：返回空

**写流程（更新数据）**

> 两种策略：**更新缓存 / 删除缓存**，企业一般用「删除缓存」

1. 更新数据库 DB
2. 删除二级 Redis 缓存
3. 删除一级本地缓存

## 一、QPS / TPS 指标

| 指标                                         | 单机阈值         | 说明                                                         |
| -------------------------------------------- | ---------------- | ------------------------------------------------------------ |
| 普通接口 QPS（会话列表、查询历史、用户信息） | **峰值≤1000QPS** | GET 查询接口，CRUD 读；单机上限 300，超过会出现响应变慢      |
| AI 聊天同步接口 QPS                          | **峰值≤80 QPS**  | 受阿里百练第三方 API 限制，不要压太高                        |
| AI‑SSE 流式接口 QPS                          | **峰值≤120 QPS** | SSE 长连接，每个连接占用 Tomcat 线程；**活跃长连接上限 150** |
| TPS（写操作：创建会话、保存聊天消息）        | **峰值≤120 TPS** | 数据库写入，会话、消息入库；单机 MySQL 承载上限              |

> 说明：
>
> 1. QPS：每秒请求数；TPS：每秒完成的事务（写操作）
> 2. 大模型接口是 IO 等待，**QPS 不能按本地代码能力压，要受第三方接口限流约束**
> 3. 日常平稳运行：QPS 30‑80，TPS 10‑30；只有高峰期到达峰值。

## 二、响应时间（P95 / P99）

| 接口类型             | P95     | P99     | 备注                                  |
| -------------------- | ------- | ------- | ------------------------------------- |
| 普通 CRUD 接口（读） | ≤200ms  | ≤350ms  | Redis 命中；不走 DB                   |
| 普通 CRUD 接口（写） | ≤300ms  | ≤500ms  | 入库写操作                            |
| AI 同步聊天接口      | ≤1800ms | ≤3000ms | 包含调用阿里百练网络耗时              |
| SSE 流式接口首包     | ≤300ms  | ≤500ms  | 第一个 token 返回时间，不能长时间阻塞 |

## 三、MySQL 数据库性能指标（单机）

1. SQL 执行耗时
   - 业务 SQL：**P95 ≤150ms**
   - 禁止出现 SQL 执行 >500ms 的慢 SQL；慢查询日志阈值设置为 500ms
   - 禁止`select *`、禁止无索引查询、禁止大 offset 分页
2. 连接池（HikariCP）
   - 活跃连接使用率：**≤70%**，不允许打满连接池
   - 最大连接数：20；最小空闲 5
3. 事务要求
   - 事务执行时长：**≤100ms**；**事务内严禁调用外部 HTTP（大模型）**
4. 表规模：消息表支持千万级单表；定期归档历史冷数据。

## 四、缓存指标（三层缓存：Caffeine 本地 + Redis + DB）

### Redis 二级缓存（核心）

1. 缓存命中率 ≥80%
   - 会话查询、用户会话上下文尽量命中 Redis；低于 80% 说明缓存策略不合理，需要优化
2. Redis 单命令耗时：**P95 ≤8ms**，禁止大 key、超大会话消息存入 Redis
3. 会话消息强制截断（最大 15 轮对话），避免 value 过大；
4. Redis 内存使用率：**≤70%**，避免 Redis OOM；开启 RDB+AOF 持久化。

### Caffeine 本地缓存（一级）

- 仅存放静态配置、提示词模板；**不存放会话动态数据**
- 命中率不做强制要求，因为数据量很小；
- 本地缓存最大容量限制，防止 JVM 内存膨胀。

## 三、安全相关：XSS、SQL 注入防御

### 一、输入校验类（注入攻击防护）

1. **SQL 注入**

- 禁止拼接 SQL 字符串，使用**预编译参数化查询**
- ORM 框架（MyBatis‑Plus、JPA）避免 ${}，优先 #{}
- 最小权限数据库账号，禁止 root 业务账号

1. **XSS（虽然主要前端，但后端也要兜底）**

- 对用户输入做 HTML 转义，过滤危险标签、脚本
- 输出到页面时做转义，不要直接把用户输入原样返回

1. **命令注入**

- 避免调用系统 shell 执行用户传入参数；必须调用时使用白名单过滤参数

### 二、身份认证 & 会话安全

1. **暴力破解 / 字典攻击**

- 账号密码强度校验，密码哈希存储（BCrypt/Argon2，**禁止明文存密码**）
- 登录失败限流、IP 黑名单、验证码、账号锁定

1. **CSRF 跨站请求伪造**

- 后端校验 CSRF Token；使用 JWT 时，不要放在 Cookie 里，放请求头；
- 配置 SameSite=Strict/Lax Cookie 属性

1. **会话劫持**

- Session 设置 HttpOnly、Secure；会话超时；登录后销毁旧 Session；
- JWT 设置过期时间，支持黑名单（Redis 存作废 token）

### 三、越权漏洞（后端高频高危）

> 重点：**不能只靠前端判断权限，后端必须校验**

- **水平越权**：查询数据时，必须带上当前登录用户 ID 做条件，不能只拿前端传过来的 id 查询
- **垂直越权**：接口调用前校验角色权限，判断是否拥有该接口操作权限

> 示例：`/user/info?id=100`，不能直接查 id=100，要校验当前登录用户是否允许访问该 id

### 四、文件上传漏洞

- 校验文件后缀、文件头魔数，禁止上传可执行脚本（jsp/php 等）
- 文件存储不要存到 web 可访问目录，使用对象存储 MinIO/OSS；重命名文件，防止路径遍历

### 五、DDoS / CC 攻击防护

- 接口限流：Redis 实现接口 QPS 限流、IP 限流
- 网关层（Spring Cloud Gateway）做流量控制；
- 业务层避免无缓存的重查询，防止大量请求打数据库；
- 外部配合云服务商 DDoS 防护

### 六、业务逻辑漏洞

1. 防止重放攻击：请求携带 nonce 随机数 + 时间戳，Redis 校验，拒绝重复请求
2. 防止金额篡改：服务端重新计算金额，**不能信任前端传过来的金额**
3. 防止参数篡改：敏感参数后端重新计算校验

### 七、其他安全

1. **接口返回信息脱敏**：不要返回完整手机号、身份证、密码等敏感信息
2. 错误信息不要返回详细堆栈，统一返回友好提示，避免泄露框架、版本信息
3. 依赖组件安全：定期扫描依赖漏洞（Dependency‑Check、Snyk），升级存在 CVE 的组件
4. 避免路径遍历：文件路径参数做白名单校验，不要直接拼接用户输入路径

# GithupActions

**一般指：本地缓存 → Redis 分布式缓存 → 数据库 MySQL** 

## 三层缓存

查询数据 → 先查本地缓存 → 命中直接返回；未命中查Redis → 命中返回；未命中查MySQL → 回写到Redis+本地缓存，返回数据

| 层级                       | 存储位置                   | 特点                                               |
| -------------------------- | -------------------------- | -------------------------------------------------- |
| **一级缓存（本地缓存）**   | JVM 内存（Caffeine/Guava） | 速度最快，服务重启丢失，仅本机生效；适合热点小数据 |
| **二级缓存（分布式缓存）** | Redis                      | 多实例共享，速度快，持久化可选；业务最常用         |
| **三级缓存（持久化存储）** | MySQL 数据库               | 永久落地存储，速度最慢，数据源                     |

> 区分：**开发环境**方便调试；**生产环境**只输出必要日志，禁止打印敏感信息，日志要可排查、可归档。

## 一、SpringBoot 应用日志（SLF4J+Logback，默认）

### 1）框架日志（SpringBoot 自带）

- Spring、SpringMVC、MyBatis、Mybatis‑Plus、Feign、Redis、Dubbo 等框架内部日志
- 级别：`INFO`生产；`DEBUG`开发

> 框架日志不要全开 DEBUG，生产会大量刷屏。

### 2）自定义业务日志（自己代码打印）

使用`org.slf4j.Logger`打印：

- **INFO**：正常业务流程，关键操作（用户登录、发起 LLM 调用、保存对话记录）
- **WARN**：非致命异常，业务告警（LLM 调用重试、参数异常、缓存未命中）
- **ERROR**：业务错误（DB 异常、LLM 调用失败、鉴权失败）
- **DEBUG**：开发调试用，**生产关闭**

> ✅规范：禁止打印密码、token、用户隐私；日志包含 traceId 链路追踪，方便定位请求。

### 3）请求链路日志

- 打印：请求入参 DTO、响应 VO、耗时、traceId、异常堆栈；
- 可使用`AOP`拦截所有接口打印请求响应日志。

------

## 二、JVM 日志（JVM 虚拟机输出，独立文件，不属于 Spring 应用日志）

> 生产必须开启，排查 OOM、GC、内存泄漏、线程死锁。 需要 JVM 启动参数配置输出到文件：

1. **GC 日志**：GC 回收详情，查看停顿时间、内存使用
2. **堆 dump 日志**：OOM 时自动 dump 堆快照，用于 MAT 分析内存溢出
3. **线程 dump 日志**：线程快照，排查死锁、线程阻塞
4. **JVM 错误日志**：`hs_err_pid.log`，JVM 崩溃时生成

> 开发环境可以关闭；**生产环境强制开启**。

## 三、数据库日志（MySQL，数据库侧，不是 Spring 打印）

1. **通用查询日志 general_log**：记录所有 SQL，**生产禁止开启，性能损耗巨大**，仅开发调试。
2. **慢查询日志 slow_query_log**：记录执行超时 SQL，**生产必须开启**，定位慢 SQL。
3. **错误日志 error_log**：MySQL 服务报错、连接异常，生产必开。

> SpringBoot 中 MyBatis/Mybatis‑Plus 可以打印**SQL 执行日志**（应用层打印 SQL），开发 DEBUG 输出 SQL；生产关闭 SQL 打印，防止日志膨胀。

## 四、生产环境额外日志（容器 / 服务器层面）

1. **容器日志（Docker/K8s）**：容器 stdout/stderr 标准输出，采集到 ELK/Loki 日志平台
2. **系统日志**：服务器 syslog，进程崩溃、磁盘满等系统层面问题

## 五、开发环境 vs 生产环境日志配置对比

表格

| 日志类型                  | 开发环境 (dev)               | 生产环境 (prod)                         |
| ------------------------- | ---------------------------- | --------------------------------------- |
| 应用根日志级别            | DEBUG                        | INFO                                    |
| 框架日志 (Spring/MyBatis) | DEBUG，打印 SQL              | INFO，关闭 SQL 打印                     |
| 业务自定义日志            | DEBUG/INFO，完整打印入参出参 | INFO/WARN/ERROR，禁止打印敏感字段       |
| 请求链路日志              | 打印完整 DTO、VO             | 只打印 traceId、耗时、关键参数，脱敏    |
| JVM GC 日志               | 可关闭                       | 必须开启，输出 GC 日志，OOM dump        |
| MySQL 慢查询日志          | 关闭                         | 开启，阈值如 200ms                      |
| MySQL 通用日志            | 可开启调试                   | 严禁开启                                |
| 异常堆栈                  | 完整打印堆栈                 | ERROR 级别打印堆栈，WARN 不打印完整堆栈 |

## 六、企业日志规范要点

1. 日志文件按**大小 / 时间滚动**，自动归档，防止磁盘占满；
2. 必须携带 **traceId**，一个请求从头到尾唯一标识，方便串联链路；
3. 禁止输出密码、token、手机号等敏感信息；
4. 生产不要开启大量 DEBUG 日志，避免日志爆炸；
5. 应用日志、JVM 日志、数据库日志分开存放，不要混在一起；
6. 生产日志统一采集（ELK/Loki），做日志检索告警。

## 七、简单总结一句话

> 开发：全开 DEBUG，打印框架 SQL、完整业务入参、JVM 调试日志； 生产：应用日志 INFO 级别，关闭 SQL 打印，开启 JVM GC + 堆 dump、MySQL 慢查询，打印 traceId 链路日志，敏感信息脱敏，异常堆栈只在 ERROR 输出。

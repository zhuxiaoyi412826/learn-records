### 接口契约

**OpenAPI 3（简称 OAS3）是一套标准化的接口描述规范**，用 JSON / YAML 文件，把 RESTful API 的全部信息完整描述出来，这份文件就叫**接口契约**。

> 通俗理解： 把接口的「接口地址、请求方式、请求头、请求参数、字段类型、枚举、响应体、错误码、示例」全部写成一份机器可读的配置文件。 **人和机器都能读这份文件，它就是接口的合同。**

写完 OpenAPI 契约，直接启动 Mock 服务，前端直接请求 Mock 地址做开发联调。

Swagger‑Codegen

**OpenAPITools/openapi‑generator**  （输入一份 OpenAPI3 yaml/json 契约文件）

输出 

1. 服务端桩代码（Server stub）
   - Java Spring：生成 Controller 接口骨架、DTO 实体类（Jakarta 包，适配 SpringBoot4）
   - ⚠️只生成接口定义、入参出参 Model，**业务逻辑需要自己实现，不会生成业务代码**
2. 客户端 SDK（Client）
   - TypeScript‑axios：TS 类型 + axios 请求函数（前端直接用）
   - Java、Go、Python 等各语言调用 SDK
3. 还可以生成：接口文档、配置文件、postman 集合等CSDN博...

| 工具              | Java Controller/DTO | TS+Axios | CI 流水线自动化 | 适用场景                                       |
| ----------------- | ------------------- | -------- | --------------- | ---------------------------------------------- |
| OpenAPI‑Generator | ✅                   | ✅        | ✅               | 后端项目 Maven 插件，CI 流水线，企业自动化首选 |
| Apifox            | ✅                   | ✅        | ❌弱             | 团队协作，界面编辑契约，快速预览               |
| Orval             | ❌                   | ✅        | ✅               | 前端工程内 npm 脚本，前端优先                  |

### ① 开发前先定义接口（契约优先 / API‑First）

> 先写接口契约（OpenAPI3），再写后端代码。 **怎么做：**

1. 产品 / 后端 / 前端一起评审，确定入参、出参、错误码、枚举；
2. 使用 OpenAPI (Swagger)、Apifox、ApiFox、YAPI 编写接口契约；
3. 评审通过，导出 OpenAPI 3.x json/yaml；
4. 通过代码生成器，直接生成后端 DTO、接口抽象接口、前端 TS 类型；
5. 后端再去实现这个已经定义好的接口。

✅优点：

- 前后端可以并行开发，后端还没写代码，前端就可以基于契约 mock 调试；
- 接口变更必须走评审，接口契约是需求的一部分；
- 文档是需求，不是代码的附属产物。

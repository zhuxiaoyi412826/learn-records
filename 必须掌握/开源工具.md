## 功能

注意：`build`、`watch` 是构建命令；其余所有查询命令，必须先执行过一次 `graphify build ./` 生成 `graphify-out/graph.json` 才能运行。

| 命令                | 说明                                                         | 示例                |
| ------------------- | ------------------------------------------------------------ | ------------------- |
| `graphify build ./` | 构建整个项目图谱，生成 graph.json、graph.html、GRAPH_REPORT.md | `graphify build ./` |
| `graphify watch ./` | 监听文件变更，**增量自动更新图谱**，改代码自动重新 build，不用反复手动 build | `graphify watch ./` |

| MCP 工具名      | CLI 命令                                | 参数说明                                                     | 用途                                                        |
| --------------- | --------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- |
| `query_graph`   | `graphify query`                        | `--query "自然语言描述" --traversal bfs|dfs --max-depth N --token-budget X` | 自然语言遍历图谱，BFS/DFS，控制 token 预算                  |
| `get_node`      | `graphify node <node_id>`               | node_id：类 / 函数 / 文件节点 ID                             | 获取类、函数完整元数据，源码片段、注释、docstring、文件路径 |
| `get_neighbors` | `graphify neighbors <node_id>`          | `--direction in|out|both`                                    | 获取直接上下游调用关系（一阶邻居）                          |
| `shortest_path` | `graphify path <source_id> <target_id>` | 源节点 ID，目标节点 ID                                       | 求 A 到 B 最短调用 / 依赖路径                               |
| `get_community` | `graphify community <community_id>`     | community_id：Leiden 聚类社区 ID                             | 获取同一子模块 / 社区全部节点                               |
| `god_nodes`     | `graphify god-nodes`                    | `--top N` 输出前 N 个枢纽节点                                | 项目核心枢纽节点，高被调用的类 / 函数                       |
| `graph_stats`   | `graphify stats`                        | 无额外参数                                                   | 图谱统计：节点数、边数、社区模块数量                        |

> Graphify：本地优先、Apache‑2.0 开源，把任意文件夹（代码、文档、图片、音视频）构建知识图谱，多用于 AI 编码助手（Claude Code / Cursor），大幅降低大模型 Token 消耗（最高 71.5 倍）。
>
> 

## 一、多模态文件解析能力

### 1. 代码解析（本地 Tree‑Sitter，**不需要大模型**）GitHub

- 支持 29 种编程语言：Python/TS/JS/Go/Rust/Java/C/C++/C#/PHP/Kotlin/Scala/Elixir 等
- 提取：类、函数、方法、导入依赖、函数调用图、docstring、注释设计动机
- SQL 专项解析：表、视图、外键、JOIN 关系

### 2. 文档文本

- Markdown、TXT、RST、PDF 论文
- Office 文档：docx/xlsx（额外依赖）

### 3. 图像

- 截图、流程图、白板照片，调用 Claude Vision 提取概念、实体、关系

### 4. 音视频

- faster‑whisper 本地语音转文字，生成转录文本再做图谱抽取，转录结果缓存复用GitHub

## 二、图谱构建与分析核心能力

1. 双引擎图谱合并
   - 确定性 AST 结构边 + LLM 语义推理边合并为 NetworkX 图结构
2. Leiden 社区聚类
   - 按拓扑自动划分子系统 / 模块，**不依赖 Embedding 向量**，识别代码库子模块、文档主题分组graphify.h...
3. God Node（枢纽节点）识别
   - 自动找出项目高耦合核心文件 / 核心概念（架构重心）
4. Surprise 意外连接检测
   - 挖掘跨模块、跨文件隐藏的非直观关联，发现潜在技术债务、异常依赖
5. 路径查询 Path Query
   - 查询两个节点之间完整关联链路，溯源依赖与设计链路
6. **可审计追踪**：完整提取审计日志，每一条边 / 节点记录来源文件、提取方式

## 三、增量与实时工作流

1. **增量重提取**：只处理变更文件，无需全库重建，大幅提速
2. **Watch 监听模式**：监控文件夹，文件修改自动更新图谱（live rebuild）
3. **聚类重跑模式**：只重新做社区聚类，不重新解析文件，调试分组效果

## 四、输出产物（一次运行生成 3 种核心产物）稀土掘金

1. **graph.html**：独立交互式可视化网页，浏览器直接打开，拖拽缩放、点击节点、筛选边
2. **graph.json**：GraphRAG 可用完整图数据，可导入其他图引擎做二次开发
3. **GRAPH_REPORT.md**：人类可读项目分析报告：模块划分、枢纽节点、异常连接、架构总结

### 额外导出格式

- SVG、GraphML、可直接推送 Neo4j 图数据库
- Obsidian Vault 输出：直接生成 Obsidian 双向链接笔记库
- Wiki 静态站点生成：索引页 + 每个聚类社区独立文章

## 五、AI Agent 集成能力

1. **MCP stdio 服务**：作为 MCP 服务端，给 Claude Code 等 AI 助手提供图谱工具调用；Agent 可以查询依赖、查找路径、检索模块信息，不需要读取全部源码文件
2. 大幅降低 Token 消耗，解决大模型读大项目上下文溢出问题

## 六、可视化交互（graph.html）

- 节点拖拽、缩放、悬停高亮关联边
- 节点搜索过滤、按社区分组着色
- 切换显示 / 隐藏孤立节点
- 节点大小、连线距离、连线粗细可调
- 跳转回原始源文件定位

## 七、运行模式

1. **本地 CLI 模式**：命令行运行，完全本地解析代码；图像 / PDF 需要 Claude API
2. **AI 助手 Skill 模式**：Claude Code 内直接输入 `/graphify` 一键执行
3. **网页上传模式**：上传 zip 包，浏览器云端运行，无需本地 Python 环境

## 八、隐私安全

- 默认无遥测，不上传源码；代码 AST 解析完全本地执行；仅图片 / PDF / 文档会调用 Claude API；支持离线模式（仅代码解析）

## 九、典型使用场景

1. 接手大型遗留代码库快速理解架构
2. 代码审查，发现隐藏跨模块依赖
3. 论文、笔记混合资料库构建知识图谱
4. 给 AI Agent 提供结构化项目索引，提升大模型理解项目能力
5. 团队共享架构图谱报告

# Npm pnpm Bun

**npm install**

Node.js**官方内置**包管理器，JavaScript 生态标准，跟随 Node.js 一同安装，仅负责依赖管理，运行代码依旧依靠 Node.js 内核。

**bun install**

Bun 一体化工具内置的包管理器，Bun 基于**Zig 语言**从零开发，集**包管理器 + JS/TS 运行时 + 打包器 + 测试工具**于一体，可完全替代 Node.js 执行脚本。

```
# 初始化新项目
bun init

# 安装全部依赖 = npm install
bun install

# 安装生产依赖 = npm i xxx
bun add xxx

# 开发依赖 = npm i -D xxx
bun add -d xxx

# 卸载依赖
bun remove xxx

# 执行 package.json 脚本
bun run dev

# 临时运行包 npx
bunx xxx

# 升级 Bun 本身
bun upgrade
```

| 冷安装（首次下载无缓存） | 中大型项目 30~120s | 1~5s        | **20~30 倍提速** |

该命令作用：**连接本地 MySQL 数据库 algoviz，自动抓取表结构、字段、索引、外键，生成网页版数据库设计文档**。

```
1. 程序启动段
java -jar schemaspy-app.jar
java：调用本机 Java 虚拟机；
-jar：执行 Java 打包后的 jar 程序；
schemaspy-app.jar：SchemaSpy 主程序包，用来解析数据库、生成结构化 HTML 文档。
2. 数据库类型与 JDBC 驱动配置
-t mysql
-t = type，指定数据库方言类型；
mysql：代表当前要连接 MySQL 数据库。
-dp mysql-connector-java-8.0.23.jar
-dp = driver path，指定 JDBC 驱动文件路径；
mysql-connector-java-8.0.23.jar：MySQL 官方 Java 连接驱动，SchemaSpy 本身不带驱动，必须手动提供才能和 MySQL 建立通讯；
驱动放在 jar 同目录，直接写文件名即可，无需填写完整路径。
3. 数据库连接核心参数
-host 127.0.0.1
数据库服务器 IP，127.0.0.1 代表本机本地 MySQL 服务。
-db algoviz
指定目标数据库名称，本次要解析的库是 algoviz。
-s algoviz
-s = schema（架构）；
MySQL 中架构名默认和数据库名完全一致，必须显式声明，否则工具无法定位数据表；
SQLServer、Oracle 架构概念与 MySQL 不同，MySQL 这里直接填库名。
-u root
-u = user，数据库登录用户名，root 是 MySQL 默认管理员账号。
-p 412826
-p = password，对应登录账号的数据库密码。
-o d
-o = output，指定文档输出文件夹；
执行结束后，所有 HTML、图片、js、ER 图都会生成在当前目录下的d文件夹内。
4. 连接属性参数（-connproperties）
-connproperties serverTimezone=Asia/Shanghai;useSSL=false;allowPublicKeyRetrieval=true
-connproperties：自定义 JDBC 连接附加参数，多个参数用分号;隔开。
serverTimezone=Asia/Shanghai
MySQL8 强制要求指定时区，设置为东八区（北京时间），不配置会直接连接报错。
useSSL=false
本地开发环境关闭 SSL 加密连接；公网线上环境建议开启true，本地可关闭提速、规避证书报错。
allowPublicKeyRetrieval=true
解决 MySQL8 常见的公钥认证异常，本地连接必备参数。
```

# openapi-generator

OpenAPI 生成器能够根据提供的 OpenAPI 规范（v2、v3 版本）自动生成 API 客户端库、服务器接口实现、文档以及配置文件。根据契约文档

https://github.com/OpenAPITools/openapi-generator



maven插件方式

1. JDK 17+（maven 插件运行需要）
2. Maven 3.8+ / Node.js 18+（CLI 方式）
3. 准备好契约文件：`04‑OpenAPI3接口契约.json`

pom文件增加plugin插件

```
<build>
    <plugins>
        <plugin>
            <groupId>org.openapitools</groupId>
            <artifactId>openapi-generator-maven-plugin</artifactId>
            <version>7.24.0</version>
            <executions>
                <!-- 执行1：生成SpringBoot4后端代码（接口+DTO） -->
                <execution>
                    <id>generate-spring-boot4</id>
                    <goals>
                        <goal>generate</goal>
                    </goals>
                    <configuration>
                        <!-- 契约文件路径 -->
                        <inputSpec>${project.basedir}/src/main/resources/openapi/04‑OpenAPI3接口契约.json</inputSpec>
                        <generatorName>spring</generatorName>
                        <output>${project.build.directory}/generated-openapi/spring</output>
                        <apiPackage>com.algo.api</apiPackage>
                        <modelPackage>com.algo.dto</modelPackage>
                        <configOptions>
                            <interfaceOnly>true</interfaceOnly>
                            <useSpringBoot4>true</useSpringBoot4>
                            <useJakartaEe>true</useJakartaEe>
                            <documentationProvider>none</documentationProvider>
                            <annotationLibrary>none</annotationLibrary>
                            <additionalModelTypeAnnotations>@lombok.Data;@lombok.NoArgsConstructor;@lombok.AllArgsConstructor</additionalModelTypeAnnotations>
                            <modelNameSuffix>Dto</modelNameSuffix>
                            <openApiNullable>false</openApiNullable>
                            <generateApiTests>false</generateApiTests>
                            <generateModelTests>false</generateModelTests>
                        </configOptions>
                    </configuration>
                </execution>

                <!-- 执行2：生成TypeScript‑Axios前端代码 -->
                <execution>
                    <id>generate-ts-axios</id>
                    <goals>
                        <goal>generate</goal>
                    </goals>
                    <configuration>
                        <inputSpec>${project.basedir}/src/main/resources/openapi/04‑OpenAPI3接口契约.json</inputSpec>
                        <generatorName>typescript-axios</generatorName>
                        <output>${project.build.directory}/generated-openapi/ts</output>
                        <configOptions>
                            <withSeparateModelsAndApi>true</withSeparateModelsAndApi>
                            <modelPackage>models</modelPackage>
                            <apiPackage>apis</apiPackage>
                        </configOptions>
                    </configuration>
                </execution>
            </executions>
        </plugin>
    </plugins>
</build>

```

执行生成命令

# Locust

**Locust 是完全开源免费的压测工具**

- 仓库：https://github.com/locustio/locust
- 协议：**MIT License**，商业项目可以无限制使用、修改、二次开发
- 语言：Python，用纯 Python 代码编写压测脚本，不用写复杂 jmeter 脚本

## 核心特点

1. 分布式压测：单机不够可以多机器组成集群模拟大量并发用户
2. Web UI：自带可视化 web 界面，可以看 TPS、响应时间、错误率图表
3. 代码驱动：所有用户行为就是普通 Python 函数，支持自定义请求、断言、逻辑
4. 支持 HTTP/HTTPS，也可以扩展压测 TCP、WebSocket 等协议

![](https://zhuxiaoyi-1300958454.cos.ap-guangzhou.myqcloud.com/img/20260823023632.png)

**1.安装**

```
# 使用清华源加速
pip install locust -i https://pypi.tuna.tsinghua.edu.cn/simple

# 验证版本
locust --version
```

**2.概念**

| 概念                           | 说明                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| `HttpUser`                     | 虚拟用户类，每个实例代表一个压测用户，内置`self.client`（http 会话，自动保存 header/cookie）CSDN博... |
| `@task(权重)`                  | 标记压测任务；权重数字越大，被执行概率越高                   |
| `wait_time = between(min,max)` | 任务执行完后随机等待时间，模拟人的思考时间；`between(0,0)`代表不等待，疯狂压接口（模拟 CC 攻击） |
| `on_start()`                   | **每个虚拟用户启动时执行 1 次**，适合放登录获取 token 逻辑Locust |
| `on_stop()`                    | 虚拟用户销毁时执行 1 次，退出清理                            |
| `self.client.get/post`         | 发 http 请求，返回 response 对象；支持`.json()`、`.status_code`；`catch_response=True`手动标记成功 / 失败 |

**3.示例 1：极简脚本（oj_demo.py）**

```
from locust import HttpUser, task, between

class OJUser(HttpUser):
    # 目标地址，也可以命令行--host覆盖
    host = "http://127.0.0.1:8080"
    # wait_time = between(1,3)  #真实用户：1‑3秒思考时间
    wait_time = between(0, 0)  # 模拟CC攻击：无间隔疯狂请求

    # @task(权重)，权重越大执行概率越高
    @task(2)
    def query_problem_list(self):
        """题目列表接口"""
        self.client.get("/api/problem/list", name="problem_list")

    @task(1)
    def health(self):
        """健康检查接口"""
        self.client.get("/api/health")
```

**4.启动方式web启动  locust -f oj_demo.py**

1. **Number of total users**：总虚拟并发用户数，本地测试先填 50‑200，不要直接上万
2. **Hatch rate(ramp‑up)**：每秒新增多少用户，填 5‑20
3. **Host**：被测服务地址，脚本写了 host 这里可以空 点击`Start swarming`开始压测。

> 界面名词对照：
>
> - Requests：总请求；Failures：失败请求；RPS：QPS；Response time：响应时间 ms；Users：当前活跃用户。

> 浏览器翻译插件可以把页面翻译成中文。

**5.无头启动**

```
# -u 用户数，‑r每秒生成用户，‑t运行时间，输出html报告
locust -f oj_demo.py --headless -u 100 -r 10 -t 60s --html=oj_report.html
```

## 第一届（2023）扑克牌 24 点

> 原文来源：CSDN https://blog.csdn.net/NineData/article/details/135499445 参赛选手：李家的张麻子 (SQL Server)、郑凌云 (MySQL 冠军 0.67s) 数据规模：万行以上，决赛百万行测试集，无普通 / 进阶区分

### 表结构 `poker24.cards`

| 字段 | 类型 | 说明      |
| ---- | ---- | --------- |
| id   | int  | 主键自增  |
| c1   | int  | 数字 1-10 |
| c2   | int  | 数字 1-10 |
| c3   | int  | 数字 1-10 |
| c4   | int  | 数字 1-10 |

### 业务需求

每行记录给出 4 个数字，使用 `+ - * /` 和括号构造四则表达式，结果等于 24。**4 个数字必须全部使用，且只能使用一次；禁止阶乘、幂、开方等其他运算符。**

输出字段：`id, c1, c2, c3, c4, result`

- `result`：合法计算公式字符串，有多解返回任意一个；无解返回 `NULL`。

> 思路分两类：
>
> 1. **暴力枚举打表方案（李家的张麻子，SQL-Server）**：预先枚举全部合法四元数字组合与对应表达式，将 4 个数字排序拼接为特征字符串，业务表同样将 4 个数字排序拼接特征字符串，JOIN 匹配输出表达式。
> 2. **运行时枚举全部运算符、括号组合（郑凌云 MySQL 冠军）**：CTE 生成全部运算符排列、数字排列、括号组合，实时计算过滤等于 24 的表达式。

### 打表思路参考片段（SQL-Server，公开片段，非冠军源码）

```
WITH t AS (
    SELECT k.s,k.ss FROM (
        SELECT '1118' s,'8*(1+1+1)' ss
        UNION ALL SELECT '1126','2*6*(1+1)'
        -- 省略大量预枚举组合（完整代码包含几百条UNION ALL预生成解）
    )k
),
tt AS(
    SELECT
        id,c1,c2,c3,c4,
        CASE
            WHEN c1>=c2 AND c2>=c3 AND c3>=c4 THEN CONCAT(c4,c3,c2,c1)
            WHEN c1>=c2 AND c2>=c4 AND c4>=c3 THEN CONCAT(c3,c4,c2,c1)
            WHEN c1>=c3 AND c3>=c2 AND c2>=c4 THEN CONCAT(c4,c2,c3,c1)
            -- 省略全部24种数字大小排序分支
        END gs
    FROM poker24.cards
)
SELECT tt.id,tt.c1,tt.c2,tt.c3,tt.c4,t.ss AS result
FROM tt
LEFT JOIN t ON tt.gs = t.s;
```

### 运行时枚举完整参考解（MySQL 8.0+，可直接运行）

> 思路：4 个数字全排列（≤24 种）× 3 个运算符（4³=64 种）× 5 种括号结构，共 ≤7680 种表达式逐一遍历，命中 24 即输出。除零用 `NULLIF` 屏蔽（NULL 结果自动被过滤）。

```sql
WITH
ops AS (
    SELECT '+' AS op UNION ALL SELECT '-' UNION ALL SELECT '*' UNION ALL SELECT '/'
),
op3 AS (                                    -- 64 种运算符组合
    SELECT a.op AS o1, b.op AS o2, c.op AS o3
    FROM ops a CROSS JOIN ops b CROSS JOIN ops c
),
idx AS (
    SELECT 1 AS i UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4
),
perm AS (                                   -- 每行 4 个数字的全排列（≤24 种）
    SELECT s.id,
           ELT(i.i, s.c1, s.c2, s.c3, s.c4) AS a,
           ELT(j.i, s.c1, s.c2, s.c3, s.c4) AS b,
           ELT(k.i, s.c1, s.c2, s.c3, s.c4) AS c,
           ELT(l.i, s.c1, s.c2, s.c3, s.c4) AS d
    FROM poker24.cards s
    CROSS JOIN idx i CROSS JOIN idx j CROSS JOIN idx k CROSS JOIN idx l
    WHERE (i.i-j.i)*(i.i-k.i)*(i.i-l.i)*(j.i-k.i)*(j.i-l.i)*(k.i-l.i) <> 0
),
calc1 AS (                                  -- 第一层：ab、bc、cd 三个相邻二元组
    SELECT p.id, p.a, p.b, p.c, p.d, x.o1, x.o2, x.o3,
           CASE x.o1 WHEN '+' THEN p.a+p.b WHEN '-' THEN p.a-p.b
                     WHEN '*' THEN p.a*p.b ELSE p.a/NULLIF(p.b,0) END AS ab,
           CASE x.o2 WHEN '+' THEN p.b+p.c WHEN '-' THEN p.b-p.c
                     WHEN '*' THEN p.b*p.c ELSE p.b/NULLIF(p.c,0) END AS bc,
           CASE x.o3 WHEN '+' THEN p.c+p.d WHEN '-' THEN p.c-p.d
                     WHEN '*' THEN p.c*p.d ELSE p.c/NULLIF(p.d,0) END AS cd
    FROM perm p CROSS JOIN op3 x
),
calc2 AS (                                  -- 第二层：四种中间组合
    SELECT f.*,
           CASE f.o2 WHEN '+' THEN f.ab+f.c WHEN '-' THEN f.ab-f.c
                     WHEN '*' THEN f.ab*f.c ELSE f.ab/NULLIF(f.c,0) END AS ab_c,
           CASE f.o1 WHEN '+' THEN f.a+f.bc WHEN '-' THEN f.a-f.bc
                     WHEN '*' THEN f.a*f.bc ELSE f.a/NULLIF(f.bc,0) END AS a_bc,
           CASE f.o3 WHEN '+' THEN f.bc+f.d WHEN '-' THEN f.bc-f.d
                     WHEN '*' THEN f.bc*f.d ELSE f.bc/NULLIF(f.d,0) END AS bc_d,
           CASE f.o2 WHEN '+' THEN f.b+f.cd WHEN '-' THEN f.b-f.cd
                     WHEN '*' THEN f.b*f.cd ELSE f.b/NULLIF(f.cd,0) END AS b_cd
    FROM calc1 f
),
calc3 AS (                                  -- 第三层：5 种括号结构各自求值
    SELECT g.*,
           CASE g.o3 WHEN '+' THEN g.ab_c+g.d WHEN '-' THEN g.ab_c-g.d
                     WHEN '*' THEN g.ab_c*g.d ELSE g.ab_c/NULLIF(g.d,0) END AS v1, -- ((a o1 b) o2 c) o3 d
           CASE g.o3 WHEN '+' THEN g.a_bc+g.d WHEN '-' THEN g.a_bc-g.d
                     WHEN '*' THEN g.a_bc*g.d ELSE g.a_bc/NULLIF(g.d,0) END AS v2, -- (a o1 (b o2 c)) o3 d
           CASE g.o2 WHEN '+' THEN g.ab+g.cd  WHEN '-' THEN g.ab-g.cd
                     WHEN '*' THEN g.ab*g.cd  ELSE g.ab/NULLIF(g.cd,0) END AS v3,  -- (a o1 b) o2 (c o3 d)
           CASE g.o1 WHEN '+' THEN g.a+g.bc_d WHEN '-' THEN g.a-g.bc_d
                     WHEN '*' THEN g.a*g.bc_d ELSE g.a/NULLIF(g.bc_d,0) END AS v4, -- a o1 ((b o2 c) o3 d)
           CASE g.o1 WHEN '+' THEN g.a+g.b_cd WHEN '-' THEN g.a-g.b_cd
                     WHEN '*' THEN g.a*g.b_cd ELSE g.a/NULLIF(g.b_cd,0) END AS v5  -- a o1 (b o2 (c o3 d))
    FROM calc2 g
),
solved AS (
    SELECT id, a, b, c, d,
           CASE WHEN v1=24 THEN CONCAT('((',a,o1,b,')',o2,c,')',o3,d)
                WHEN v2=24 THEN CONCAT('(',a,o1,'(',b,o2,c,'))',o3,d)
                WHEN v3=24 THEN CONCAT('(',a,o1,b,')',o2,'(',c,o3,d,')')
                WHEN v4=24 THEN CONCAT(a,o1,'((',b,o2,c,')',o3,d,')')
                WHEN v5=24 THEN CONCAT(a,o1,'(',b,o2,'(',c,o3,d,'))') END AS result
    FROM calc3
    WHERE 24 IN (v1, v2, v3, v4, v5)
)
SELECT c.id, c.c1, c.c2, c.c3, c.c4, MIN(s.result) AS result
FROM poker24.cards c
LEFT JOIN solved s ON s.id = c.id
GROUP BY c.id, c.c1, c.c2, c.c3, c.c4;
```

样例数据验证：`(1,2,3,4)→1*2*3*4`、`(5,5,5,5)→5*5-5/5`、`(1,1,1,8)→8*(1+1+1)`、`(1,3,4,6)→6/(1-3/4)`、`(1,5,5,5)→5*(5-1/5)` 均可命中。

> 两个性能与正确性要点：
>
> 1. **除法精度**：MySQL DECIMAL 除法默认保留 4 位小数（`div_precision_increment`），遇到 `1/3` 这类无限小数会截断丢解。冠军级做法是把中间结果表示为**分数（分子/分母两个整数列）**一路整数运算，最后判断 `分子 = 24 × 分母`，彻底消除浮点误差。
> 2. **百万行场景**：逐行运行时枚举的开销是 `行数 × 7680`，百万行必须走打表思路——先把数字组合的解预生成为常量 CTE，线上表只做一次特征字符串等值 JOIN，这正是冠军 0.67s 的核心。

## 第二届（2024）火车票席位分配

> 原文来源：掘金 https://juejin.cn/post/74445675705799638 冠军：郭其 Oracle，评测耗时 1.184s；数据规模：初赛小批量，**进阶决赛百万行数据** 性能坑提示：`OR + BETWEEN` 范围 JOIN 会导致 Oracle 禁用 Hash Join，严重拖慢性能。

### 原始业务表

#### 表 `train` 列车表

| 字段              | 说明                              |
| ----------------- | --------------------------------- |
| train_id          | 车次唯一 ID                       |
| departure_station | 列车出发站                        |
| arrival_station   | 列车到达站                        |
| seat_count        | 列车总座位：600 / 800 /1200 /1600 |

> 业务说明：**同一趟列车的出发站、到达站固定，只能承运该起终点的乘客**；每趟列车允许生成 10% 数量的无座票。

#### 表 `passenger` 乘客表

| 字段              | 说明        |
| ----------------- | ----------- |
| passenger_id      | 乘客唯一 ID |
| departure_station | 乘客出发站  |
| arrival_station   | 乘客到达站  |

### 普通挑战（初赛）

需求：给每一位乘客匹配**同出发站、同到达站**的列车。 输出字段：`passenger_id, departure_station, arrival_station, train_id`

### 进阶挑战（八强决赛，百万数据）

在普通挑战基础上，完成座位分配：

1. 同起终点线路下，乘客按 `passenger_id` 升序编号；
2. 优先分配列车的有座座位；座位耗尽后分配无座；
3. 输出扩展字段：`coach_number`车厢号、`seat_number`座位编号；无座乘客 `seat_number='无座'`；

> 座位规则参考：每 100 个座位一个车厢；每行 5 个座位，座位后缀 A/B/C/E/F。

进阶完整输出字段： `passenger_id, departure_station, arrival_station, train_id, coach_number, seat_number`

### 进阶完整参考解（MySQL 8.0+，可直接运行）

> 思路：递归 CTE 把每趟列车展开成座位粒度记录（有座 + 10% 无座），乘客与座位各自按线路分区 `ROW_NUMBER()`，最后**序号等值 JOIN**——把范围匹配转成等值匹配，规避 `OR/BETWEEN` 导致的 Hash Join 失效。
> 座位顺序解释为"每趟车先分完有座、再上无座，坐满一辆车再上下一辆"，与"每趟列车允许 10% 无座"的业务描述一致。

```sql
WITH RECURSIVE
seq AS (
    SELECT 1 AS n UNION ALL SELECT n+1 FROM seq WHERE n < 2000   -- 覆盖最大 1600×1.1
),
seat_detail AS (                        -- 每列车展开：1..seat_count 有座，之后 10% 无座
    SELECT t.train_id, t.departure_station, t.arrival_station,
           s.n AS seat_no,
           CASE WHEN s.n <= t.seat_count THEN 1 ELSE 0 END AS is_seat
    FROM train t JOIN seq s
         ON s.n <= FLOOR(t.seat_count * 1.1)
),
seat_rk AS (                            -- 线路内全局连续编号（先按车次，车内按座号自然序）
    SELECT d.*,
           ROW_NUMBER() OVER (
               PARTITION BY d.departure_station, d.arrival_station
               ORDER BY d.train_id, d.seat_no) AS rk
    FROM seat_detail d
),
pax_rk AS (
    SELECT p.passenger_id, p.departure_station, p.arrival_station,
           ROW_NUMBER() OVER (
               PARTITION BY p.departure_station, p.arrival_station
               ORDER BY p.passenger_id) AS rk
    FROM passenger p
)
SELECT p.passenger_id, p.departure_station, p.arrival_station,
       s.train_id,
       CASE WHEN s.is_seat = 0 THEN '无座'
            ELSE CAST(FLOOR((s.seat_no - 1) / 100) + 1 AS CHAR) END AS coach_number,
       CASE WHEN s.is_seat = 0 THEN '无座'
            ELSE CONCAT(CAST(FLOOR(((s.seat_no - 1) % 100) / 5) + 1 AS CHAR),
                        ELT((s.seat_no - 1) % 5 + 1, 'A','B','C','E','F')) END AS seat_number
FROM pax_rk p
JOIN seat_rk s
  ON  p.departure_station = s.departure_station
  AND p.arrival_station   = s.arrival_station
  AND p.rk = s.rk
ORDER BY p.passenger_id;
```

座位编号规则：车内第 `n` 个座位 → 车厢号 `FLOOR((n-1)/100)+1`；车厢内排号 `FLOOR(((n-1)%100)/5)+1`；字母 `A/B/C/E/F` 按 `%5` 轮转（跳过 D，与真实车厢一致）。

> 若把"座位耗尽后分配无座"理解为**整条线路所有有座耗尽后才给无座**，只需把 `seat_rk` 的排序改为 `ORDER BY is_seat DESC, train_id, seat_no`，其余不变——两种口径一行切换。

## 第三届（2025）SQL 解数独

> 原文来源：DAMO 开发者矩阵 https://damodev.csdn.net/694a5687bf6b0e4b285db9c5.html 冠军：郑凌云 PostgreSQL，评测耗时 4.855s 两级难度：普通挑战 4×4 四宫数独；进阶 9×9 九宫数独；数据规模：普通挑战 100 行；进阶挑战 1000～100 万行

### 表结构

1. 普通挑战表 `game3.sudoku4_4`（4 宫）

   | 字段   | 说明                                 |
   | ------ | ------------------------------------ |
   | id     | 自增主键                             |
   | puzzle | 题目字符串，长度 16，`?`代表待填空格 |

2. 进阶挑战表 `game3.sudoku9_9`（9 宫）

   | 字段   | 说明                                 |
   | ------ | ------------------------------------ |
   | id     | 自增主键                             |
   | puzzle | 题目字符串，长度 81，`?`代表待填空格 |

### 游戏规则

1. **四宫数独（4×4）**：填入数字 1-4。每行、每列、每个 2×2 小宫格内数字不能重复。
2. **九宫数独（9×9）**：填入数字 1-9。每行、每列、每个 3×3 小宫格内数字不能重复。

### 业务需求

输入：`puzzle`字符串，问号代表待填充空位； 输出字段：`id, puzzle, result`

- `result`：完整解字符串，把全部 `?` 替换为正确数字，无问号。

> 样例四宫输入输出
>
> | id | puzzle            | result            |
> | -- | ----------------- | ----------------- |
> | 1  | `4?21?1?41?4?3??2` | `4321213412433412` |

> 评分权重：解题正确性 30%；性能 30%；代码创新性 20%；代码可读性 20%。

### 四宫完整参考解（MySQL 8.0+，可直接运行）

> 思路：递归 CTE 模拟深度优先搜索——状态就是"当前棋盘字符串 + 处理到的位置"。预先生成 `conflict` 互斥位置对（同行 / 同列 / 同宫），每步放数字时用**反连接（LEFT JOIN … IS NULL）**校验冲突；已填格子只按原值通过，空格尝试 1-4。深度固定 16 层，天然收敛。

```sql
WITH RECURSIVE
pos AS (
    SELECT 1 AS p UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4
    UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8
    UNION ALL SELECT 9 UNION ALL SELECT 10 UNION ALL SELECT 11 UNION ALL SELECT 12
    UNION ALL SELECT 13 UNION ALL SELECT 14 UNION ALL SELECT 15 UNION ALL SELECT 16
),
val AS (
    SELECT '1' AS v UNION ALL SELECT '2' UNION ALL SELECT '3' UNION ALL SELECT '4'
),
conflict AS (                           -- 互斥位置对：同行 / 同列 / 同 2×2 宫
    SELECT a.p AS p, b.p AS q
    FROM pos a JOIN pos b ON a.p <> b.p
    WHERE FLOOR((a.p-1)/4) = FLOOR((b.p-1)/4)                          -- 同行
       OR (a.p-1) % 4 = (b.p-1) % 4                                    -- 同列
       OR (FLOOR((a.p-1)/8) = FLOOR((b.p-1)/8)                         -- 同宫
           AND FLOOR(((a.p-1)%4)/2) = FLOOR(((b.p-1)%4)/2))
),
solve AS (
    SELECT id, 1 AS p, puzzle AS g FROM game3.sudoku4_4
    UNION ALL
    SELECT r.id, r.p + 1,
           CONCAT(SUBSTRING(r.g, 1, r.p - 1), v.v, SUBSTRING(r.g, r.p + 1))
    FROM solve r
    JOIN val v
    LEFT JOIN conflict c
           ON c.p = r.p AND SUBSTRING(r.g, c.q, 1) = v.v
    WHERE r.p <= 16
      AND (SUBSTRING(r.g, r.p, 1) = '?' OR SUBSTRING(r.g, r.p, 1) = v.v)
      AND c.p IS NULL                   -- 反连接：没有任何互斥位已填同数字
)
SELECT b.id, b.puzzle, s.g AS result
FROM game3.sudoku4_4 b
JOIN (SELECT id, MIN(g) AS g FROM solve WHERE p = 17 GROUP BY id) s
  ON s.id = b.id;
```

运行说明：棋盘字符串按行主序编号 1-16，位置 `p` 的行号 `FLOOR((p-1)/4)+1`、列号 `(p-1)%4+1`；`conflict` 涵盖三种互斥关系；MySQL 递归默认深度上限 1000（本解固定 16 层，无需调整）。

> 9×9 进阶与冠军思路：上面的朴素 DFS 在 9 宫上状态爆炸。冠军郑凌云的关键是 **MRV（最少剩余候选）剪枝**——每层优先展开候选数最少的格子，并用递归 CTE 承载状态串；这正是"算法思想移植进 SQL"的得分点。四宫解法把 `pos`/`val` 扩到 81/9、宫判定改为 3×3 后即可作为 9 宫的基线（正确但慢），在此之上再引入 MRV 才能达到秒级。

## 新拟练习题一：一条 SQL 解 N 皇后

### 赛题背景

与数独同为经典约束满足问题（CSP）：在 N×N 棋盘上放 N 个皇后，任意两个皇后不同行、不同列、不同对角线。考察递归 CTE 回溯、位运算状态压缩——与第三届一脉相承但更吃剪枝功力。

### 表结构 `game4.queens`

| 字段 | 类型 | 说明                    |
| ---- | ---- | ----------------------- |
| id   | int  | 主键自增                |
| n    | int  | 皇后数量，取值 4~8      |

### 普通挑战

表内仅一行 `n=6`。输出字段：`id, n, result`，`result` 为一个解：长度 n 的字符串，第 i 个字符表示第 i 行皇后放在第几列。多解返回任意一个。

### 进阶挑战（批量 + 性能）

表内多行，`n` 取值 4~8 混合（样例规模 1000 行，压测规模 10 万行）。要求输出**字典序最小**的解，执行耗时越短得分越高。

### 完整参考解（MySQL 8.0+ / PostgreSQL，可直接运行）

> 思路：逐行放皇后，状态压缩为三个 bitmask——列占用 `cm`、"/"对角线占用 `dm`（行列和区分）、"\"对角线占用 `em`（行列差区分）。合法性判断全部是 O(1) 位运算，不需要任何子查询，天然契合递归 CTE 的"递归项只能引用自身一次"限制。`MIN(sol)` 即字典序最小解。

```sql
WITH RECURSIVE
cols8 AS (
    SELECT 1 AS c UNION ALL SELECT 2 UNION ALL SELECT 3 UNION ALL SELECT 4
    UNION ALL SELECT 5 UNION ALL SELECT 6 UNION ALL SELECT 7 UNION ALL SELECT 8
),
place AS (
    SELECT id, n, '' AS sol, 0 AS r,
           0 AS cm, 0 AS dm, 0 AS em                    -- 列 / "/"对角 / "\"对角 掩码
    FROM game4.queens
    UNION ALL
    SELECT p.id, p.n, CONCAT(p.sol, c.c), p.r + 1,
           p.cm | (1 << c.c),
           p.dm | (1 << (p.r + 1 + c.c)),               -- 行列和：2..16
           p.em | (1 << (p.r + 1 - c.c + 9))            -- 行列差+9：恒为正
    FROM place p CROSS JOIN cols8 c
    WHERE p.r < p.n
      AND c.c <= p.n
      AND (p.cm & (1 << c.c)) = 0
      AND (p.dm & (1 << (p.r + 1 + c.c))) = 0
      AND (p.em & (1 << (p.r + 1 - c.c + 9))) = 0
)
SELECT q.id, q.n, MIN(p.sol) AS result
FROM place p JOIN game4.queens q ON q.id = p.id
WHERE p.r = q.n
GROUP BY q.id, q.n;
```

样例数据预期：`n=4 → 2413`（另一解 3142）、`n=6 → 246135`（4 个解中的字典序最小）；`n=8` 共 92 个解，留作进阶自测。

> 三个实现细节：
>
> 1. **对角线编号**："/"方向用 `行+列`（范围 2~16），"\"方向用 `行-列+9`（平移避免负数），两者都与列号一起压进位掩码，一次 `&` 判重。
> 2. **为什么不用 NOT EXISTS 子查询**：MySQL / PostgreSQL 都要求递归项中自引用只能出现在 FROM 里一次，相关子查询会被拒绝；位掩码把"查历史"变成"算位运算"，是绕开该限制的标准手法。
> 3. **性能**：n=8 的有效前缀状态只有数千个，递归深度 8，默认递归上限内秒出。想再快可按 n 分组只算一次再自关联到行（同 n 共享解），10 万行压测的关键优化。

## 新拟练习题二：一条 SQL 规划地铁最短路径

### 赛题背景

图论经典 BFS 落地到"地铁导航"业务场景，与第二届"火车票"一样自带业务味：输出人类可读的途经站序列。考察递归 CTE 模拟广度优先搜索、字符串路径携带、环剪枝。

### 表结构

#### 表 `metro.station` 车站表

| 字段         | 类型        | 说明       |
| ------------ | ----------- | ---------- |
| station_id   | int         | 车站唯一 ID |
| station_name | varchar(32) | 车站名     |

#### 表 `metro.line_station` 线路站序表

| 字段       | 类型 | 说明                       |
| ---------- | ---- | -------------------------- |
| line_id    | int  | 线路 ID                    |
| station_id | int  | 车站 ID                    |
| seq        | int  | 该车站在本线路中的顺序（相邻 seq 可双向通行） |

#### 表 `metro.trip` 出行需求表

| 字段         | 类型 | 说明         |
| ------------ | ---- | ------------ |
| id           | int  | 主键自增     |
| from_station | int  | 出发站 ID    |
| to_station   | int  | 目的站 ID    |

### 普通挑战

给定一对起终点，输出**经过站数最少**的路径。输出字段：`id, from_station, to_station, steps, path`，`path` 为途经站名用 ` -> ` 连接的字符串（含起终点），`steps` 为乘坐区间数。

### 进阶挑战（批量 + 最少换乘）

`trip` 表批量出行需求（样例 1000 行）。优化目标变为：**换乘次数最少优先，站数少次之**，输出增加 `transfers` 换乘次数与 `lines` 乘坐线路序列（如 `1号线->2号线`）。

### 普通挑战完整参考解（MySQL 8.0+，可直接运行）

> 思路：`line_station` 自连接生成无向相邻边；递归 CTE 从起点逐层扩展（等价 BFS，边权全为 1 时最先到达即最短）；`FIND_IN_SET` 检查"走过的站不再走"做环剪枝——最短路径本身不含重复站，该剪枝不丢最优解。终态用 `ROW_NUMBER()` 按 `(steps, path)` 取每个出行的第一条。

```sql
WITH RECURSIVE
edge AS (                                -- 无向相邻边（去重）
    SELECT DISTINCT x.s, x.e FROM (
        SELECT a.station_id AS s, b.station_id AS e
        FROM metro.line_station a JOIN metro.line_station b
          ON a.line_id = b.line_id AND b.seq = a.seq + 1
        UNION
        SELECT b.station_id, a.station_id
        FROM metro.line_station a JOIN metro.line_station b
          ON a.line_id = b.line_id AND b.seq = a.seq + 1
    ) x
),
walk AS (
    SELECT t.id, t.from_station, 0 AS steps,
           sn.station_name AS path,
           CAST(t.from_station AS CHAR) AS visited
    FROM metro.trip t JOIN metro.station sn ON sn.station_id = t.from_station
    UNION ALL
    SELECT w.id, e.e, w.steps + 1,
           CONCAT(w.path, ' -> ', sn.station_name),
           CONCAT(w.visited, ',', e.e)
    FROM walk w
    JOIN edge e ON e.s = w.from_station
    JOIN metro.station sn ON sn.station_id = e.e
    WHERE w.steps < 30
      AND FIND_IN_SET(e.e, w.visited) = 0
),
best AS (
    SELECT w.id, w.steps, w.path,
           ROW_NUMBER() OVER (PARTITION BY w.id ORDER BY w.steps, w.path) AS rn
    FROM walk w JOIN metro.trip t
      ON t.id = w.id AND w.from_station = t.to_station      -- 到达终点的状态
)
SELECT b.id, sf.station_name AS from_station, st.station_name AS to_station,
       b.steps, b.path
FROM best b
JOIN metro.trip t       ON t.id = b.id
JOIN metro.station sf ON sf.station_id = t.from_station
JOIN metro.station st ON st.station_id = t.to_station
WHERE b.rn = 1;
```

样例数据预期：`北站→机场` 3 站（北站->鼓楼->中心站->机场）；`南站→大学城` 3 站（南站->科技园->中心站->大学城）；`西站→港口` 4 站。

> 进阶思路要点（最少换乘版）：
>
> 1. 状态从"当前站"升级为"（当前站，当前线路）"，`edge` 保留 `line_id`；
> 2. 转移分两类：沿当前线坐一站（换乘不变）/ 在当前站换任意其他线（换乘 +1，站数不变）；
> 3. 终态排序改为 `ORDER BY transfers, steps`；剪枝除"走过的站"外可加"（站，线）状态去重"；
> 4. 性能上限：朴素递归会展开全部简单路径，竞赛级优化是按层去重（同一 `(trip, 站)` 只保留最小代价状态）——这正是这道题的"性能考点"，与数独 MRV 剪枝同一思想：**SQL 竞赛的本质是把算法的状态压缩与剪枝翻译成集合运算**。

### 适配说明

1. **PostgreSQL**：`AUTO_INCREMENT` → `GENERATED ALWAYS AS IDENTITY`（或 `SERIAL`）；`CREATE SCHEMA IF NOT EXISTS` 保留；参考解中的 `ELT(x,a,b,c)` 改为 `CASE`/`CHOOSE` 写法，`FIND_IN_SET` 用 `position(x in y)` 或数组替代；`| & <<` 位运算两者通用。
2. **Oracle**：序列 + 触发器替代自增；`CONCAT` 只支持两参数（用 `||` 拼接）；递归 CTE 需 11g R2+。
3. **SQL Server**：递归 CTE 前一条语句必须以分号结尾；`SUBSTRING` 起始下标一致（均为 1）。

### 常见问题

| 现象 | 原因与处理 |
| ---- | ---------- |
| `Recursive query aborted: recursion depth exceeded` | MySQL 递归默认上限 1000，执行前 `SET SESSION cte_max_recursion_depth = 10000;` |
| `Syntax error near 'WITH'`（SQL Server） | 递归 CTE 前一条语句缺分号，改成 `;WITH RECURSIVE ...` |
| 中文乱码 | 建库时指定 `utf8mb4`；客户端连接串加 `characterEncoding=utf8` |
| Doris 跑不了递归 CTE | 需 Doris 2.x 并开启相关功能开关，练习建议直接用 MySQL / PostgreSQL |

选型建议：**练正确性用 SQLite/DuckDB（零安装），练性能对齐用 MySQL 8.0 / PostgreSQL 的 Docker 实例**——历届冠军的耗时都是在官方评测库上调出来的，递归 CTE 的执行计划差异（尤其 Doris、SQL Server）足以让同一份 SQL 相差一个数量级，冲刺名次前务必在目标库上实测。

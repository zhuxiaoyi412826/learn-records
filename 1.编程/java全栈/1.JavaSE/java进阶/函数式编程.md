# 函数式编程

## ✨一句话定义

**函数式编程是一种编程范式，把「函数当作一等公民」；尽量使用纯函数，避免可变状态，尽量用表达式而不是语句。**

> 函数式编程是一种编程范式。核心思想是把函数作为一等公民，推崇纯函数、不可变数据、高阶函数，尽量消除副作用。Java 并不是纯函数式语言，Java8 引入 Lambda、函数式接口、Stream，支持混合式的函数式开发；写业务的时候可以用 Stream 处理集合；好处是代码简洁，减少可变状态，有利于并发；但是纯函数写 IO、数据库操作并不方便。

- **命令式编程（Imperative）**：告诉计算机**怎么做**（写一堆步骤、循环、for，修改变量），C、Java 传统写法。
- **面向对象 OOP**：把数据和行为封装进**对象**；Java、C++。
- **函数式 FP**：把**函数当成值**；侧重**做什么**，而不是一步步怎么做；Lisp、Scala、Haskell；Java8 之后引入函数式。

**面向对象抽象数据 而函数式编程抽象行为**

**纯函数式它消除了一大类并发 bug：【共享可变状态带来的数据竞争】。**

> 1. **数据竞争（race condition、竞态、修改共享变量） → 纯函数式可以消除这一类问题**

## 一个方法传入不同的数据会产生不同的结果   如果将代码传入给方法就可以控制其行为了

普通的方法：**接收数据，返回结果；输入不同的数据，得到不同结果。** 高阶函数：**除了传数据之外，还可以把一段代码（逻辑 / 函数）也当做参数传进去；以此控制这个方法内部的行为。**

### 1、普通方法 — 参数只能是数据

举例子：写一个遍历打印集合的方法，只能做固定行为「打印」

```
public static void printAll(List<Integer> list){
    for(Integer num : list){
        System.out.println(num); //行为写死了，只能打印
    }
}
```

👉 只能改变输入的数据 list；**内部的行为是硬编码写死，改不了。** 不管你传什么数据，循环里面永远执行打印。

### 2、把代码（逻辑）作为参数传进去 → 就可以控制内部行为

现在，不再把行为写死。我们接收一段行为作为参数（Java 里用函数式接口） `Consumer<Integer>` 就代表一段可以执行的代码逻辑。

```
//接收【数据list】 + 接收【一段行为逻辑action】
public static void forEach(List<Integer> list, Consumer<Integer> action){
    for(Integer num : list){
        action.accept(num); //执行传进来的那段代码！行为由外部传入决定
    }
}
```

调用的时候，**传入不同的 lambda（代码片段），同一个 forEach 方法，就表现出完全不一样的行为**

```
List<Integer> data = List.of(1,2,3,4);

//传入逻辑：打印
forEach(data, n -> System.out.println(n));

//传入逻辑：求平方输出
forEach(data, n -> System.out.println(n*n));

//传入逻辑：存到别的集合
List<Integer> result = new ArrayList<>();
forEach(data, n -> result.add(n));
```

> 💡关键点对比

- 传**数据**：控制**处理什么值**
- 传**函数 (代码片段)**：控制**怎么处理这个值**

### 🧠联系以前的 OOP 思想：策略模式

> 在还没有 Lambda 的时候，Java 想实现同样效果，要用**策略模式**：定义接口，写不同实现类，把对象传进去。

```
interface Strategy{
    void handle(int n);
}
class PrintStrategy implements Strategy{...}
class SquareStrategy implements Strategy{...}
```

把策略对象传入方法。 👉 **Lambda + 高阶函数，可以看作策略模式的语法简化版本。不再需要单独新建一堆实现类。**

### 📌抽象视角总结（面试思路）

1. 普通函数的参数是**数据**：输入的数据改变，输出结果改变；但函数内部的处理逻辑是固定不变。
2. **高阶函数允许将行为本身（一段可执行代码、函数）作为参数传入；同一个框架方法，通过传入不同的逻辑，就改变它内部的行为。实现逻辑与循环骨架的复用。**
3. Stream 里面的`filter、map`全部都是这个思想：集合遍历循环的骨架已经写好了，你只传入判断、转换的逻辑。

```
users.stream().filter(u -> u.getAge()>18);
//filter内部遍历循环是固定骨架；lambda是外部传入的过滤行为
```

### 🗣简短口述版

> 普通方法接收的是数据，改变输入的数据得到不同结果，但是方法内部处理行为是固定的。 如果我们可以把一段代码、也就是行为本身当作参数传递给方法，那么同一个方法就可以根据传入的逻辑，动态控制内部怎么做；这就是高阶函数的思想。在 Java8 之前，这种能力一般通过策略模式接口实现；有了 Lambda 之后就可以直接传递函数，简化开发。

如果你愿意，我们接下来可以聊聊函数作为返回值。

# Lambda 表达式（Java）

## ✨基础语法格式

```
(参数列表) -> { 方法体 }
```

`->` 叫 **Lambda 箭头符号**，分隔参数和执行代码。

> 💡前提：**Lambda 必须对应一个【函数式接口】（@FunctionalInterface，只有一个抽象方法）**

## 四种简写规则（重点，面试经常写）

### 规则 1：参数只有一个，小括号 `()` 可以省略

```
//完整写法
(String s) -> {System.out.println(s);}

//简写（单个参数去掉括号）
s -> {System.out.println(s);}
```

### 规则 2：方法体只有**一行执行语句**，大括号 `{}` 可以省略；注意！**有 return 的时候 return 也要一起省略**

```
//完整写法
(int a,int b)->{ return a+b; }

//简写，一行，省略{}和return
(a,b)-> a+b
```

### 规则 3：参数的**数据类型可以省略**，编译器自动做类型推断

```
//写类型
(Integer x) -> x * 2
//省略类型
x -> x *2
```

### 规则 4：无参数！小括号不能丢，保留空括号 `()`

```
() -> System.out.println("无参数执行")
```

## 📋语法汇总表格

表格

| 情况                                        | 写法示例                              |
| ------------------------------------------- | ------------------------------------- |
| 无参数                                      | `() -> { System.out.println("hi"); }` |
| 单个参数                                    | `s -> System.out.println(s)`          |
| 多个参数                                    | `(a,b) -> a - b`                      |
| 多行方法体（不能省略大括号！return 不能省） | `(x)->{ x++; return x; }`             |

> ⚠️注意：**只有一行的时候才可以省略大括号；一旦有多行逻辑，必须写 {}，return 关键字必须写上。**

## 递归

> Java 的 Lambda 本身是匿名函数，**不能直接在 lambda 内部引用自身变量完成递归；因为变量还没有初始化完成。** 如果非要实现 lambda 递归，一般两种方式： 第一种借助数组或者 AtomicReference 做一层间接引用，先声明存储容器，之后再赋值 lambda，内部通过容器间接调用自己。 第二种就是 Y 组合子，函数式理论上的匿名递归方案；可读性很差。 同时要注意，**JVM HotSpot 没有尾递归优化，不管是普通方法递归，还是 Lambda 递归，深度大的时候都会栈溢出。实际业务开发，优先直接写普通静态递归方法，不建议强行使用 Lambda 递归。**

## 方法引用

> 方法引用`::`是 lambda 表达式的简写形式。当 lambda 里面仅仅直接调用一个已经存在的方法，没有额外业务逻辑的时候，就可以使用方法引用。一共分为四种： 第一是对象引用实例方法；第二是类引用静态方法；第三是类名引用实例方法，这种比较特殊，函数式接口的第一个参数会作为调用方法的实例对象；第四是构造方法引用，类名::new，还支持数组构造引用。 需要注意，如果 lambda 内部还包含额外的计算、判断逻辑，就不能简化为方法引用。

| 分类             | 写法                   | 说明                                                |
| ---------------- | ---------------------- | --------------------------------------------------- |
| 对象：：实例方法 | `obj::fun`             | 使用已经实例化好的对象调用成员方法                  |
| 类：：静态方法   | `ClassName::staticFun` | 调用 static 静态方法                                |
| 类：：实例方法   | `ClassName::fun`       | **第一个参数作为调用该方法的实例对象**              |
| 类::new          | `ClassName::new`       | 引用构造方法，实例化对象；也可以数组`String[]::new` |

# 函数式接口

> **有且仅有一个抽象方法的接口，就叫函数式接口。** 这个唯一的抽象方法，用来描述 Lambda / 方法引用要执行的行为。 **Lambda 表达式的类型就是函数式接口。Lambda 就是实现这个唯一抽象方法。**

⚠️关键点：

- **只能有一个抽象方法；**
- **可以拥有默认方法 (default)、静态方法 (static)；**
- **可以包含 Object 里面的 public 方法（equals、toString）不算抽象方法计数！**

# 高阶函数

高阶函数只是一个能接受函数作为参数或能把参数当返回值的函数

# 闭包（Closure）

## 📖定义

> **闭包：内层函数（Lambda）可以捕获外层方法作用域里面的局部变量；内层函数保存住了外层局部变量，即使外层方法已经执行完毕，内层函数依旧还可以访问这个变量。**

> 简单一句话：**函数可以记住并访问它词法作用域的变量，就算离开了原来的作用域。**

Java 有闭包的效果，但是是【有限闭包】，并不是完整的闭包（和 JavaScript、Scala 不一样） 内部类 闭包

# 函数组合（Function Composition）

## 📚概念

> **函数组合：把若干小粒度的函数拼装起来，生成一个全新的复合函数。一个函数输出，直接当做下一个函数的输入。**

数学写法：\(h(x)=f(g(x))\) 先执行 g，拿 g 的结果再传给 f。

思想：把复杂的运算拆成很多简单小函数；再通过组合组装业务；**复用小函数，而不是反复写逻辑**。

> 和高阶函数关系：函数组合本身就是高阶函数，接收函数，返回新的函数。

# 柯里化（Currying） & 部分求值（Partial application，部分应用）

## 📖基础概念

### 柯里化

> **柯里化：把一个接收多个参数的函数，转化成一系列只接收**单个参数**的函数，每次接收一个参数，返回新函数，直到拿到全部参数再计算结果。**

数学：原来 `f(a,b,c)` → 柯里化之后变成 `f(a)(b)(c)`

### 部分应用（部分求值）

> **部分应用：给多参函数传入一部分参数，得到一个新函数；剩下的参数后续再补。**

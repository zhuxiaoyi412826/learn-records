用「出题专家」插件（coding-problem-generator）生成20道数据结构与算法编程题。要求：4道简单难度、4道中等难度、12道困难难度。每道题都要有不同的主题和知识点，题目名称不能与已有题目重复。

========================================
一、输出格式
========================================

**只输出 JSON 文件，不输出 MD 文件。**

========================================
二、分卷路由规则（核心逻辑）
========================================

题目按每 100 题一档自动分文件存储。路由公式：
  range_start = floor((id - 1) / 100) * 100
  range_end   = range_start + 100

文件对应关系：
- ID 1-100：   算法题目.json（默认文件）
- ID 101-200：算法题目100-200.json
- ID 201-300：算法题目200-300.json
- 以此类推

所有文件位于 D:\文件\算法\ 目录下。

========================================
三、执行流程
========================================

【步骤1】读取 D:\文件\算法\problem_history.json
- 获取 lastId（当前最大题目ID）
- 获取 history 数组（用于去重，检查 title 是否已存在）
- 如果文件不存在，初始化 lastId = 0, history = []

【步骤2】生成20道新题
- 新题ID从 lastId + 1 开始，依次递增
- 每道题生成后，先用 javac 编译、java 运行测试，全部 PASS 后才算完成
- 测试代码不依赖 JUnit，使用 main 方法 + 简单断言
- 确保题目标题不与 history 中已有标题重复

【步骤3】按分卷路由分组
- 对每道新题，根据其 ID 计算目标文件：
  range_start = floor((id - 1) / 100) * 100
  range_end   = range_start + 100
- 如果 range_start == 0，目标文件为 算法题目.json
- 否则目标文件为 算法题目{range_start}-{range_end}.json
- 将新题按目标文件分组

【步骤4】逐卷写入 JSON 文件
对每个涉及的分卷：

(A) 如果目标 JSON 文件不存在或为空（0字节），先初始化：
  创建 {"version":"1.0","generatedAt":"今天日期","totalProblems":0,"problemRange":{"from":range_start+1,"to":range_end},"problems":[]}

(B) 读取目标 JSON 文件：
  - 解析现有 problems 数组
  - 为每道新题生成 JSON 对象，包含字段：id, title, difficulty, category, tags(数组), date(YYYY-MM-DD), problem(含description/inputFormat/outputFormat/constraints/examples), solutions(数组，含name/approach/code/timeComplexity/spaceComplexity), comparison(中/困难必填，简单题为null), testCases, testResult, summary
  - 追加到 problems 数组
  - 更新 totalProblems 和 generatedAt
  - 覆写整个 JSON 文件

【步骤5】更新 problem_history.json
- 更新 lastId 为最大的ID
- 将新题的 {id, title, difficulty, category, date} 追加到 history 数组
- 覆写文件

========================================
四、总结（summary）撰写规范 —— 五步结构化详实总结
========================================

每道题的 summary 字段必须严格按以下五步结构撰写。
每步要求 3-5 句话（约 60-100 字），整体总结约 300-500 字。内容必须具体、有针对性，禁止泛泛而谈。

各步骤之间用 \n\n 分隔，每个步骤标题加粗。

1. **题目概述**（3-5句话）：
   - 说明本题属于什么算法类别
   - 描述问题的核心约束和挑战点
   - 说明输入数据的特征和规模范围
   - 如有经典实际应用场景，简要提及

2. **解题方法**（3-5句话）：
   - 列出本题采用的所有解法名称（至少2种，简单题可以1种）
   - 对每种解法用 2-3 句话解释其核心思路和关键步骤
   - 说明为什么最优解法优于其他解法
   - 如果涉及巧妙的状态定义或数据结构选择，要点明设计动机

3. **时间复杂度**（3-5句话）：
   - 给出每种解法的时间复杂度（用大O表示）
   - 解释为什么最优解法能达到该复杂度
   - 如果有嵌套循环，说明均摊分析或数学推导
   - 对比不同解法的效率差异

4. **空间复杂度**（3-5句话）：
   - 给出每种解法的空间复杂度
   - 具体说明额外空间的用途
   - 如果存在空间优化技巧，详细说明优化前后对比
   - 说明哪些空间开销是不可避免的

5. **改进方向**（3-5句话）：
   - 指出当前最优解法是否已达到理论下界
   - 如果有更高级的算法可以进一步优化，简要说明思路
   - 讨论本题的变体或扩展方向
   - 提及在实际工程中需要注意的常数因子优化或缓存友好性

JSON 格式的 summary 字段示例：
"**题目概述：** ...\n\n**解题方法：** ...\n\n**时间复杂度：** ...\n\n**空间复杂度：** ...\n\n**改进方向：** ..."

========================================
五、重要注意事项
========================================

1. 同一批次的新题可能跨越分卷边界（如从 ID 99 到 101），此时需分别写入两个 JSON 文件
2. 去重时通过 problem_history.json 的 history 数组统一查重
3. 20道题全部完成后再统一写入 JSON 文件
4. 如果某个分卷 JSON 文件已存在且有内容，读取后在现有内容的基础上追加；如果文件为空（0字节），按初始化模板创建后写入
5. 总结必须严格按五步结构化格式撰写，每步3-5句话，内容要具体有针对性，禁止一句话概括
6. **不要生成或更新任何 .md 文件，只操作 .json 文件**

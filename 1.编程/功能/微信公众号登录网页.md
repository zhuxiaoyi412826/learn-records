# 验证码登录

## 一、核心原理一句话总结

用户在网站登录页看到公众号二维码和验证码 → 扫码关注公众号并回复验证码 → 后端校验验证码和用户身份 → 网站登录页验证成功，用户直接登录。

本质是用**公众号消息接口 + 后端缓存**，实现无密码、免手机号的快速登录。

------

## 二、需要提前准备的东西

### 1. 公众号相关

- 一个已认证的**微信公众号**（服务号 / 订阅号都可以，订阅号也能实现基础消息接收）

- 公众号后台的：`AppID`、`AppSecret`、`Token`（用于消息接口配置）

- 公众号后台配置：

  - 消息接收服务器（URL、Token、EncodingAESKey）
  - 域名已完成 ICP 备案（否则无法配置消息接口）

  

### 2. 后端技术栈

- 语言不限（Java/Node.js/Python/PHP 都可以）
- 缓存服务：**Redis**（必须！用来存验证码、openid 映射，设置过期时间）
- 数据库：存储用户信息、openid 与网站账号的绑定关系
- 公网可访问的服务器（用来接收微信公众号的消息推送）

### 3. 前端页面

- 登录页：显示公众号二维码、验证码、倒计时
- 轮询逻辑：定时请求后端，检查验证码是否已被验证

------

## 三、完整实现流程（分前后端 + 用户操作）

### 1. 【前端 + 后端：初始化登录】

1. 用户访问网站登录页，点击 “微信公众号登录”。

2. 前端向后端发起请求，申请一个登录会话。

3. 后端生成一个

   6 位随机验证码

   （如你图中的

   ```
   177314
   ```

   ），同时生成一个临时会话 ID，将：

   - `验证码` → `会话ID`

   - ```
     会话ID
     ```

      → 

     ```
     未验证状态
     ```

     

     存入 Redis，设置过期时间（比如你图中的 60 秒）。

   

4. 后端返回：公众号二维码（可以是公众号的永久二维码）、验证码、过期时间给前端。

5. 前端渲染页面：显示二维码、验证码、倒计时，并开启轮询（比如每 2 秒请求一次后端，检查会话状态）。

### 2. 【用户端：扫码 + 回复验证码】

1. 用户用微信扫码，关注公众号（如果未关注，会触发公众号的`subscribe`事件；已关注则直接进入对话）。
2. 用户在公众号对话框里，回复验证码（比如`177314`）。

### 3. 【公众号 + 后端：接收消息并校验】

1. 微信服务器将用户的消息（包括`openid`、消息内容、公众号 ID）推送到你配置的后端消息接口 URL。

2. 后端接收消息，解析出：`openid`（用户在公众号的唯一标识）、`content`（用户回复的验证码）。

3. 后端校验：

   - 检查`content`是否是当前有效的验证码（从 Redis 中查询验证码对应的会话 ID）。

   - 如果验证码有效：

     - 将`会话ID`的状态改为`已验证`，并关联用户的`openid`。

     - 同时，检查数据库中是否存在该

       ```
       openid
       ```

       对应的网站账号：

       - 存在：直接生成网站的登录态（token/session）。
       - 不存在：自动创建一个新用户，并绑定`openid`。

       

     - 可选：给用户回复 “登录成功，请返回网站” 的提示语。

     

   - 如果验证码无效 / 过期：给用户回复 “验证码错误或已过期，请刷新页面重试”。

   

### 4. 【前端 + 后端：完成登录】

1. 前端的轮询请求到后端，查询会话状态。
2. 后端发现会话状态为`已验证`，返回成功，并携带登录态（token）。
3. 前端收到成功响应，跳转到网站首页，登录完成。

------

## 四、关键细节与避坑点

### 1. 验证码安全

- 验证码必须**一次性有效**：用户回复后，Redis 中立刻删除该验证码，防止重复使用。
- 过期时间要合理：一般 30-60 秒，和前端显示的倒计时一致。
- 验证码可以绑定 IP / 会话 ID，防止跨用户盗用。

### 2. 消息接口配置

- 公众号后台的消息服务器配置必须正确：

  - `URL`：必须是公网可访问的 HTTPS 地址（微信要求）。
  - `Token`：前后端配置必须一致，用于验证微信服务器签名。
  - `EncodingAESKey`：用于消息加解密，建议开启。

  

- 消息接口的处理逻辑要快速响应，否则微信会重试推送，导致重复处理。

### 3. 用户身份绑定

- `openid`是用户在公众号下的唯一标识，不能直接暴露给前端。
- 建议用`openid`和网站用户 ID 做绑定，用户首次登录时自动注册，后续直接识别。
- 可以支持多公众号绑定同一个网站账号（用 UnionID 机制）。

### 4. 轮询优化

- 轮询间隔不要太频繁（比如 2-3 秒一次），避免给服务器造成压力。
- 登录成功后要立刻停止轮询，前端跳页。
- 验证码过期后，前端要提示用户刷新页面重新获取验证码。

------

## 五、可选的优化方案

1. **带参数二维码**：生成带会话 ID 的临时二维码，用户扫码后直接触发公众号事件，无需手动回复验证码，体验更好。
2. **自动回复关键词**：用户回复 “登录”，公众号自动生成验证码，再让用户在网站输入，反向流程。
3. **消息模板推送**：登录成功 / 失败用公众号模板消息通知用户，提升体验。

# 加密算法全景指南（哈希 / 对称 / 非对称）

> 现代密码学的三大支柱：**哈希函数、对称加密、非对称加密**。真实系统中的加密几乎都是三者组合（混合加密）。

---

## 一、密码学总览

| 类别 | 核心思想 | 代表性算法 | 主要用途 |
|------|----------|------------|----------|
| **哈希（单向）** | 任意长度输入 → 定长摘要，**不可逆** | SHA-2、SHA-3、BLAKE2/3、SM3 | 完整性校验、密码存储、签名、区块链 |
| **对称加密** | 加密和解密用**同一把密钥** | AES、ChaCha20、SM4、3DES | 大数据量加密：HTTPS、磁盘、文件、数据库 |
| **非对称加密** | **公钥**加密、**私钥**解密；私钥签名、公钥验签 | RSA、ECC（ECDSA/Ed25519）、SM2、后量子 | 密钥交换、数字签名、证书、身份认证 |

---

## 二、哈希算法（单向散列）

### 2.1 核心特性
- 任意长度输入 → 固定长度输出（如 SHA-256 → 256 位）
- **单向性**：由摘要无法反推原文
- **抗碰撞**：难以找到两个不同输入产生相同摘要
- **雪崩效应**：输入微小变化，输出剧烈变化
- ⚠️ **哈希不是加密**：没有密钥、不可逆，不能用于保密传输，只能用于"校验/指纹/防篡改"

### 2.2 常见算法一览

| 算法 | 输出长度 | 状态 | 说明 |
|------|---------|------|------|
| MD5 | 128 bit | ❌ 已攻破 | 2004 年起可制造碰撞，仅用于非安全校验（如普通下载校验） |
| SHA-1 | 160 bit | ❌ 已淘汰 | 2017 年 SHAttered 实际碰撞攻击；TLS、证书、Git 均已弃用 |
| **SHA-2**（SHA-256/384/512） | 256/384/512 bit | ✅ **安全 · 最流行** | 全球应用最广：TLS、区块链、证书指纹、HMAC |
| SHA-3（Keccak） | 224~512 bit | ✅ 安全 | NIST 2015 标准，海绵结构，与 SHA-2 互为备份 |
| BLAKE2 / **BLAKE3** | 256/512 bit | ✅ 安全 · 快速 | BLAKE3（2020）速度极快、支持并行，现代开发工具常用 |
| SM3 | 256 bit | ✅ 安全（国密） | 中国商用密码标准，与 SHA-256 同级 |
| RIPEMD-160 | 160 bit | ⚠️ 仍可见 | 比特币地址中与 SHA-256 组合使用 |

### 2.3 优点与不足
- ✅ **优点**：速度快；输出定长；不可逆；标准化程度高；可用于指纹、校验、去重
- ❌ **不足**：不可用于加密（无法解密）；存密码必须配合"慢哈希"（Argon2 等），否则易被字典/彩虹表攻击；量子计算（Grover）会使碰撞强度减半

### 2.4 应用领域
- 文件/数据完整性校验（下载校验和、TLS 记录完整性）
- 密码存储（盐 + 慢 KDF：Argon2id / bcrypt / scrypt / PBKDF2）
- 数字签名（先哈希再签名，RSA/ECDSA 均如此）
- 区块链与加密货币（比特币 SHA-256、以太坊 Keccak-256）
- 版本控制（Git 对象寻址）、内容寻址（IPFS）
- 证书指纹、消息认证（HMAC）

### 2.5 密码哈希 KDF（慢哈希，属于哈希子类，专门存用户密码）

在普通哈希基础上：**加盐、多次迭代、消耗 CPU / 内存，故意跑慢**，抵抗暴力破解与彩虹表攻击。

| 算法 | 输出长度 | 存储参考（至少） | 说明 |
|------|---------|----------------|------|
| **Argon2id** | 32 B（16~64 可配置） | 编码串约 97 字符：hash 32B + salt 16B + 参数 | PHC 冠军，**现代首选**，抗 GPU 破解 |
| **BCrypt** | 固定 23 B（184 bit） | 固定 60 字符 ASCII 串（含版本/成本/salt+hash 一体） | 生态成熟，SpringSecurity、Sa-Token 广泛使用 |
| **Scrypt** | 默认 32 B（可配置） | hash 32B + salt 16B + 参数（无标准编码串） | 强内存消耗，适合高安全场景 |
| **PBKDF2-HMAC-SHA256** | 默认 32 B（可配置） | hash 32B + salt 16B + 迭代次数 | 兼容性好，FIPS 合规；SHA256 反复迭代 |
| **PBKDF2-HMAC-SM3**（国密版） | 32 B（SM3 为 256 位） | hash 32B + salt 16B + 迭代次数（国密格式） | 把底层哈希替换成 SM3 |

> 📏 **存储最小要求**：输出（哈希值）**至少 16 B（128 bit），推荐 32 B（256 bit）**；除哈希本身外，还必须**一并存储随机盐（16 B）和算法参数**（版本/迭代次数/内存），否则无法验证密码。
>
> ⚠️ **注意**：普通哈希（SHA-256 等）**不能**直接用来存密码，必须使用本节的慢哈希 KDF。

## 三、对称加密算法

### 3.1 分类
- **分组密码（Block Cipher）**：按固定块加密（如 AES 128 位块），需配合工作模式使用
- **流密码（Stream Cipher）**：逐字节/逐位加密（ChaCha20、RC4）

### 3.2 分组密码算法一览

| 算法 | 密钥长度 | 分组大小 | 状态 | 说明 |
|------|---------|---------|------|------|
| DES | 56 bit | 64 bit | ❌ 已攻破 | 1998 年被穷举破解，已淘汰 |
| 3DES | 112/168 bit | 64 bit | ❌ 淘汰中 | NIST 2023 年正式退役，2024 年起禁止新增使用 |
| **AES**（Rijndael） | 128/192/256 bit | 128 bit | ✅ **最流行** | 全球事实标准，硬件加速（AES-NI/指令集） |
| SM4 | 128 bit | 128 bit | ✅ 安全（国密） | 中国国标，WAPI、国密 TLS 常用 |
| Blowfish | 32~448 bit | 64 bit | ⚠️ 遗留 | 老系统/老工具（如旧版 bcrypt）遗留 |
| Twofish | 128~256 bit | 128 bit | ⚠️ 安全但少见 | AES 决赛算法之一 |
| Camellia | 128/192/256 bit | 128 bit | ✅ 安全 | 日本标准，ISO/IEC 18033-3 |

### 3.3 流密码

| 算法 | 密钥长度 | 状态 | 说明 |
|------|---------|------|------|
| RC4 | 40~2048 bit | ❌ 已淘汰 | 2015 年 TLS 禁用（RFC 7465），安全性极差 |
| **ChaCha20** | 256 bit | ✅ **流行** | 软件实现极快，手机端/无 AES 硬件时首选；常配 Poly1305 组成 AEAD |

### 3.4 分组工作模式（易踩坑，重点）

| 模式 | 是否认证 | 说明 |
|------|---------|------|
| ECB | ❌ | 相同明文块输出相同密文，泄露结构模式，**不安全，勿用** |
| CBC | ❌ | 经典模式，需 IV，需另配 HMAC 防篡改 |
| CTR | ❌ | 计数器模式，可并行 |
| **GCM** | ✅ AEAD | 加密+认证一体（AES-GCM），TLS 1.3 主力 |
| CCM | ✅ AEAD | 加密+认证，Wi-Fi WPA2（AES-CCMP） |
| **ChaCha20-Poly1305** | ✅ AEAD | TLS 1.3 / WireGuard / 移动端流行 |

> **AEAD（认证加密）**：同时保证机密性 + 完整性 + 真实性，现代系统强制要求（TLS 1.3 只允许 AEAD）。

### 3.5 优点与不足
- ✅ **优点**：加解密速度极快；适合海量数据；硬件支持广泛（AES-NI）
- ❌ **不足**：**密钥分发是难题**（如何安全地把密钥给对方？→ 交给非对称加密解决）；密钥数量随通信方平方级增长；密钥管理与轮换复杂；模式误用（如 ECB）会致命

### 3.6 应用领域
- HTTPS/TLS 数据加密（AES-128/256-GCM、ChaCha20-Poly1305）
- 磁盘全盘加密（BitLocker、FileVault、LUKS 的 AES-XTS）
- Wi-Fi 安全（WPA2-AES-CCMP、WPA3-AES-GCMP）
- VPN（IPsec、WireGuard 用 ChaCha20-Poly1305）
- 数据库透明加密（TDE）、文件加密（VeraCrypt、7-Zip）
- 即时通讯（Signal/WhatsApp：AES-256 或 AEAD）

## 四、非对称加密算法（公钥密码）

### 4.1 核心思想
- **公钥（公开）+ 私钥（保密）** 成对出现
- 公钥加密 → 私钥解密（保密传输）
- 私钥签名 → 公钥验签（身份认证、防抵赖）
- 依赖数学困难问题：大整数分解（RSA）、椭圆曲线离散对数（ECC）

### 4.2 算法一览

| 算法 | 密钥/强度参考 | 状态 | 说明 |
|------|-------------|------|------|
| RSA | 2048/3072/4096 bit | ✅ 经典主力 | 1024 bit 已破；2048 为最低要求；支持加密与签名 |
| DSA | — | ❌ 已淘汰 | FIPS 186-5 已移除，改用 ECDSA/EdDSA |
| ElGamal | — | ⚠️ 少见 | 基于离散对数，PGP 早期使用 |
| **ECDSA** | 256 bit ≈ RSA-3072 | ✅ 流行 | 椭圆曲线签名；证书、区块链（secp256k1） |
| **EdDSA**（Ed25519/Ed448） | 256/456 bit | ✅ 更推荐 | 速度快、实现抗侧信道、确定性签名；SSH/Git/TLS 普及 |
| **ECDH / X25519** | 256 bit | ✅ 主流 | 密钥交换（DH 的椭圆曲线版），TLS 1.3 默认 |
| SM2 | 256 bit | ✅ 安全（国密） | 中国标准：签名 / 加密 / 密钥交换一体 |
| **ML-KEM**（Kyber） | 128/192/256 bit | ✅ 后量子 | NIST FIPS 203（2024），抗量子密钥封装 |
| **ML-DSA**（Dilithium） | 128~256 bit | ✅ 后量子 | NIST FIPS 204（2024），抗量子签名 |
| SLH-DSA（SPHINCS+） | — | ✅ 后量子 | NIST FIPS 205（2024），哈希签名，签名较大但最保守 |

### 4.3 优点与不足
- ✅ **优点**：解决密钥分发难题；公钥可公开传播；天然支持数字签名与身份认证；密钥管理成本低（每人一对密钥）
- ❌ **不足**：速度比对称加密慢 2~4 个数量级；密钥更长；**面临量子威胁**（Shor 算法可分解 RSA/ECC）→ 后量子算法成为当前热点

### 4.4 应用领域
- HTTPS/TLS 握手与数字证书（X.509：RSA / ECDSA / Ed25519）
- 数字签名：代码签名、文档签名、软件更新签名、供应链安全（Sigstore）
- 加密货币钱包（比特币 secp256k1、以太坊 ECDSA、Solana/StarkNet Ed25519）
- SSH 密钥认证、PGP 邮件加密
- 电子政务 / 电子身份证 / 网银 U 盾（国密 SM2）

## 五、混合加密（现实系统的标准做法）

单用任一技术都不够，实际系统将三者组合：

```
TLS 1.3 示例：
1. 非对称：X25519/ECDHE 交换会话密钥（前向保密）+ 证书签名验证身份
2. 对称：AES-256-GCM / ChaCha20-Poly1305 加密实际传输数据
3. 哈希：HKDF-SHA-256 派生会话密钥；SHA-256 校验完整性
```

- ✅ 优势：兼顾**速度**（对称）+ **安全密钥交换**（非对称）+ **防篡改**（AEAD/签名）
- 应用：HTTPS、SSH、VPN、S/MIME、PGP、区块链交易（签名+哈希）、TLS 1.3/1.2 全系

## 六、消息认证码 MAC（完整性 + 真实性）

| 算法 | 说明 | 应用 |
|------|------|------|
| HMAC（HMAC-SHA256 等） | 哈希 + 密钥，最常用 | TLS、API 签名、JWT |
| CMAC / CBC-MAC | 基于分组密码 | 银行协议、认证 |
| Poly1305 | 一次性 MAC，配 ChaCha20 | ChaCha20-Poly1305 AEAD |
| KMAC | 基于 SHA-3 | 新系统 |

## 七、密钥派生与密码哈希（防暴力破解）

> 本节为快速索引，密码哈希 KDF 的完整介绍（含国密版 PBKDF2-HMAC-SM3）见 [2.5 节](#25-密码哈希-kdf慢哈希属于哈希子类专门存用户密码)。

| 算法 | 特点 | 推荐度 |
|------|------|--------|
| PBKDF2 | 标准但抗 GPU/ASIC 弱 | ⚠️ 旧系统兼容 |
| bcrypt | 1999，抗 ASIC 较好 | ✅ 常见 |
| scrypt | 内存密集，抗 ASIC 更强 | ✅ 推荐 |
| **Argon2id** | 2015 PHC 冠军 | ✅✅ **当前首选** |

> 明文密码**绝不**直接存 SHA-256，必须"随机盐 + 慢哈希"（如 Argon2id）。

## 八、国密算法（中国商用密码，GB/T 系列）

| 算法 | 类型 | 用途 |
|------|------|------|
| SM2 | 非对称（椭圆曲线） | 签名、加密、密钥交换 |
| SM3 | 哈希（256 bit） | 完整性校验、SM2 配套 |
| SM4 | 对称分组（128 bit） | 数据加密（WAPI、国密 TLS） |
| 配套 | 随机数（GB/T 32915 等） | 密钥生成、IV 等 |

## 九、三类算法横向对比

| 维度 | 哈希 | 对称加密 | 非对称加密 |
|------|------|----------|------------|
| 密钥 | 无密钥 | 同一把密钥 | 公钥/私钥一对 |
| 可逆性 | 不可逆 | 可逆（加解密） | 可逆 |
| 速度 | 极快 | 快 | 慢（差 2~4 个数量级） |
| 安全强度 | SHA-256 ≈ 128 bit | AES-256 | RSA-2048 ≈ 112 bit；ECC-256 ≈ 128 bit |
| 主要威胁 | 碰撞、彩虹表 | 暴力破解、模式误用 | 量子计算（Shor 算法） |
| 典型用途 | 校验 / 密码 / 签名 | 大数据量加密 | 密钥交换 / 签名 / 认证 |

## 十、2025–2026 流行现状与未来趋势

1. **对称加密事实标准**：AES-256-GCM；移动端/无硬件加速时用 ChaCha20-Poly1305
2. **非对称主流**：X25519（密钥交换）+ Ed25519 / ECDSA（签名）；TLS 1.3 全部 AEAD、默认前向保密
3. **哈希主力**：SHA-256（TLS、区块链、证书）；BLAKE3 在开发工具中普及；SM3 在国密体系
4. **密码存储**：Argon2id 取代 bcrypt / scrypt 成为首选
5. **后量子密码（PQC）落地**：NIST 已于 2024-08 发布 FIPS 203/204/205（ML-KEM、ML-DSA、SLH-DSA）；2025 年起 Chrome / Firefox / Apple（iMessage PQ3）/ Signal 等已部署**混合抗量子方案**（X25519 + ML-KEM-768）；美国 CNSA 2.0 计划 2030 年全面弃用 RSA/ECC
6. **合规趋势**：中国等国推行国密（SM2/SM3/SM4）商用密码合规改造，政务与金融系统强制
7. **新系统选型建议**：X25519 + Ed25519 + AES-256-GCM / ChaCha20-Poly1305 + Argon2id + SHA-256 / BLAKE3，并按需叠加 ML-KEM / ML-DSA 混合抗量子

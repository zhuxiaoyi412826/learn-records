

# 差异

**一句话总结差异**

1. **Demo：实现功能，证明可行，只考虑理想情况，不考虑线上风险。**
2. **企业级：不仅功能要实现，还要考虑：安全不出漏洞、线上不崩、出问题快速定位、流量大扛得住、运维可控、合规、兼容各种异常。**

## 1、功能实现层面

表格

| 维度       | Demo 项目                                    | 企业级项目                                                   |
| ---------- | -------------------------------------------- | ------------------------------------------------------------ |
| 业务流程   | 只实现主流程，Happy Path，异常场景基本不处理 | 完整主流程 + 大量异常分支：参数非法、超时、重试、降级、限流、空值、第三方失败、业务冲突 |
| 边界输入   | 假设输入都是合法正确                         | 严格参数校验；防超长输入、特殊字符、非法格式；做输入截断     |
| 功能完备度 | 核心功能做完就算完成                         | 配套周边能力：埋点、日志、监控、告警、导出、导入、权限、批量操作、分页、导出、错误提示友好 |
| 兼容性     | 只在自己开发环境测试                         | 多浏览器、多版本、不同客户端、不同数据库版本兼容；新旧数据兼容；版本平滑升级 |
| 业务埋点   | 几乎没有埋点                                 | 业务埋点、错误埋点、前端埋点，可统计用户行为、错误分布       |

# 完整链路

SpringBoot 接收请求 → 参数校验 → 登录鉴权 (JWT) →会话管理 → 业务逻辑 → 调用数据库 → 返回结果，全局异常处理→ 返回前端渲染

```
HTTP请求到达SpringBoot
↓
1.JWT登录鉴权（Filter）→ token解析、是否登录，失败直接返回401
↓
2.会话管理（Interceptor，ThreadLocal存当前登录用户）
↓
3.DispatcherServlet分发到Controller
↓
4.参数接收 + @Valid 参数校验（校验失败抛异常）
↓
5.Controller调用Service执行业务逻辑
↓
6.Service层（三种分支）
    ├─分支A：仅远程调用（OpenFeign/RestTemplate/WebClient）
    │        → 发起网络请求调用下游微服务
    │        → 下游服务独立完整执行整套链路，**下游服务访问它自己的远程数据库**
    │        ← 下游把处理结果通过HTTP响应返回给当前Service
    │
    ├─分支B：远程调用 + 访问本地数据库
    │        → 调用下游微服务，下游操作远程数据库
    │        → 拿到远程返回结果后，本服务再调用Mapper操作本地数据库
    │
    └─分支C：不远程调用，仅调用Mapper访问本地数据库
↓
7.业务正常：Service把业务结果返回给Controller
    ↘业务出错（本地异常 / 远程调用异常 / SQL异常）：异常向上抛出 → @RestControllerAdvice【全局异常处理器】捕获，包装错误JSON
↓
8.Controller接收Service返回的数据，组装统一响应封装对象（Result<T>）
↓
9.消息转换器 HttpMessageConverter（MappingJackson2HttpMessageConverter）
    Java对象序列化 → JSON字符串
↓
10.Spring组装HTTP响应报文（Response Headers + Body JSON）
↓
11.Tomcat底层把HTTP响应报文通过网络发送给前端浏览器
↓
12.前端JS接收HTTP响应，解析JSON，拿到code、msg、data
↓
13.前端框架（Vue/React）根据data渲染页面，展示给用户

```

**层次划分** 

1. **Filter**：Servlet 过滤器。JWT 解析、跨域、流重复读；**不要写业务逻辑**。
2. **Interceptor 拦截器**：拿到解析后的用户信息，存入 ThreadLocal 会话；做接口权限（角色）。
3. **Controller**：只做：接收参数、@Valid 校验、调用 service、组装返回；**禁止写复杂业务、禁止直接操作数据库**。
4. **Service**：核心业务逻辑、事务、业务校验；调用 Mapper；**不要处理 Http、不要操作 request/response**。
5. **Mapper(MyBatis‑Plus)**：只做数据库 CRUD。
6. **全局异常 @RestControllerAdvice**：统一捕获所有层抛出来的异常，输出统一格式 JSON；**正常成功流程不会进这里**。

# 企业级忘记密码 & 重置密码 全维度安全校验

企业级系统（后台 OA、SaaS、企业管理平台、ToB 账号体系），**不能只依赖邮箱链接**，会叠加多层身份核验、风险校验、防攻击策略；区分：**自助重置、管理员代重置、高敏感账号特殊管控**。

> 核心思想：**重置密码是高危操作，不是单一凭证过了就放行，做多因子分层校验，风险越高校验越强**。

## 一、发送重置凭证阶段（发起忘记密码时）

### 1. 人机对抗校验（防批量刷重置）

1. 必须人机验证：滑块 / 无感验证，防止脚本批量调用重置接口，轰炸员工邮箱
2. 接口限流
   - 单账号 / 邮箱：1 小时最多 3 次发送重置请求，24 小时上限 5 次
   - 单 IP 维度限流，拦截批量扫描
3. 账号枚举防护
   - 无论账号 / 邮箱是否存在，返回完全相同提示，禁止返回 “该邮箱未注册”

### 2. 账号状态前置校验（直接拦截不能重置的账号）

发起重置前后端校验：

1. 账号是否存在；
2. 账号是否被锁定、禁用、冻结；禁用账号直接拒绝重置；
3. 是否为管理员 / 超级管理员账号，部分企业策略：**超级管理员禁止自助重置，必须由其他管理员操作**；
4. 账号是否绑定可信凭证（邮箱 / 手机），无绑定凭证直接拒绝自助重置。

## 二、重置 Token / 链接本身安全（核心凭证安全）

1. **Token 不能明文落库**：数据库只存储 token 哈希（SHA‑256 / Argon2），明文仅在邮件链接中传递。

2. 短有效期：企业级一般 **15‑30 分钟**，不允许 24h 以上长时效。

3. 一次性凭证：使用后立刻作废；重复访问直接失效。

4. 生成新重置 token 时，**作废该用户所有历史未使用的重置 token**，旧链接全部失效。

5. Token 长度：CSPRNG 密码安全随机生成，≥32 字节，禁止 UUID 简单方案（UUID 可预测风险）。

6. 绑定上下文（高安全企业必做）

   - token 绑定**客户端 IP、浏览器指纹**；用户打开链接的 IP 与发起重置时 IP 差异过大，直接提升风险等级，增加二次校验。

   > 黑客窃取重置链接，但在别的网络环境打开，不能直接改密码。

7. 防预加载消耗 token：修改密码动作必须 POST 接口；禁止 GET 请求直接执行密码修改，防止邮件客户端预加载、爬虫消耗 token。

## 三、打开重置链接之后：多层身份二次核验（企业重点，区别普通 Demo）

> 拿到重置链接≠直接允许改密码，企业系统会根据风险等级追加二次校验。

表格

| 风险场景                            | 追加校验项                                             |
| ----------------------------------- | ------------------------------------------------------ |
| 普通员工、常用网络环境              | 仅校验 token 有效性，允许设置新密码                    |
| IP 发生跨地域、异地网络访问重置链接 | 短信验证码 / 企业 MFA 二次验证（TOTP）                 |
| 管理员账号、高权限账号              | 强制 MFA/TOTP 验证，不允许仅凭邮箱链接重置             |
| 账号近期有异常登录记录              | 强制 MFA，甚至阻断自助重置，要求联系 IT 管理员人工处理 |

> 企业常见：**超级管理员禁止自助密码重置，只能由另外一名管理员代重置**，避免单点泄露。

## 四、新密码本身校验策略

1. 密码复杂度强制策略：最小长度、大小写、数字、特殊字符；禁止弱密码字典。
2. 密码历史复用拦截：不能使用过去 N 次历史密码（比如禁止最近 5 次历史密码复用）。
3. 禁止密码与账号、邮箱、用户名相同。
4. 密码有效期策略：重置后的密码是否需要强制下次登录修改。
5. 禁止连续重复字符、常见弱口令黑名单。

## 五、重置成功之后安全动作（非常关键）

1. 销毁该账号全部会话、全部设备的登录态（踢所有终端下线）

   - Web Session、JWT/RefreshToken、移动端 token 全部失效；防止攻击者持有旧会话继续访问。

2. 审计日志完整记录：

   > 日志字段：账号 ID、重置时间、操作类型（自助重置 / 管理员代重置）、客户端 IP、UA、是否成功、重置凭证类型（邮箱 / 短信）。

3. 强通知告警

   - 邮件 + 企业站内信双重通知：告知用户密码已重置，附带操作时间、IP 地址。
   - 高权限账号重置密码，发送告警给安全管理员 / IT 运维。

4. 重置完成后，重置 token 彻底销毁，不可复用。

## 六、管理员后台代重置密码场景（企业 IT 常用）

> IT 管理员在后台帮用户重置密码，这是高危操作，需要额外管控：

1. 管理员操作必须记录审计日志，谁操作、操作哪个账号、时间。
2. 管理员不能直接查看用户原密码（密码哈希存储）。
3. 不允许管理员设置永久明文密码；一般生成**一次性临时密码**。
4. 临时密码策略：
   - 临时密码有有效期（例如 24 小时）；
   - 用户登录后**强制修改密码**，临时密码不能长期使用。
5. 权限隔离：普通管理员不能重置超级管理员密码；超级管理员重置需要双人复核。
6. 代重置完成，向用户发送通知邮件。

## 七、高级企业安全增强（等保、安全合规要求）

1. MFA 多因子绑定
   - 如果账号已经开启 TOTP 二次验证，重置密码后，**不自动清除 MFA 绑定**；除非是管理员人工接管重置。
2. 风险评分体系
   - 结合 IP 信誉库、设备指纹、历史行为，计算风险分；高风险直接阻断自助重置，走人工工单流程。
3. 防链接共享：重置链接绑定会话，不能复制给其他浏览器打开。
4. 账号接管告警：短时间多次重置密码，触发安全告警推送安全人员。
5. 满足等保 2.0 要求：操作留痕、不可篡改审计日志、密码策略管控。

## 八、常见企业级漏洞点

1. 拿到重置链接直接修改密码，无任何二次风险校验；
2. 管理员代重置，生成长期有效密码，用户不会被强制改密；
3. 重置成功不踢除已有登录会话；
4. 超级管理员账号支持自助邮箱重置，邮箱泄露直接接管最高权限账号；
5. token 无 IP / 设备绑定，链接被窃取后跨网络直接利用；
6. 审计日志缺失，出现安全事件无法溯源。

## 企业级完整流程总结

1. 用户发起忘记密码 → 人机验证 + 接口限流 + 账号状态校验
2. 生成带哈希存储、短时效、一次性 reset token，发送邮件
3. 用户打开重置链接：校验 token、过期、是否已使用；**校验 IP / 设备风险，风险高追加 MFA 二次验证**
4. 校验新密码强度，禁止历史密码复用
5. 更新密码，销毁 token，踢掉全部登录会话
6. 用户收到重置告警通知，全流程写入审计日志
7. 高权限账号：限制自助重置，走管理员代重置流程

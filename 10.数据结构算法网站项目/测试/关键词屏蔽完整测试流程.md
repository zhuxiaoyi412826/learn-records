## 七、ES → Redis 定时拉取

### 7.1 手动触发拉取（不必等定时任务）

```cmd
curl -s -X POST "http://localhost:80/api/audit/pending/pull"
```

正确返回（有新待审项时）：

```json
{"success":true,"message":"操作成功","code":200,"data":"ES拉取 15 条审计日志，新推送 1 条待审核，跳过 14 条重复"}
```

无新待审项时：`{"success":true,"message":"本轮无新增待审核项","code":200}`

### 7.2 定时任务验证（每 60 秒自动执行）

无法用单条命令直接触发，操作步骤：
1. 执行 5.2 新增一条中危题目；
2. 等待约 80 秒（启动后 20 秒首轮 + 60 秒间隔 + ES 延迟 15 秒）；
3. 后端日志窗口应出现：`[audit] 推送 1 条待审核(pending)任务到 Redis 队列`；
4. 执行 8.1 查看待审列表确认。

### 7.3 去重验证（重复拉取不重复入队）

连续执行两次 7.1，第二次正确返回：`"本轮无新增待审核项"`（submitId 已在 `audit:pushed` 集合）。

## 十一、Redis 验证（redis-cli 若不在 PATH，跳过本节，用 API 验证等效）

### 11.1 词库缓存

```cmd
redis-cli -p 6379 STRLEN audit:words:cache
```

正确返回：一个大于 100 的数字（词库 JSON 长度）；再执行 `redis-cli -p 6379 TTL audit:words:cache`，返回 1~600 之间的剩余秒数（TTL 600 秒）。

### 11.2 待审队列长度

```cmd
redis-cli -p 6379 LLEN audit:pending
```

正确返回：与 9.3 的 `pendingQueue` 数值一致。

### 11.3 已推送去重集合

```cmd
redis-cli -p 6379 SCARD audit:pushed
```

正确返回：已推送过的 submitId 个数（≥ 拉取过的待审条数）。

## 附：常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| /api/audit 返回 404 或 "No static resource" | 后端未重启加载新 Controller | 重启 Spring Boot |
| detect 中文内容永不命中 | cmd 内联中文乱码 | 使用 0.3 的 @file 方式 |
| ES 查不到 AUDIT 日志 | Fluentd 未启动 / 延迟 | 检查 fluentd 进程，等 15 秒重试 |
| 手动拉取返回 "Redis 不可用" | Redis 未启动 | 启动 Redis(6379) 后重试 |
| 驳回后题目仍可见 | ES 回写失败被容忍 / 前端缓存 | 查 MySQL status 字段确认，前端强刷 |
| 待审列表 total=-1 | Redis 连接异常 | 同 "Redis 不可用" |

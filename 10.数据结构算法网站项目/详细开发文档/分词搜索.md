# 编程题库 ES 分词搜索功能开发方案（基于 Elasticsearch 7.12.1）

本文档基于既有 EFK 7.12.1 技术栈扩展，实现题目全文分词检索能力，与现有敏感审核体系深度联动，兼顾搜索召回率、准确率与业务合规性。

## 一、功能目标与设计原则

### 1.1 核心目标

- 支持用户对题目标题、题干描述、标签、示例代码进行**中文分词 + 英文标识符拆分**的全文检索
- 支持按难度、标签、时间等维度进行条件过滤，结果按相关性智能排序
- 支持搜索关键词高亮展示，提升用户体验
- 与现有内容审核体系打通，违规未通过题目自动从搜索结果中屏蔽
- 兼容现有 ES 7.12.1 集群，复用基础设施，无需额外部署组件

### 1.2 设计原则

- **召回优先，精准为辅**：索引阶段细粒度分词保证召回，搜索阶段粗粒度分词提升准确率
- **业务解耦**：搜索服务独立封装，与业务提交、审核逻辑物理隔离
- **数据一致性**：题目数据变更后分钟级同步至 ES，保证最终一致
- **合规兜底**：搜索全链路嵌入敏感校验，杜绝违规内容透出

## 二、整体架构与数据流向

```
┌─────────────────┐    新增/修改题目     ┌─────────────────────┐
│   业务管理后台   │ ──────────────────> │   MySQL 题目主库     │
└─────────────────┘                      └─────────┬───────────┘
                                                    │
                                                    │ 增量同步
                                                    ▼
┌─────────────────┐    分词搜索请求     ┌─────────────────────┐
│   用户前端页面   │ ──────────────────> │  题目搜索服务        │
└─────────────────┘                      └─────────┬───────────┘
                                                    │
                                                    │ 构建DSL查询
                                                    ▼
                                          ┌─────────────────────┐
                                          │  Elasticsearch 7.12.1│
                                          │  - problem_index 索引│
                                          │  - IK分词器          │
                                          └─────────────────────┘
                                                    ▲
                                                    │
                                          ┌─────────────────────┐
                                          │  敏感审核过滤逻辑    │
                                          │  仅透出审核通过题目  │
                                          └─────────────────────┘
```

核心数据链路：

1. 运营后台新增 / 编辑题目 → 写入 MySQL 主库
2. 增量同步任务定时拉取变更数据 → Upsert 写入 ES 题目索引
3. 用户前端输入关键词 → 搜索服务构造 DSL 向 ES 查询
4. ES 执行分词匹配、评分排序、过滤合规题目 → 返回结果与高亮片段
5. 搜索服务封装结果 → 返回前端展示

## 三、ES 索引设计（核心）

### 3.1 分词器选型与配置

ES 7.12.1 默认 `standard` 分词器对中文支持极差，针对编程题库场景采用**多分词器组合方案**。

#### 3.1.1 中文分词器：IK Analyzer

选用与 ES 7.12.1 版本严格匹配的 `elasticsearch-analysis-ik v7.12.1`，提供两种分词模式：

表格

| 分词模式      | 适用场景 | 特点                                           |
| ------------- | -------- | ---------------------------------------------- |
| `ik_max_word` | 索引阶段 | 细粒度拆分，将文本拆分为最小语义单元，召回率高 |
| `ik_smart`    | 搜索阶段 | 粗粒度拆分，按最合理语义切分，准确率高         |

**安装方式**：

```
# 在线安装（ES 集群所有节点均需执行）
./bin/elasticsearch-plugin install https://github.com/medcl/elasticsearch-analysis-ik/releases/download/v7.12.1/elasticsearch-analysis-ik-7.12.1.zip

# 安装完成后重启 ES 节点，验证插件
./bin/elasticsearch-plugin list
```

#### 3.1.2 英文 / 代码标识符分词优化

针对编程题目中的函数名、变量名（如 `quickSort`、`two_sum`），自定义 `code_analyzer` 分词器，支持驼峰、下划线拆分：

```
{
  "settings": {
    "analysis": {
      "analyzer": {
        "code_analyzer": {
          "type": "pattern",
          "pattern": "([^a-zA-Z0-9]+)|(?<=[a-z])(?=[A-Z])|(?<=[A-Z])(?=[A-Z][a-z])|_",
          "lowercase": true
        }
      },
      "char_filter": {
        "code_strip": {
          "type": "pattern_replace",
          "pattern": "[{}();,.\\[\\]]",
          "replacement": " "
        }
      }
    }
  }
}
```

效果：`quickSort` → `quick`、`sort`；`list_node_add` → `list`、`node`、`add`。

#### 3.1.3 字段分词策略

表格

| 字段     | 索引分词器      | 搜索分词器      | 权重 |
| -------- | --------------- | --------------- | ---- |
| 题目标题 | `ik_max_word`   | `ik_smart`      | 10   |
| 题目描述 | `ik_max_word`   | `ik_smart`      | 3    |
| 题目标签 | `ik_smart`      | `ik_smart`      | 8    |
| 示例代码 | `code_analyzer` | `code_analyzer` | 1    |

### 3.3 索引别名管理

采用**别名 + 多版本**方案，实现索引重建零停机：

```
# 创建别名

```

后续索引结构变更时：新建 `problem_index_v2` → 全量同步数据 → 切换别名 → 删除旧索引，业务侧无感知。

## 四、题目数据同步方案

### 4.1 方案对比与选型

结合现有技术栈（Spring Boot + XXL-Job），采用**全量初始化 + 定时增量同步**方案，兼顾实现成本与数据时效性。

表格

| 方案              | 实时性 | 复杂度 | 耦合度 | 推荐场景                         |
| ----------------- | ------ | ------ | ------ | -------------------------------- |
| 业务双写          | 毫秒级 | 低     | 高     | 数据量小、实时性要求极高         |
| 定时增量同步      | 分钟级 | 低     | 低     | 题目更新不频繁，现有调度体系复用 |
| Canal 监听 binlog | 秒级   | 高     | 低     | 大规模数据、高实时要求           |

**选型结论**：默认使用定时增量同步，同步周期 1 分钟；若后续实时性要求提升，可平滑切换为 Canal 方案。

### 4.2 全量初始化流程

1. 暂停增量同步任务
2. 新建目标索引并执行 Mapping 初始化
3. 分页读取 MySQL 题目全量数据（每次 1000 条）
4. 批量 Upsert 写入 ES（Bulk API）
5. 刷新索引，验证数据量一致性
6. 切换别名，恢复增量同步

### 4.3 增量同步核心逻辑

```
// XXL-Job 定时任务，每分钟执行
@XxlJob("problemEsSyncJob")
public void syncProblemToEs() {
    // 1. 读取上次同步时间戳
    Long lastSyncTime = redisTemplate.opsForValue().get("es:sync:problem:last_time");
    
    // 2. 查询 MySQL 中 update_time > lastSyncTime 的题目
    List<Problem> problemList = problemService.listByUpdateTime(lastSyncTime);
    if (CollectionUtils.isEmpty(problemList)) {
        return;
    }

    // 3. 批量写入 ES
    BulkRequest bulkRequest = new BulkRequest();
    for (Problem problem : problemList) {
        IndexRequest request = new IndexRequest("problem_search");
        request.id(String.valueOf(problem.getProblemId()));
        request.source(JSON.toJSONString(problem), XContentType.JSON);
        bulkRequest.add(request);
    }
    restHighLevelClient.bulk(bulkRequest, RequestOptions.DEFAULT);

    // 4. 更新同步时间戳为本次最大 update_time
    Long maxUpdateTime = problemList.stream()
        .map(Problem::getUpdateTime)
        .max(Long::compareTo)
        .orElse(System.currentTimeMillis());
    redisTemplate.opsForValue().set("es:sync:problem:last_time", maxUpdateTime);
}
```

## 五、核心搜索 DSL 实现

### 5.1 基础多字段分词搜索

对标题、描述、标签、代码示例进行加权分词匹配：

```
POST /problem_search/_search
{
  "query": {
    "bool": {
      "must": [
        {
          "multi_match": {
            "query": "两数之和 哈希表",
            "fields": ["title", "description", "tags^2", "code_example"],
            "type": "most_fields",
            "operator": "or",
            "minimum_should_match": "70%"
          }
        }
      ],
      "filter": [
        { "term": { "status": "NORMAL" } },
        { "term": { "audit_status": "PASS" } }
      ]
    }
  },
  "from": 0,
  "size": 20,
  "sort": [
    { "_score": "desc" },
    { "create_time": "desc" }
  ]
}
```

### 5.2 带维度过滤的组合搜索

支持按难度、标签精确过滤：

```
POST /problem_search/_search
{
  "query": {
    "bool": {
      "must": [
        { "match": { "title": "动态规划" } }
      ],
      "filter": [
        { "term": { "difficulty": "MEDIUM" } },
        { "terms": { "tags": ["数组", "背包问题"] } },
        { "term": { "status": "NORMAL" } },
        { "term": { "audit_status": "PASS" } }
      ]
    }
  }
}
```

### 5.3 关键词高亮配置

搜索结果中高亮命中关键词，前端直接渲染：

```
POST /problem_search/_search
{
  "query": { "match": { "title": "二叉树" } },
  "highlight": {
    "pre_tags": ["<em class='highlight'>"],
    "post_tags": ["</em>"],
    "fields": {
      "title": { "number_of_fragments": 0 },
      "description": { 
        "number_of_fragments": 2,
        "fragment_size": 150
      }
    }
  }
}
```

### 5.4 深度分页优化

默认分页 `from + size` 支持 10000 条以内；若需深度遍历，使用 `search_after`：

```
POST /problem_search/_search
{
  "size": 20,
  "search_after": [1.5, 1690000000000],
  "sort": [
    {"_score": "desc"},
    {"create_time": "desc"}
  ]
}
```

## 六、Java 服务端实现（Spring Boot + RestHighLevelClient）

### 6.1 依赖引入

```
<dependency>
    <groupId>org.elasticsearch.client</groupId>
    <artifactId>elasticsearch-rest-high-level-client</artifactId>
    <version>7.12.1</version>
</dependency>
```

### 6.2 核心搜索服务代码

```
@Service
public class ProblemSearchService {

    @Autowired
    private RestHighLevelClient restHighLevelClient;

    public PageResult<ProblemSearchVO> search(ProblemSearchQuery query) {
        // 1. 构建搜索请求
        SearchRequest searchRequest = new SearchRequest("problem_search");
        SearchSourceBuilder sourceBuilder = new SearchSourceBuilder();

        // 2. 构建布尔查询
        BoolQueryBuilder boolQuery = QueryBuilders.boolQuery();
        
        // 关键词分词匹配
        if (StringUtils.isNotBlank(query.getKeyword())) {
            MultiMatchQueryBuilder multiMatch = QueryBuilders.multiMatchQuery(query.getKeyword())
                .field("title", 10)
                .field("tags", 8)
                .field("description", 3)
                .field("code_example", 1)
                .minimumShouldMatch("70%");
            boolQuery.must(multiMatch);
        }

        // 过滤条件：仅展示正常且审核通过的题目
        boolQuery.filter(QueryBuilders.termQuery("status", "NORMAL"));
        boolQuery.filter(QueryBuilders.termQuery("audit_status", "PASS"));

        // 难度、标签过滤
        if (StringUtils.isNotBlank(query.getDifficulty())) {
            boolQuery.filter(QueryBuilders.termQuery("difficulty", query.getDifficulty()));
        }
        if (CollectionUtils.isNotEmpty(query.getTags())) {
            boolQuery.filter(QueryBuilders.termsQuery("tags", query.getTags()));
        }

        // 3. 分页与排序
        sourceBuilder.from((query.getPageNum() - 1) * query.getPageSize());
        sourceBuilder.size(query.getPageSize());
        sourceBuilder.sort(SortBuilders.scoreSort().order(SortOrder.DESC));
        sourceBuilder.sort("create_time", SortOrder.DESC);

        // 4. 高亮配置
        HighlightBuilder highlightBuilder = new HighlightBuilder();
        highlightBuilder.field("title", 0).field("description", 2, 150);
        highlightBuilder.preTags("<em class='highlight'>").postTags("</em>");
        sourceBuilder.highlighter(highlightBuilder);

        sourceBuilder.query(boolQuery);
        searchRequest.source(sourceBuilder);

        // 5. 执行查询并解析结果
        SearchResponse response = restHighLevelClient.search(searchRequest, RequestOptions.DEFAULT);
        SearchHit[] hits = response.getHits().getHits();
        
        List<ProblemSearchVO> voList = new ArrayList<>();
        for (SearchHit hit : hits) {
            ProblemSearchVO vo = JSON.parseObject(hit.getSourceAsString(), ProblemSearchVO.class);
            // 替换高亮内容
            Map<String, HighlightField> highlightFields = hit.getHighlightFields();
            if (highlightFields.containsKey("title")) {
                vo.setTitle(highlightFields.get("title").getFragments()[0].string());
            }
            voList.add(vo);
        }

        long total = response.getHits().getTotalHits().value;
        return new PageResult<>(total, voList);
    }
}
```

## 七、与现有审核体系的联动

### 7.1 搜索结果合规兜底

- 所有搜索 DSL 强制加入 `audit_status: PASS` 与 `status: NORMAL` 过滤条件，从底层杜绝违规题目透出
- 高危违规题目在审核驳回时，同步调用 ES API 将其从索引中逻辑删除（更新状态）
- 定时校验任务每日比对 ES 与 MySQL 审核状态，修复数据不一致

### 7.2 搜索词敏感检测

用户输入的搜索关键词先调用既有敏感检测服务：

- 命中辱骂、违规关键词：直接拦截，返回 “搜索内容不合规” 提示
- 命中高危敏感词：记录搜索日志至 ES 审计索引，同步至审核后台人工复核
- 正常关键词：放行执行搜索

## 九、性能优化与运维配置

### 9.1 索引性能优化

- `refresh_interval` 设为 30s，题目更新频率低，大幅提升写入性能
- 大字段 `description`、`code_example` 关闭 `doc_values`，减少存储占用
- 开启索引压缩：`index.codec: best_compression`

### 9.2 查询性能优化

- 过滤条件全部放入 `filter` 上下文，不参与评分，利用缓存
- 限制单次查询最大返回条数，禁止深度翻页（默认最大 100 页）
- 开启查询缓存：`indices.queries.cache.size: 10%`

### 9.3 索引生命周期

题目索引为常驻业务索引，不采用日志索引的每日滚动策略：

- 每月执行一次索引段合并（force merge）
- 每季度全量重建一次索引，优化碎片
- 定期备份索引快照至对象存储

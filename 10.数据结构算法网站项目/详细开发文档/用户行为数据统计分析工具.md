```
## 一、两个提示符是什么意思

1. **`postgres=#` ✅主提示符（就绪状态）**

> 
> 代表：连接数据库成功，现在可以输入新 SQL 命令。
> 在这里可以执行 SQL、可以执行`\q`退出。

2. **`postgres‑#` ⚠续行模式（卡住）**

> 
> 代表：**上一行输入的 SQL 没有写英文分号`;`结尾**，psql 认为你的语句还没有写完，等待你继续输入剩下的 SQL 内容。

> 
> ❗坑：卡在`postgres‑#`的时候，**`\q 不能直接退出！`**
> 因为 psql 以为你`\q`是 SQL 文本的一部分，不是退出命令。

### 从`postgres‑#`卡住状态恢复回到 `postgres=#`（2 种方法）

1. **快捷键（最推荐 Windows cmd/PowerShell）：`Ctrl + C`**
直接丢弃你刚才没写完的输入，立刻回到正常`postgres=#`提示符CSDN博...。
2. 输入 `\r` 回车（清除缓冲区），回到主提示符。
```

## ❗踩坑重点（关键教训）

1. **绿色 zip 包不要注册 Windows 系统服务** 注册后会出现：服务面板显示已停止，但 postgres 进程实际还在运行，状态不同步、启动报错。已经删除`PostgreSQL17`错误服务。
2. `.\`用法：只有 cd 进到 bin 目录，才可以用`.\pg_ctl.exe`；普通目录直接写命令，不要加`.\`
3. psql 规则：SQL 必须完整语句，**以英文分号`;`结尾**；提示符`postgres‑#`代表语句未结束；裸写数字会报语法错误，要用`select 数字;`
4. 异常崩溃会残留`postmaster.pid`锁文件，会报 “其他服务器进程可能正在运行”；必须确认 postgres 进程全部结束，才可删除 pid 锁文件。

# Windows 踩坑清单

1. Docker 访问宿主机 PostgreSQL：连接串 host 写`host.docker.internal`，不要写 127.0.0.1。
2. PostgreSQL 时区必须 UTC，否则日期统计偏移 8 小时。
3. 源码 build 失败：确认 Node22，pnpm 版本，删除 node_modules 重新`pnpm install`。
4. 埋点脚本访问失败：检查 umami 服务地址网络可达，内网环境不需要外网。
5. V3 完全移除 MySQL；V2 镜像标签`mysql‑latest`为旧版本，不再接收新功能。
6. 备份：直接备份 PostgreSQL `umami`数据库。

# Umami V3 完整数据分析能力

> 分为：**基础流量分析、多维度属性分析、自定义事件、高级行为分析、性能分析、营销分析、API 可导出数据**。 注意：**大部分统计原始数据可以通过 API 拿出来，在你自己页面渲染；但会话回放、热力图渲染组件依赖 Umami 前端，只能拿到打点元数据，不能直接拿到回放视频二进制**GitHub。

## 一、基础流量指标（全部 API 可获取，你自研页面完全可用）Umami

表格

| 指标             | 说明                                  |
| ---------------- | ------------------------------------- |
| PV pageviews     | 页面浏览总数                          |
| UV visitors      | 独立访客数（无 Cookie 哈希计算）      |
| visits           | 会话次数，用户一次连续访问算一个会话  |
| bounceRate       | 跳出率：只看 1 个页面就离开的会话占比 |
| session duration | 平均会话停留时长                      |
| 实时在线人数     | 当前活跃访问用户                      |
| 时间趋势         | 按小时 / 天 / 月的流量时序数据        |

## 二、多维度维度拆解（API 全部支持）

1. **页面维度**：各个页面路径访问排行，每个页面 PV/UV
2. **来源渠道**：直接访问、外链来源网站、搜索引擎、社交平台
3. **设备终端**：移动端 / 桌面端
4. **浏览器、操作系统版本分布**
5. **地理地域**：国家、省份、城市访问分布
6. **UTM 营销参数**：utm_source、utm_medium、utm_campaign，统计推广渠道效果Umami

## 三、自定义事件分析（业务埋点，适合你的 OJ 系统）

可以 JS 埋点追踪任意业务行为：登录、注册、提交题目、点击按钮、下载文件。

```
umami.track('submit_problem', {problemId:1001, result:"ac"})
```

可分析：

- 事件触发次数、事件时间趋势
- 事件附带属性筛选统计（比如哪道题目提交最多）

> OJ 场景：统计注册按钮点击、做题提交事件、登录事件。

## 四、V3 高级行为分析（重点区分：哪些可以 API 拿原始数据，哪些 UI 组件依赖 Umami 前端）GitHub

### ✅ 可以拿到原始数据，可接入自研后台

1. **Funnel 转化漏斗** 配置访问路径序列，看每一步用户流失率。 例：访问首页 → 打开题目页 → 提交代码 → AC 通过；看哪一步大量流失。
2. **Segments 用户分段** 保存筛选条件，例如：“来自国内手机端访客”，复用筛选条件做统计。
3. **Cohorts 用户队列 & 留存分析** 按某一批触发事件的用户做留存，比如 “8 月注册用户后续回访情况”。
4. **Goals 业务目标统计** 将事件设置为业务目标，统计目标完成量、完成率。
5. **User Journey 用户旅程（PG15+）** 用户页面流转路径，看用户浏览顺序。

### ⚠️仅可拿到元数据，渲染必须依赖 Umami 前端（iframe 或者复用组件）

1. **Session Replay 会话回放** 记录用户页面操作（点击、滚动、输入）；API 只能拿到回放列表元数据，**录像回放渲染必须 Umami 前端**，不能直接把视频拿到你自己页面渲染。
2. **Heatmaps 点击热力图** 页面点击、滚动热图；API 返回点击坐标原始点，热力图渲染组件依赖 Umami 前端。

### 其他追踪能力

- **短链接追踪 Links**：生成短链接统计点击量
- **像素埋点 Pixels**：图片埋点，外部邮件、第三方页面统计点击。

- CLS 布局偏移
- INP 交互延迟
- FCP 首屏时间、TTFB 后端响应时间

> 可以统计 OJ 各个页面加载性能。

## 六、过滤与对比能力

1. 多条件过滤：路径、国家、浏览器、事件属性、设备；
2. 时间段对比：本周 vs 上周，看指标涨跌。

## 七、哪些能力你可以完全脱离 Umami 前端，用自己页面展示

✅ **完全可以自研渲染（API 输出原始 JSON）**

- PV、UV、跳出率、时长、实时在线
- 页面排行、来源、浏览器、操作系统、地域分布
- UTM 渠道统计
- 自定义事件统计、事件时序
- 漏斗原始步骤数据、队列留存指标
- Core Web Vitals 性能指标

❌ **无法完全脱离 Umami 前端，只能 iframe 嵌入**

- 会话回放录屏
- 页面点击热力图

> 你的 OJ 后台场景：绝大多数业务统计（访问量、页面热度、注册提交埋点、性能指标）全部可以在你自己系统页面展示；只有想看录屏回放、热力图的时候，才需要打开 Umami 页面或者 iframe 嵌入。

## 八、不具备什么（重要边界）

1. **不采集后端接口调用、服务器 CPU、内存、QPS**；服务器监控依旧需要 Prometheus+Grafana。
2. **不能获取真实用户身份**，默认无 Cookie，只能匿名会话，拿不到账号 ID，除非你手动业务埋点传入 userId。
3. 没有内置告警、邮件报表（可以自己读取 Umami API，在 SpringBoot 做告警）。

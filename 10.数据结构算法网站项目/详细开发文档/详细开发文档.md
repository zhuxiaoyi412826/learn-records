## 二、运行代码流程（runCode）

### 2.1 流程图

```
用户点击「运行」
       │
       ▼
前端获取编辑器代码 + 自定义输入
       │
       ▼
POST /api/submissions/run
       │
       ▼
后端接收请求
       │
       ├── 1. 验证题目存在
       │
       ├── 2. 获取输入（自定义输入 或 第一个测试用例）
       │
       ├── 3. 调用 executeJavaCode() 沙箱执行
       │       │
       │       ├── 创建临时目录 (oj_judge_xxxxx)
       │       ├── 保存代码为 Main.java
       │       ├── javac -encoding UTF-8 Main.java
       │       │     ├── 编译超时 → 返回 CE
       │       │     └── 编译失败 → 返回 CE + 错误信息
       │       │
       │       ├── java -Xmx256m -Xss1m Main [input]
       │       │     ├── 运行超时 → 返回 TLE
       │       │     ├── 运行异常 → 返回 RE
       │       │     └── 运行成功 → 读取 stdout
       │       │
       │       └── 清理临时目录
       │
       └── 4. 返回 JSON 结果
               │
               ▼
前端展示运行结果（输出/错误/运行时间）
```

### 2.2 前端关键代码

**文件**: `AlgoVize/qianduan/js/oj.js` → `runCode()`

```javascript
async function runCode() {
    if (OJState.isRunning) return;
    const code = OJState.editor.getValue();    // 获取编辑器代码
    const lang = OJState.currentLanguage;
    const input = document.getElementById('ojCustomInput').value;

    // 验证
    if (!code.trim()) { displayRunResult({ status: 'error', message: '代码不能为空' }); return; }
    if (!OJState.currentProblem) { displayRunResult({ status: 'error', message: '请先选择一道题目' }); return; }

    OJState.isRunning = true;
    // 按钮显示加载状态...

    try {
        // 发送代码到后端运行
        const response = await fetch(`${API_BASE}/submissions/run`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({
                problemId: OJState.currentProblem.id,
                code: code,
                language: lang,
                input: input
            })
        });

        const data = await response.json();

        if (data.success) {
            const statusMap = {
                'SUCCESS': 'success',
                'CE': 'ce',
                'RE': 'error',
                'TLE': 'error'
            };
            displayRunResult({
                status: statusMap[data.status] || 'error',
                output: data.output || '',
                time: data.runtime || 0,
                message: data.compileError || data.error
            });
        }
    } catch (error) {
        displayRunResult({ status: 'error', message: '无法连接到服务器: ' + error.message });
    } finally {
        OJState.isRunning = false;
    }
}
```

```java
@PostMapping("/run")
public Map<String, Object> runCode(@RequestBody Map<String, Object> body) {
    Map<String, Object> result = new HashMap<>();

    Long problemId = ((Number) body.get("problemId")).longValue();
    String code = (String) body.get("code");
    String language = (String) body.get("language");
    String input = (String) body.get("input");

    // 1. 验证题目存在
    OJProblem problem = problemMapper.getProblemById(problemId);
    if (problem == null) { /* 返回错误 */ }

    // 2. 获取输入（无自定义输入时使用第一个测试用例）
    if (input == null || input.isEmpty()) {
        List<TestCase> testCases = testCaseMapper.findByProblemId(String.valueOf(problemId));
        if (!testCases.isEmpty()) {
            input = testCases.get(0).getInput();
        }
    }

    // 3. 沙箱执行
    Map<String, Object> runResult = executeJavaCode(code, input, problemId);

    // 4. 返回结果
    result.put("success", true);
    result.put("output", runResult.get("output"));
    result.put("status", runResult.get("status"));
    result.put("runtime", runResult.get("runtime"));
    result.put("compileError", runResult.get("compileError"));

    return result;
}
```

```java
private Map<String, Object> executeJavaCode(String userCode, String input, Long problemId) {
    Map<String, Object> result = new HashMap<>();
    Path tempDir = Files.createTempDirectory("oj_judge_");  // 创建临时目录

    // 1. 保存用户代码为 Main.java
    Path javaFile = tempDir.resolve("Main.java");
    Files.writeString(javaFile, userCode);

    // 2. 编译
    ProcessBuilder compilePB = new ProcessBuilder("javac", "-encoding", "UTF-8", "Main.java");
    compilePB.directory(tempDir.toFile());
    Process compileProcess = compilePB.start();
    boolean compileDone = compileProcess.waitFor(2500, TimeUnit.MILLISECONDS);

    if (compileExitCode != 0) {
        result.put("status", "CE");
        result.put("compileError", compileOutput);
        return result;
    }

    // 3. 运行（限制内存256MB、超时5秒）
    List<String> cmd = new ArrayList<>();
    cmd.add("java");
    cmd.add("-Xmx256m");                          // 内存限制
    cmd.add("-Xss1m");                            // 栈大小
    cmd.add("-Djava.security.manager=allow");     // 安全管理器
    cmd.add("Main");
    if (!inputStr.isEmpty()) {
        cmd.add(inputStr);                        // 输入通过命令行参数传递
    }

    ProcessBuilder runPB = new ProcessBuilder(cmd);
    runPB.directory(tempDir.toFile());
    Process runProcess = runPB.start();
    boolean runDone = runProcess.waitFor(5000, TimeUnit.MILLISECONDS);

    // 4. 收集结果
    String runOutput = new String(runProcess.getInputStream().readAllBytes());
    String runError = new String(runProcess.getErrorStream().readAllBytes());

    result.put("status", "SUCCESS");
    result.put("output", runOutput);
    result.put("runtime", runTime);

    // 5. 清理临时目录
    Files.walk(tempDir).sorted(Comparator.reverseOrder())
        .map(Path::toFile).forEach(File::delete);

    return result;
}
```

## 三、提交代码流程（submitCode）

### 3.1 流程图

```
用户点击「提交」
       │
       ▼
前端获取编辑器代码
       │
       ▼
POST /api/submissions（提交代码）
       │
       ▼
后端接收请求
       │
       ├── 1. 验证题目存在
       │
       ├── 2. 生成 submissionId（SUB + 时间戳 + UUID）
       │
       ├── 3. 保存提交记录到数据库（状态=PENDING）
       │
       ├── 4. 异步线程执行判题 judgeCode()
       │       │
       │       ├── 获取所有测试用例
       │       │
       │       ├── 遍历每个测试用例：
       │       │     │
       │       │     ├── 调用 executeJavaCode() 执行代码
       │       │     │
       │       │     ├── 编译错误 → 状态=CE，终止
       │       │     ├── 运行时错误 → 状态=RE，终止
       │       │     ├── 运行超时 → 状态=TLE，终止
       │       │     │
       │       │     └── 比对输出：
       │       │           ├── 匹配 → 通过+1
       │       │           └── 不匹配 → 状态=WA
       │       │
       │       └── 更新数据库（最终状态 + 判题日志）
       │
       └── 5. 立即返回 submissionId 给前端
               │
               ▼
前端开始轮询判题结果
       │
       ├── 每 500ms 调用 GET /api/submissions/{submissionId}
       │
       ├── 状态 = PENDING → 继续轮询
       │
       └── 状态 = AC/WA/CE/RE/TLE → 判题完成，展示结果
```

### 3.2 前端关键代码

**文件**: `AlgoVize/qianduan/js/oj.js` → `submitCode()`

```javascript
async function submitCode() {
    const code = OJState.editor.getValue();
    const lang = OJState.currentLanguage;

    // 验证
    if (!code.trim()) { /* 提示代码不能为空 */ return; }

    OJState.isSubmitting = true;

    try {
        // ========== 第1步：提交代码 ==========
        const submitResponse = await fetch(`${API_BASE}/submissions`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({
                problemId: OJState.currentProblem.id,
                code: code,
                language: lang,
                userId: 1,
                username: '前端用户'
            })
        });

        const submitData = await submitResponse.json();
        const submissionId = submitData.submissionId;

        // ========== 第2步：轮询判题结果 ==========
        const maxPollCount = 30;  // 最多轮询30次
        let pollCount = 0;

        while (pollCount < maxPollCount) {
            await new Promise(resolve => setTimeout(resolve, 500));  // 等待500ms

            const detailResponse = await fetch(`${API_BASE}/submissions/${submissionId}`);
            const detailData = await detailResponse.json();

            if (detailData.success && detailData.submission) {
                const status = detailData.submission.status;

                if (status !== 'PENDING' && status !== 'JUDGING') {
                    // 判题完成，展示结果
                    const statusMap = {
                        'AC': 'accepted', 'WA': 'wa', 'CE': 'ce',
                        'RE': 're', 'TLE': 'tle', 'MLE': 'tle'
                    };

                    displayJudgeResult({
                        status: statusMap[status],
                        passedCount: /* 解析日志 */,
                        totalCount: /* 解析日志 */,
                        time: submission.runtime,
                        message: submission.judgeLog
                    });
                    break;
                }
            }
            pollCount++;
        }
    } catch (error) {
        /* 错误处理 */
    } finally {
        OJState.isSubmitting = false;
    }
}
```

```java
@PostMapping
public Map<String, Object> submitCode(@RequestBody Map<String, Object> body) {
    Long problemId = ((Number) body.get("problemId")).longValue();
    String code = (String) body.get("code");
    String language = (String) body.get("language");
    Long userId = body.get("userId") != null ? ((Number) body.get("userId")).longValue() : null;

    // 1. 验证题目
    OJProblem problem = problemMapper.getProblemById(problemId);

    // 2. 生成提交ID
    String submissionId = "SUB" + System.currentTimeMillis()
                        + UUID.randomUUID().toString().substring(0, 8);

    // 3. 保存提交记录（状态=PENDING）
    Submission submission = new Submission();
    submission.setSubmissionId(submissionId);
    submission.setProblemId(problemId);
    submission.setProblemTitle(problem.getTitle());
    submission.setUserId(userId);
    submission.setCode(code);
    submission.setLanguage(language);
    submission.setStatus("PENDING");
    submission.setSubmitTime(LocalDateTime.now());
    submissionMapper.insertSubmission(submission);

    // 4. 异步判题（不阻塞响应）
    judgeCode(submissionId, problem, code);

    // 5. 立即返回 submissionId
    result.put("success", true);
    result.put("submissionId", submissionId);
    return result;
}
```

### 3.4 异步判题关键代码

**文件**: `AlgoVize/houduan/.../SubmissionController.java` → `judgeCode()`

```java
private void judgeCode(String submissionId, OJProblem problem, String code) {
    new Thread(() -> {
        // 1. 获取所有测试用例
        List<TestCase> testCases = testCaseMapper.findByProblemId(String.valueOf(problemId));

        int passedCount = 0;
        String finalStatus = "AC";
        StringBuilder judgeLog = new StringBuilder();

        // 2. 遍历每个测试用例
        for (int i = 0; i < testCases.size(); i++) {
            TestCase tc = testCases.get(i);

            // 调用沙箱执行
            Map<String, Object> runResult = executeJavaCode(code, tc.getInput(), problemId);

            // 检查编译错误
            if ("CE".equals(runResult.get("status"))) {
                finalStatus = "CE";
                break;
            }

            // 检查运行时错误
            if ("RE".equals(runResult.get("status"))) {
                finalStatus = "RE";
                break;
            }

            // 比对输出（标准化：去空格、去换行）
            String actualOutput = runResult.get("output").toString().trim().replaceAll("\\s+", " ");
            String expectedOutput = tc.getOutput().trim().replaceAll("\\s+", " ");

            if (actualOutput.equals(expectedOutput)) {
                passedCount++;
                judgeLog.append("测试用例 #").append(i + 1).append(": 通过\n");
            } else {
                finalStatus = "WA";
                judgeLog.append("测试用例 #").append(i + 1).append(": 答案错误\n");
                judgeLog.append("  期望: ").append(expectedOutput).append("\n");
                judgeLog.append("  实际: ").append(actualOutput).append("\n");
            }
        }

        // 3. 更新数据库
        submissionMapper.updateSubmissionStatus(
            submissionId, finalStatus, avgRuntime, usedMemory,
            errorMessage, judgeLog.toString()
        );
    }).start();
}
```

## 五、判题状态说明

| 状态    | 含义       | 触发条件             | 前端展示     |
| ------- | ---------- | -------------------- | ------------ |
| PENDING | 等待判题   | 提交成功后初始状态   | 加载中...    |
| AC      | 通过       | 所有测试用例输出正确 | ✅ 通过       |
| WA      | 答案错误   | 输出与期望不匹配     | ❌ 答案错误   |
| CE      | 编译错误   | javac 编译失败       | ⚠️ 编译错误   |
| RE      | 运行时错误 | 运行时抛出异常       | ❌ 运行时错误 |
| TLE     | 运行超时   | 运行超过 5 秒        | ⏱️ 运行超时   |

## 六、沙箱安全机制

| 机制         | 实现方式                                       |
| ------------ | ---------------------------------------------- |
| 内存限制     | JVM 参数 `-Xmx256m`                            |
| 栈大小限制   | JVM 参数 `-Xss1m`                              |
| 运行超时     | `Process.waitFor(5000, TimeUnit.MILLISECONDS)` |
| 编译超时     | `Process.waitFor(2500, TimeUnit.MILLISECONDS)` |
| 安全管理器   | JVM 参数 `-Djava.security.manager=allow`       |
| 临时目录隔离 | 每次执行创建独立临时目录，执行后清理           |
| 进程强制终止 | 超时后调用 `destroyForcibly()`                 |

## 一、数据表的设计

### 1.1 表结构：`announcement` 公告表

```sql
DROP TABLE IF EXISTS `announcement`;
CREATE TABLE `announcement` (
    `id`           BIGINT        NOT NULL AUTO_INCREMENT  COMMENT '主键',
    `title`        VARCHAR(200)  NOT NULL                 COMMENT '公告标题',
    `content`      TEXT                                   COMMENT '公告正文',
    `type`         VARCHAR(20)   DEFAULT 'notice'         COMMENT '类型：notice公告/update更新/maintenance维护/warning警告/event活动/info通知',
    `is_top`       TINYINT(1)    DEFAULT 0                COMMENT '是否置顶：0否 1是',
    `sort_order`   INT           DEFAULT 0                COMMENT '排序号，数字越小越靠前',
    `status`       VARCHAR(20)   DEFAULT 'draft'          COMMENT '状态：published=已发布 draft=草稿 expired=过期',
    `publish_time` DATETIME      DEFAULT NULL             COMMENT '发布时间',
    `create_time`  DATETIME      DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`  DATETIME      DEFAULT CURRENT_TIMESTAMP COMMENT '最后更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_announcement_status`      (`status`),
    KEY `idx_announcement_sort_order`  (`sort_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='公告表';
```

### 1.2 字段说明

| 字段         | 类型         | 必填 | 说明                                                         |
| ------------ | ------------ | ---- | ------------------------------------------------------------ |

| content      | TEXT         | -    | 公告正文（支持 HTML 渲染）                                   |

| is_top       | TINYINT(1)   | -    | 置顶标记：`0`=否，`1`=是，默认 `0`                           |
| sort_order   | INT          | -    | 同等级内的排序号，越小越靠前                                 |

### 2.6 核心实现细节

#### 2.6.1 状态规范化 `normalizeStatus()`

```java
/**
 * 将数据库存储的各种 status 值统一为 published / draft
 * 兼容：整数(0/1)、大小写英文字符串
 */
private String normalizeStatus(String rawStatus) {
    if (rawStatus == null) return "draft";
    String s = rawStatus.trim();
    switch (s) {
        case "0":
        case "published":
        case "online":
        case "PUBLISHED":
        case "ONLINE":
        case "true":
            return "published";
        case "1":
        case "2":
        case "draft":
        case "DRAFT":
        case "offline":
        case "OFFLINE":
        case "false":
            return "draft";
        default:
            return s.toLowerCase();
    }
}
```

#### 2.6.2 兼容整数/字符串的 SQL 查询

```xml
<!-- 关键：用 CAST(status AS CHAR) 统一比较，整数和字符串都能命中 -->
<select id="getPublishedAnnouncements" resultMap="AnnouncementResultMap">
    SELECT * FROM announcement
    WHERE CAST(COALESCE(status, '') AS CHAR)
          IN ('0', 'published', 'ONLINE', 'PUBLISHED', 'online')
    ORDER BY COALESCE(is_top, 0) DESC,
             COALESCE(sort_order, 0) ASC,
             COALESCE(publish_time, create_time) DESC
</select>
```

#### 2.6.3 创建公告时直接发布（`POST /api/announcements`）

```java
@PostMapping
public Map<String, Object> createAnnouncement(@RequestBody Map<String, Object> body) {
    Announcement a = new Announcement();
    a.setTitle((String) body.get("title"));
    a.setContent((String) body.get("content"));
    a.setType(body.get("type") != null ? (String) body.get("type") : "notice");
    a.setIsTop(Boolean.valueOf(String.valueOf(body.getOrDefault("isTop", false))));

    String status = body.get("status") != null ? (String) body.get("status") : "draft";
    a.setStatus(status);
    a.setSortOrder(announcementMapper.getMaxSortOrder() + 1);
    a.setCreateTime(LocalDateTime.now());
    a.setUpdateTime(LocalDateTime.now());

    // 核心：status=published 时立刻设置 publishTime
    if ("published".equals(status)) {
        a.setPublishTime(LocalDateTime.now());
    }

    announcementMapper.insert(a);

    result.put("success", true);
    result.put("message", "published".equals(status) ? "公告发布成功" : "公告创建成功");
    result.put("id", a.getId());
    return result;
}
```

### 3.4 常见问题排查

| 现象                                      | 原因                               | 解决                                                         |
| ----------------------------------------- | ---------------------------------- | ------------------------------------------------------------ |
| 前台返回 `announcements:[]`，后台查到数据 | 旧数据 `status=1`（草稿）          | `UPDATE announcement SET status=0, publish_time=NOW() WHERE id=xxx;` |
| 控制台 CORS 报错                          | 前端 origin 未在 CorsConfig 白名单 | 在 `CorsConfig.java` 的 `AllowedOriginPatterns` 追加         |
| 报 `Could not initialize Logback`         | logback-spring.xml DOCTYPE 错误    | 移除 DOCTYPE 行，或使用本文档版本                            |
| `status` 返回 `1` 不是 `published`        | 后端未重启                         | 修改代码后必须 `mvn spring-boot:run` 重启                    |
| 悬浮窗不弹出                              | 已读列表里有该 ID                  | 浏览器控制台：`localStorage.removeItem('readAnnouncementIds')` |

## 一、当前能抗多少并发？

### 各层瓶颈参数

| 层级                  | 参数                | 配置值                                             | 含义                                          |
| :-------------------- | :------------------ | :------------------------------------------------- | :-------------------------------------------- |
| Tomcat（HTTP）        | `threads.max`       | 300                                                | 最大 300 个请求线程同时处理，超出排队         |
| Tomcat（TCP）         | `max-connections`   | 10000                                              | TCP 最大连接数（不等于并发请求）              |
| Tomcat（等待队列）    | `accept-count`      | 200                                                | 线程满后最多 200 个请求排队等执行，再超就 503 |
| HikariCP（DB 连接池） | `maximum-pool-size` | **50**                                             | 最多 50 条活跃 DB 连接                        |
| MySQL 事务            | `@Transactional`    | 购买接口 1 次请求 = 1 个事务占 1 条连接直到 commit |                                               |

### 实际并发上限（硬瓶颈 = HikariCP = **50**）

`purchase()` 方法加了 `@Transactional`，整个流程（查商品→查用户→校验→扣币→写记录）占着一条 DB 连接直到事务 commit。HikariCP 最大连接数只有 **50**，这意味着**同时最多只有 50 个购买事务在进行**，即使 Tomcat 有 300 个线程，其余 250 个只能阻塞等连接。

所以：**理论上限 ≈ 50 并发购买同时进行**（50 QPS 如果每个事务耗时 1 秒；如果更快如 50ms，则可以达到约 1000 TPS）。

### 额外的隐性瓶颈

1. **cmd 打印是串行瓶颈**：`CoinServiceImpl.java#L94-L103` 每次购买做 8 次 `System.out.println()`。`System.out` 内部是 `synchronized` 的，高并发下所有线程会争同一把锁排队打印（100 人并发时性能可能骤降到几十 QPS）。

1. **登录前置开销**：脚本里每个购买线程先调 `/api/login/account` 登录，再调 `/api/coin/purchase`。登录流程也会用 DB 连接 + 创建 Session，叠加压力。

### 快速压测建议

先用 `batch_purchase_products.py` 跑 `CONCURRENT_BUYERS=100`，观察后端日志是否出现 `HikariPool-1 - Connection is not available, request timed out after 30000ms`（连接池耗尽）以及 cmd 输出卡顿，来验证实际上限。

## 二、如何解决超卖？

### ⚠️ 现状：当前代码**存在超卖漏洞**（Lost Update）

先看当前购买扣币的执行顺序（`CoinServiceImpl.java#L44-L91`）：

```
① SELECT coins = 1000 FROM user WHERE id = 1    ← 事务中读
② 应用层判断 if (1000 >= 120) ✅ 通过
③ UPDATE user SET coins = 880 WHERE id = 1      ← 用"计算好的绝对值"直接 SET
```

**竞态复现（初始余额 1000，单价 120）：**

| 时序 | 线程 A（请求 1）       | 线程 B（请求 2）              |
| :--- | :--------------------- | :---------------------------- |
| T1   | ① 读到 coins = 1000    |                               |
| T2   |                        | ① 读到 coins = 1000（同快照） |
| T3   | ② 判断 1000 ≥ 120 ✅    | ② 判断 1000 ≥ 120 ✅           |
| T4   | ③ UPDATE coins = 880 ✅ |                               |
| T5   |                        | ③ UPDATE coins = **880** ✅    |

**结果**：用户买了 2 件（应扣 240），余额却只从 1000 → 880，实际只扣了 120。**亏了 120 硬币 = 超卖发生**。

即便加了 `@Transactional`，MySQL 默认隔离级别是 `REPEATABLE READ`，普通 SELECT 是一致性快照读（不锁行），两个事务快照到同一个 1000。

------

### ✅ 正确的超卖防护方案（推荐方案三：原子扣减 + 条件判断，性能最佳）

**UserMapper 现有的扣币方法是绝对赋值**（`setCoins`，[UserMapper.java#L43-L44](file:///D:/daima/XiangMu/算法数据结构可视化/AlgoVize/houduan/src/main/java/com/algoviz/mapper/UserMapper.java#L43-L44)），必须改为：

SQL

```sql
-- 核心：在 SQL 原子里完成 "金额够不够？够就扣减" 两件事
-- 返回值 = 影响行数，1 表示成功，0 表示余额不足（无需 Java 判断）
UPDATE user 
   SET coins = coins - #{price},
       updated_at = NOW()
 WHERE id = #{id} 
   AND coins >= #{price}   -- 余额判断放在 SQL 条件里，天然并发安全
```

这是**单条原子 SQL**，InnoDB 对单行 UPDATE 内部自带行锁（`next-key lock`），同一用户的两个并发 UPDATE 必须排队：第一个扣成功后，第二个再看 `AND coins >= #{price}` 就不满足了，自动返回 0 行。

# 优化2

普通qps/s 事务qps/s 达到我要的要求 读取 10000 qps/s 写入事务 500 qps/s

## 目标拆解

先明确指标含义：

- **HTTP 5000 并发** = 同时有 5000 个 TCP 连接挂在 Tomcat 上
- **QPS 5000** = 每秒处理 5000 个 HTTP 请求
- **TPS 500** = 每秒 500 个购买事务（写 DB）

按 Little's Law（并发数 = QPS × 平均响应时间）：

- HTTP 层：5000 QPS × 0.05s（50ms 平均响应）= **250 个 worker 线程**就够
- DB 层：500 TPS × 0.1s（100ms 单事务）= **50 条活跃连接**实际使用，500 连接池严重过剩

**结论先行**：5000 QPS/500 TPS 这个量级**单机可达**，但需要解决三个真瓶颈——超卖、`System.out` 串行锁、MySQL `max_connections` 默认值。500 DB 连接池对单机 MySQL 是浪费且有害，建议降到合理值。

------

## 一、单机优化方案（推荐先做，能扛 5000 QPS）

### 1. Tomcat 线程池调优

[application.yml](file:///D:/daima/XiangMu/算法数据结构可视化/AlgoVize/houduan/src/main/resources/application.yml#L61-L77)

YAML

```yaml
server:
  tomcat:
    threads:
      max: 500              # 300→500，扛 5000 QPS（假设均响应 100ms）
      min-spare: 50         # 25→50，预热减少冷启动抖动
    max-connections: 10000  # 保持，5000 并发连接够用
    accept-count: 500       # 200→500，突发流量缓冲
    connection-timeout: 20000
    keep-alive-timeout: 20000
```

**为什么 max=500 而不是 5000**：线程是昂贵的（每线程约 1MB 栈内存），5000 线程会吃掉 5GB 内存且上下文切换开销巨大。500 线程 × 100ms 响应 = 5000 QPS，刚好匹配目标。

### 2. HikariCP 连接池调优（关键：不要设 500）

YAML

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 100    # 50→100，不是500！
      minimum-idle: 20
      connection-timeout: 30000
      idle-timeout: 600000
      max-lifetime: 1800000
      leak-detection-threshold: 30000
```

**为什么不是 500**：

- 公式：`池大小 = (TPS × 单事务耗时)` = 500 × 0.1s = **50 条够用**，留 2 倍冗余 = 100
- 500 连接会让 MySQL 每个连接占 ~4MB 内存 → 2GB 仅用于连接，且锁竞争反而下降性能
- HikariCP 官方建议：**池大小从 10 开始压测，不要盲目调大**（连接越多性能越差）

## 二、单机瓶颈与扩容触发点

当 QPS 持续超过 **8000** 或 TPS 超过 **1000** 时，单机会撞到这些墙：

1. **MySQL 写瓶颈**：单机 InnoDB 写入约 1000-2000 TPS 上限（取决于硬件），`coin_purchase` 表写入会成为热点
2. **JVM GC 抖动**：5000 QPS 下对象创建极快，G1 可能频繁 Young GC
3. **单点故障**：Tomcat 挂了全站不可用

**触发扩容的信号**：

- MySQL `Threads_running` 持续 > 100
- HikariCP `pending` 连接数 > 0 持续 30s
- 接口 P99 延迟 > 500ms

Spring Boot 用 `@Master` / `@Slave` 注解或 ShardingSphere 自动路由。

- 按 `user_id` 哈希分表（如 16 张表）

针对你"5000 QPS + 500 TPS"的目标，按顺序做：

| 步骤 | 动作                                                         | 效果                | 是否必须               |
| :--- | :----------------------------------------------------------- | :------------------ | :--------------------- |
| 1    | 修复超卖 + 移除 System.out + 商品缓存                        | 单机 5000 QPS       | ✅ 必须                 |
| 2    | Tomcat threads.max=500 + HikariCP=100 + MySQL max_connections=200 | 配置对齐目标        | ✅ 必须                 |
| 3    | JVM G1 + 4G 堆                                               | 减少 GC 抖动        | ✅ 必须                 |

```
    upstream backend_pool {
        server backend:8080;
        keepalive 64;               # 保持 64 个长连接到后端
    }

    # === 代理缓存 ===
    proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=api_cache:100m
                     max_size=1g inactive=10m use_temp_path=off;

    # === 限流 ===
    limit_req_zone $binary_remote_addr zone=api:100m rate=1000r/s;

    location /api/ {
        proxy_pass http://backend_pool/api/;
        proxy_set_header Connection "";  # 清除 Connection 头，启用 keepalive
        proxy_cache api_cache;
        proxy_cache_valid 200 302 5m;

    }

    location ~* \.(js|css|png|jpg|svg|gif|woff2)$ {
        root /usr/share/nginx/html;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
```

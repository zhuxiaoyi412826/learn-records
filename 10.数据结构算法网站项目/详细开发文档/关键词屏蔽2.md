# 编程题库关键词屏蔽与审核系统开发文档

## 一、项目概述

### 1.1 项目背景

编程题库系统已引入 EFK（Elasticsearch + Fluentd + Kibana）7.12.1 日志栈，现需在此基础上构建内容安全审核体系，对用户提交的代码、问题描述等内容进行敏感词检测与危害代码识别，实现违规内容的自动发现、日志归集、人工审核与最终入库的全流程闭环管理。

### 1.2 建设目标

- **自动检测**：对用户提交的代码内容、问题描述进行实时敏感词扫描与危害代码识别
- **日志归集**：命中规则的内容自动写入 Elasticsearch 专项索引，便于汇总分析
- **定时同步**：定期将 ES 中待审核数据同步至业务数据库
- **人工审核**：提供审核后台，支持人工判定违规类型与处理结果
- **闭环管理**：审核结果回写入库，形成检测 - 审核 - 处置的完整链路

### 1.3 检测范围

表格

| 检测类别   | 检测对象                             | 检测内容                                                     |
| ---------- | ------------------------------------ | ------------------------------------------------------------ |
| 辱骂类内容 | 问题标题、问题描述、代码注释、用户名 | 脏话、人身攻击、歧视性语言、恶意调侃                         |
| 危害代码   | 提交的源代码                         | 系统命令执行、文件删除、端口扫描、挖矿代码、后门程序、无限循环攻击 |

### 2.2 数据流向说明

1. **提交检测**：用户提交代码或问题时，敏感检测服务同步扫描内容，命中规则则标记违规等级与命中详情
2. **日志输出**：业务系统将提交内容 + 检测结果以结构化日志形式输出到日志文件
3. **Fluentd 采集**：Fluentd 实时采集日志文件，解析为结构化数据后写入 Elasticsearch 对应索引
4. **定时同步**：调度任务每 30 分钟从 ES 拉取新增待审核记录，同步至 MySQL 审核表
5. **人工审核**：运营人员通过审核后台查看待审记录，判定通过 / 驳回 / 封禁
6. **结果入库**：审核结果更新至业务库，同步触发对应业务处置（如内容下架、用户封禁）

## 四、核心模块详细设计

### 4.1 敏感内容检测模块

#### 4.1.1 检测层级设计

采用**三层检测架构**，兼顾性能与准确率：

**第一层：AC 自动机快速匹配（毫秒级）**

- 基于敏感词库构建前缀树，实现多模式快速匹配
- 覆盖辱骂词、政治敏感词、违规广告等确定型词汇
- 支持全匹配、模糊匹配、拼音变体检测

**第二层：正则规则匹配（十毫秒级）**

- 针对危害代码编写专用正则规则
- 检测危险函数调用、系统命令、文件操作等模式
- 支持按编程语言分类规则

**第三层：语义加权评分（可配置开启）**

- 对上下文进行语义分析，降低误报率
- 结合命中位置、频次、上下文进行风险评分
- 高分自动标记为高危，低分进入人工复核

#### 4.1.2 辱骂词检测规则

```
检测维度：
- 基础脏词库：约 2000+ 条常用辱骂词汇
- 变体识别：谐音、拼音、拆字、符号插入等变体
- 上下文判定：单独出现的疑似词不触发，结合语境评分
- 分级机制：
  - 严重：直接辱骂、人身攻击 → 自动拦截 + 高危标记
  - 一般：低俗用语、不文明表达 → 待人工审核
  - 轻微：疑似词、边缘词汇 → 记录日志，不拦截
```

#### 4.1.3 危害代码检测规则

按编程语言分类建立规则库，核心检测项：

表格

| 风险类别 | 典型检测模式                                                | 风险等级 |
| -------- | ----------------------------------------------------------- | -------- |
| 命令执行 | `Runtime.exec()`、`os.system()`、`eval()`、`ProcessBuilder` | 高危     |
| 文件操作 | `rm -rf`、`File.delete()`、格式化磁盘相关 API               | 高危     |
| 网络攻击 | 端口扫描代码、Socket 批量连接、发包循环                     | 高危     |
| 恶意循环 | 死循环占用 CPU、内存爆炸代码                                | 中危     |
| 信息窃取 | 读取环境变量、读取系统文件、收集用户信息                    | 中危     |
| 挖矿特征 | 特定加密算法循环、矿池地址、挖矿关键词                      | 高危     |
| 后门特征 | 反向 Shell、远程代码执行模板                                | 高危     |

> 检测说明：代码检测以静态规则匹配为主，避免误判正常教学代码。对注释中的内容单独检测，代码逻辑区与注释区分开评分。

### 4.3 定时同步模块

#### 4.3.1 同步机制

采用**增量时间窗口同步**方案：

- 调度频率：每 30 分钟执行一次
- 时间窗口：查询上一个同步时间点至当前时间前 1 分钟的数据（留出写入缓冲）
- 去重策略：以 `submit_id` 为唯一键，MySQL 端唯一索引防重
- 同步范围：仅同步 `hit=true` 且 `sync_flag=false` 的记录
- 状态回写：同步成功后更新 ES 中 `sync_flag` 为 true

#### 4.3.2 同步流程

1. 读取 Redis 中记录的上次同步时间戳 `last_sync_time`
2. 构造 ES 查询：`submit_time > last_sync_time AND submit_time <= now - 60s AND hit=true AND sync_flag=false`
3. 分页滚动查询（scroll API），批量拉取数据
4. 批量写入 MySQL 审核表，冲突则跳过
5. 批量更新 ES 文档的 `sync_flag` 为 true
6. 更新 Redis 中的 `last_sync_time`
7. 记录同步日志：本次同步条数、成功数、失败数

#### 4.3.3 核心代码逻辑示意

```
// ES 查询构造
SearchSourceBuilder sourceBuilder = new SearchSourceBuilder();
BoolQueryBuilder query = QueryBuilders.boolQuery()
    .must(QueryBuilders.rangeQuery("submit_time").gt(lastSyncTime).lte(endTime))
    .must(QueryBuilders.termQuery("hit", true))
    .mustNot(QueryBuilders.termQuery("sync_flag", true));

// 滚动查询
SearchScrollRequest scrollRequest = new SearchScrollRequest(scrollId);
scrollRequest.scroll(TimeValue.timeValueMinutes(1));

// 批量写入 MySQL
auditRecordService.batchInsert(auditRecords);

// 批量更新 ES sync_flag
bulkProcessor.add(new UpdateRequest(index, docId)
    .doc(XContentFactory.jsonBuilder()
        .startObject()
        .field("sync_flag", true)
        .endObject()));
```

## 六、部署与配置方案

### 6.1 Elasticsearch 配置优化

**索引生命周期管理（ILM）**：

- 热阶段：0-7 天，主分片 3，副本 1
- 温阶段：7-30 天，分片收缩，只读
- 冷阶段：30-180 天，冻结存储
- 删除阶段：180 天后自动删除

**性能优化**：

- 审核日志索引设置 `refresh_interval: 30s`，提升写入性能
- `code_snippet` 字段设置 `index: false`，不建立倒排索引
- 开启 `_source` 压缩，节省存储空间

### 6.2 Fluentd 部署

- 采用 Sidecar 或 DaemonSet 方式部署，与业务服务同节点
- 配置缓冲队列：`buffer_chunk_limit 2M`、`buffer_queue_limit 64`
- 配置重试机制：网络抖动时自动重试，避免日志丢失
- 监控 Fluentd 队列长度，超过阈值告警

### 6.3 检测服务部署

- 独立微服务部署，与业务系统解耦
- 敏感词库预热加载到内存，启动时构建 AC 自动机
- 规则变更通过 Redis 发布订阅机制热更新，无需重启
- 支持水平扩展，应对提交高峰

------

## 七、关键业务流程

### 7.1 代码提交流程

1. 用户在前端提交代码
2. 业务系统调用敏感检测服务进行扫描
3. 检测服务返回风险等级与命中详情
4. 业务系统判断：
   - 高危：直接拦截，提示内容违规
   - 中危：允许提交但标记待审
   - 低危 / 正常：正常提交
5. 业务系统输出结构化审计日志
6. Fluentd 采集日志写入 Elasticsearch
7. 定时任务同步至 MySQL 审核表
8. 人工审核后执行对应处置

### 7.2 规则更新流程

1. 运营人员在后台新增 / 修改敏感词或代码规则
2. 管理后台更新数据库并发布 Redis 消息
3. 检测服务订阅消息，重新加载规则到内存
4. 记录规则变更日志，便于追溯

## 八、性能与安全考量

### 8.1 性能指标

- 单条内容检测耗时：< 50ms（常规内容）
- 检测服务 QPS：单节点 ≥ 500
- Fluentd 采集延迟：< 10s
- ES 写入性能：单节点 ≥ 5000 doc/s
- 定时同步：万级数据 5 分钟内完成

### 8.2 安全措施

- 代码快照存储加密，避免二次泄露
- 审核后台权限控制，操作日志全程留痕
- Elasticsearch 配置账号密码与 IP 白名单
- 敏感词库与规则库定期备份
- 检测服务接口鉴权，防止恶意调用

### 8.3 误报优化机制

- 建立误报样本库，持续优化规则
- 支持白名单机制，特定场景跳过检测
- 高频误报规则自动降级处理
- 定期复盘审核数据，迭代检测准确率

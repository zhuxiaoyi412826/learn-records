# 发布题解评论功能综合复习文档

## 一、整体业务流程

```
[前端用户输入评论]
        │
        ▼
[Controller: 校验用户 / 回填题解ID]
        │
        ▼
[Service.publish: 敏感词检测] ◄────── MySQL(词库) ──► Redis(缓存) ──► DFA内存(前缀树)
        │
        ▼
   检测结果三档分支
        ├── HIGH 级 → 拦截(BLOCK)，返回前端提示修改
        ├── MEDIUM 级 → 放行但标记 pending(待人工审核)
        └── LOW/NONE 级 → 直接放行(logonly/none)
        │
        ▼
[写入 MySQL oj_solution_comment 表]
        │   ├── 回填 root_id（顶层=自身ID，子评论=父root_id）
        │   └── 题解 comment_count +1
        │
        ▼
[写入审计日志 content_audit_log]
        │
        ▼
返回前端 {success, auditStatus, riskLevel, commentId}
        │
        ▼
[用户侧查询评论列表]
        │   └── maskContent()：DFA 命中词替换为 * 显示
        │
        ▼
[后台人工审核]
        ├── 待审核(pending) → 通过 → auditStatus=passed, status=PUBLISHED
        └── 待审核(pending) → 驳回 → auditStatus=rejected, status=HIDDEN
```

## 三、关键流程细节

### 3.1 敏感词库管理（词源层）

- **存储**：MySQL `sensitive_word`（工作区）+ `sensitive_word_version`（快照版）
- **缓存**：Redis key `audit:words:cache`（JSON 序列化，TTL 默认 600s），失效自动回源 MySQL
- **内存 DFA**：`trieCache` + `trieFingerprint`（指纹=size@lastId@firstId），词表变化时重建
- **版本发布**：冻结工作区 JSON 快照到 `sensitive_word_version`，版本号自增；回滚时快照写回工作区

**关键代码（SensitiveWordService.java）**：
```java
/** 启用词列表：Redis -> MySQL（Redis 故障自动降级直查） */
public List<SensitiveWord> getEnabledWords() {
    try {
        String json = redis.opsForValue().get(CACHE_KEY);
        if (json != null) {
            return objectMapper.readValue(json, List.class);
        }
    } catch (Exception e) {
        log.warn("Redis 读取词库失败，降级 MySQL: {}", e.getMessage());
    }
    List<SensitiveWord> words = wordMapper.selectAllEnabled();
    try {
        redis.opsForValue().set(CACHE_KEY, objectMapper.writeValueAsString(words),
                Duration.ofSeconds(cacheTtlSeconds));
    } catch (Exception ignored) {}
    return words;
}

/** 获取 DFA（带内存缓存，词表变化自动重建） */
public DfaTrie getTrie() {
    List<SensitiveWord> words = getEnabledWords();
    String fp = words.size() + "@" + words.get(words.size()-1).getId();
    if (trieCache == null || !fp.equals(trieFingerprint)) {
        DfaTrie nt = new DfaTrie();
        for (SensitiveWord w : words) nt.insert(w.getWord());
        trieCache = nt;
        trieFingerprint = fp;
    }
    return trieCache;
}
```

### 3.2 DFA 前缀树匹配（算法层）

- **FUZZY 策略**：插入时剥离噪声字符（标点/空白/Emoji/控制字符）；匹配时遇到噪声跳过但不回退 root（对抗 赌*博、赌·博 变体）
- **连续噪声保护**：`MAX_CONSECUTIVE_NOISE=3`，超过 3 个噪声字符终止前缀，防止 "赌...千文...博" 误命中
- **命中保留原始下标**：`Hit.start` 是原文本位置，用于前端高亮 / 屏蔽替换

**关键代码（DfaTrie.java 匹配核心）**：
```java
public List<Hit> matchAll(String text) {
    for (int i = 0; i < n; i++) {
        Node cur = root;
        int j = i, noiseRun = 0;
        StringBuilder matched = new StringBuilder();
        while (j < n) {
            char ch = text.charAt(j);
            // 进入前缀后遇到噪声：跳过不回退 root
            if (cur != root && isNoise(ch)) {
                if (++noiseRun > MAX_CONSECUTIVE_NOISE) break;
                j++;
                continue;
            }
            if (isNoise(ch)) break; // root 下首字符必须有效
            cur = cur.next.get(ch);
            if (cur == null) break;
            noiseRun = 0;
            matched.append(ch);
            if (cur.end) {
                if (seen.add(matched.toString()))
                    hits.add(new Hit(i, matched.toString()));
            }
            j++;
        }
    }
    return hits;
}
```

### 3.3 内容检测引擎（风险判定层）

- **双层检测**：敏感词 DFA + 危险代码正则（按 language 过滤规则）
- **分数累加**：HIGH=90，MEDIUM=60，LOW=30，多命中累加（上限 1000）
- **preCheck 判定**：
  - `HIGH` → `preCheck=BLOCK, auditStatus=blocked`（直接拦截）
  - `MEDIUM` → `preCheck=PASS, auditStatus=pending`（放行+待人工审）
  - `LOW` → `preCheck=PASS, auditStatus=logonly`（放行+仅记录）
  - 无命中 → `auditStatus=none`

**关键代码（AuditDetectService.java）**：
```java
public DetectResult detect(String contentType, String language, String title, String content) {
    String fullText = title + "\n" + content;

    // 第一层：敏感词 DFA
    List<DfaTrie.Hit> wordHits = wordService.getTrie().matchAll(fullText);
    for (DfaTrie.Hit h : wordHits) {
        SensitiveWord w = meta.get(h.word());
        int s = switch (level) {
            case "HIGH" -> 90; case "LOW" -> 30; default -> 60;
        };
        hits.add(new HitDetail("SENSITIVE_WORD", w.getId(), h.word(),
                "["+category+"/"+level+"]", s));
        score += s;
        maxLevel = maxLevel(maxLevel, level);
    }

    // 第二层：危险代码正则
    for (CompiledRule cr : ruleService.getCompiledRules()) {
        if (!language.equals(rule.getLanguage())) continue;
        Matcher m = cr.pattern().matcher(fullText);
        if (m.find()) { /* hits.add(...) */ }
    }

    r.setRiskLevel(maxLevel);
    if ("HIGH".equals(maxLevel)) {
        r.setPreCheck("BLOCK"); r.setAuditStatus("blocked");
    } else if ("MEDIUM".equals(maxLevel)) {
        r.setPreCheck("PASS"); r.setAuditStatus("pending");
    }
    return r;
}
```

### 3.4 评论发布（业务层）

**流程**：用户 Controller 传入 → 调 `AuditDetectService.detect()` → BLOCK 直接返回拒绝 → 非 BLOCK 入库 + 回填 root_id + 评论数 +1 + 审计日志

**关键代码（OJSolutionCommentService.java）**：
```java
@Transactional
public PublishResult publish(OJSolutionComment c) {
    DetectResult d = auditDetectService.detect(
            "OJ_COMMENT", "ALL", null, c.getContent());

    if ("BLOCK".equals(d.getPreCheck())) {
        logAudit(c, d, "blocked");
        return new PublishResult(false, "评论包含违规内容，请修改后重新发布",
                d.getRiskLevel(), d.getAuditStatus(), null);
    }

    c.setAuditStatus(d.getAuditStatus());
    c.setRiskLevel(d.getRiskLevel());
    c.setDetectSummary(buildSummary(d));
    c.setStatus("PUBLISHED");
    commentMapper.insert(c);

    // 顶层评论：root_id=自身；子评论：复用父评论 root_id
    if (c.getParentId() == 0) {
        commentMapper.updateRootId(c.getId(), c.getId());
    } else {
        OJSolutionComment parent = commentMapper.selectById(c.getParentId());
        commentMapper.updateRootId(c.getId(), parent.getRootId());
    }

    solutionMapper.incrementCommentCount(c.getSolutionId(), 1);
    logAudit(c, d, d.getAuditStatus());
    return new PublishResult(true, "评论发布成功", ...);
}
```

### 3.5 用户侧查询（屏蔽返回）

- **maskContent()**：DFA 重新匹配评论内容，命中区间替换为 `*`
- **分级查询**：`listTopLevel`（顶层分页）→ `listReplies`（某 root_id 下子评论分页）

**关键代码（OJSolutionCommentService.java）**：
```java
/** 屏蔽：命中词替换为 * 字符 */
private String maskContent(String text) {
    List<DfaTrie.Hit> hits = wordService.getTrie().matchAll(text);
    char[] arr = text.toCharArray();
    for (DfaTrie.Hit h : hits) {
        int len = h.word().length();
        for (int i = h.start(); i < h.start()+len && i < arr.length; i++) {
            arr[i] = '*';
        }
    }
    return new String(arr);
}

/** 顶层评论列表（分页，带屏蔽） */
public PageResult<OJSolutionComment> listTopLevel(Long solutionId, int page, int pageSize) {
    int total = commentMapper.countTopLevel(solutionId);
    List<OJSolutionComment> list = commentMapper.selectTopLevel(solutionId,
            (page-1)*pageSize, pageSize);
    list.forEach(c -> {
        c.setMaskContent(maskContent(c.getContent()));
        c.setReplyCount(commentMapper.countReplies(c.getId()));
    });
    return PageResult.of(list, total, page, pageSize);
}
```

### 3.6 后台人工审核

**状态流转**：
```
pending（待审核） ──通过──► passed ─► status=PUBLISHED（正常展示）
                 └──驳回──► rejected ─► status=HIDDEN（前端不展示）
```

## 四、数据结构要点

### oj_solution_comment 表关键字段
| 字段 | 含义 |
|------|------|
| `parent_id` | 父评论 ID，0=顶层评论 |
| `root_id` | 顶层评论 ID；顶层=自身，子评论=顶层 ID（用于"查看全部回复"） |
| `audit_status` | none / logonly / pending / blocked / passed / rejected |
| `risk_level` | NONE / LOW / MEDIUM / HIGH |
| `detect_summary` | 命中摘要：`规则名(命中词); 规则名(命中词)` |
| `status` | PUBLISHED / HIDDEN |

### SensitiveWord（敏感词条目）
| 字段 | 含义 |
|------|------|
| `word` | 词原文 |
| `level` | HIGH / MEDIUM / LOW（决定分数/阻断策略） |
| `category` | POLITICS / PORN / VIOLENCE / AD / OTHER |
| `match_mode` | EXACT / FUZZY（当前全局 FUZZY） |
| `enabled` | 1=启用 |

## 五、不足之处（后续扩展）

1. **DFA 模式拆分**：当前全局 FUZZY。建议按 `match_mode` 拆分 `exactTrie + fuzzyTrie`，命中时记录 mode，避免 FUZZY 对 EXACT 词的过度敏感。

2. **异步审核**：当前发布流程是同步 DFA+正则。若词表/规则规模较大，建议改发布为"快速预检 BLOCK → 异步高风险重检（正则大集合）→ 更新 auditStatus"，降低 P99 延迟。

3. **ES 同步审计日志**：`AuditLogService` 目前写 MySQL + Fluentd。后续可把命中摘要、用户画像、content 索引到 ES，支持 Kibana 聚合分析"高频词、TOP 违规用户、时段曲线"。

4. **多级评论查询优化**：当前 `listReplies` 是按 `root_id` 全表扫描分页，数据量大后建议用 `(root_id, created_at)` 联合索引 + 游标分页。

5. **屏蔽白名单**：当前只有命中即屏蔽。建议增加"LOW 级在评论区显示原文，仅后台标记"的策略开关；或根据用户等级（VIP/高信誉）降低屏蔽强度。

6. **缓存穿透保护**：`getEnabledWords()` miss 时直接查 MySQL。若 Redis 全量故障且请求高，建议加本地 Caffeine 二级缓存，或布隆过滤器判断空集合。

7. **评论反灌水**：未做单位时间发表限流、同内容去重。后续可加：`userId+5min+hash(content)` 去重、BLOCK 次数多的用户强制待审。

8. **根评论串结构**：目前 root_id 回填是二级存储，超过二级回复（回复的回复）会扁平展示。如需树形 N 级，建议改为 `path` 字段存储祖先链（MySQL CTE 或 Materialized Path）。

9. **审核工作台队列**：当前后台只是简单关键词+状态筛选。后续可加"自动派单、审核速度、审核一致性（多人交叉判题）、封禁申诉"。

10. **前端展示**：目前 maskContent 是 *** 占位，后续可改为高亮命中词（背景色 + tooltip 展示命中等级/类别），提升用户体验。

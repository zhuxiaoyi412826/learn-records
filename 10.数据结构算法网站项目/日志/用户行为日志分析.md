前端埋点 后端接收

## 一、用户行为日志包含哪些内容（字段设计）

用户行为日志核心字段，埋点时就要打印出来：

表格

| 字段        | 说明                                                         |
| ----------- | ------------------------------------------------------------ |
| `traceId`   | 链路追踪 ID，串联一次完整请求                                |
| `userId`    | 登录用户 ID，未登录为空                                      |
| `sessionId` | 会话 ID，区分同一个浏览器多次访问                            |
| `eventTime` | 行为发生时间                                                 |
| `eventName` | 事件名：page_view 页面浏览 /search 搜索 /click 点击 /collect 收藏 /share 分享 /error 报错 |
| `pageUrl`   | 访问页面地址                                                 |
| `keyword`   | 搜索关键词（你的面试题系统 ES 搜索行为）                     |
| `targetId`  | 目标业务 ID，如面试题 id                                     |
| `device`    | 设备：移动端 /pc                                             |
| `os`        | 操作系统                                                     |
| `browser`   | 浏览器                                                       |
| `ip`        | 客户端 IP，可解析地域                                        |
| `duration`  | 页面停留时长                                                 |

> 两种埋点方式：

1. **前端埋点**：JS 上报，采集页面浏览、点击、停留时长；发送 http 请求上报行为日志。
2. **后端埋点**：Spring AOP / 拦截器，采集接口调用、搜索行为、收藏、登录，输出日志到文件。

## 二、完整技术选型（微服务）

### 方案 1：EFK（你已经了解）

```
Filebeat` → `Logstash/Fluentd` → `Elasticsearch` → `Kibana
```

- Filebeat：采集服务器磁盘上的日志文件，轻量，部署在各个微服务实例
- Fluentd/Logstash：清洗日志，过滤、格式化、ip 转地域、字段处理
- Elasticsearch：存储行为日志，做检索、聚合统计
- Kibana：可视化看板，画图表

### 方案 2：高吞吐大数据方案（用户量大）

`Filebeat` → `Kafka` → `Flink/Spark`实时计算 → `Elasticsearch / ClickHouse`存储

> 用户量很大时，不能直接打给 ES，中间加 Kafka 削峰，Flink 做实时计算；ClickHouse 非常适合行为日志 OLAP 统计分析。

表格

| 场景                          | 推荐存储      |
| ----------------------------- | ------------- |
| 查询、检索、Kibana 可视化     | Elasticsearch |
| 海量日志统计、UV/PV、多维分析 | ClickHouse    |

## 三、核心分析指标（面试题系统举例）

### 1. 流量指标

- PV：页面访问次数
- UV：独立用户访问数（按 userId/sessionId 去重）
- 搜索量：用户搜索总次数
- 热门搜索词 TOP10（正好对应你的 ES 搜索业务）

### 2. 用户行为

- 搜索后点击转化率：搜索之后是否点开题目详情
- 收藏率、分享率
- 用户访问路径：首页 → 搜索页 → 题目详情
- 用户留存：今日访问用户，后续是否再来

### 3. 质量指标

- 搜索无结果占比：很多搜索关键词返回空，代表需要补充题库
- 错误率：接口报错行为
- 平均页面停留时长

## 四、两种分析模式

### 1️⃣ 实时分析（近实时，秒 / 分钟级别）

Flink 消费 Kafka 中的行为日志，实时聚合：

- 实时热门搜索词排行榜
- 当前在线人数
- 实时错误告警

### 2️⃣ 离线分析（T+1，凌晨跑批）

- 日 UV/PV、周、月统计
- 用户留存、用户画像
- 导出报表

## 五、落地实现细节（SpringBoot 微服务）

### 方式 A：AOP 输出行为日志到本地文件

写 AOP 拦截搜索、收藏接口，直接输出 JSON 格式日志。Filebeat 采集这个日志文件。

```
// AOP 记录用户搜索行为日志示例
@Around("execution(* com.xxx.problem.controller.ProblemController.search(..))")
public Object recordSearchLog(ProceedingJoinPoint joinPoint) throws Throwable{
    // 获取userId、keyword、traceId、ip
    // 打印JSON日志到磁盘，filebeat采集
    log.info("【user_behavior】{}", JSON.toJSONString(behaviorLog));
    return joinPoint.proceed();
}
```

Filebeat 读取日志文件，发送到 Fluentd，清洗后写入 ES。

> 日志**打印 JSON 格式**，方便后续解析，不要打印非结构化文本。

### 方式 B：直接发送到 Kafka

高并发场景，不写磁盘，AOP 直接把行为事件发送 kafka 主题，下游 Flink 消费。

## 六、ES 聚合示例（统计热门搜索词 TOP10）

行为日志存入 ES，`eventName="search"`代表搜索事件，用 terms 聚合：

```
GET user_behavior_log/_search
{
  "size": 0,
  "query": {
    "term": {
      "eventName": "search"
    }
  },
  "aggs": {
    "hot_keyword": {
      "terms": {
        "field": "keyword.keyword",
        "size": 10
      }
    }
  }
}
```

拿到搜索最多的关键词，业务可以：把高频无结果的关键词用来补充题库。

## 七、ClickHouse 适合做什么？

> ClickHouse 是 OLAP 数据库，擅长海量行为日志**聚合统计**，count、sum、group by 速度极快； 不适合复杂全文检索，搜索还是交给 ES。 典型 SQL：统计每日 UV/PV

```
SELECT eventTime, count(DISTINCT userId) as uv, count(*) as pv
FROM user_behavior
WHERE eventName='page_view'
GROUP BY eventTime
ORDER BY eventTime;
```

## 八、常见坑

1. UV 统计不能 count (*)，**必须去重 userId/sessionId**
2. 时间字段格式一定要规范，避免聚合失败
3. 日志量巨大，ES 一定要设置生命周期 ILM，7 天 / 30 天自动删除旧日志，防止磁盘占满
4. 高并发场景禁止直接写入 ES，中间加 Kafka 缓冲，防止 ES 被打挂
5. 埋点不要阻塞主业务线程：行为日志属于旁路数据，异步处理，不能影响用户正常接口响应

## 九、整体架构简图

```
前端埋点 / SpringAOP后端埋点
        ↓
输出JSON行为日志（本地文件 / 发送Kafka）
        ↓
Filebeat采集日志文件
        ↓
Kafka（削峰缓冲，大流量必加）
        ↓
Fluentd / Flink：清洗、转换、IP解析地域
        ↓
├─→ Elasticsearch：检索，Kibana看板，查询明细日志
└─→ ClickHouse：海量离线统计UV、PV、留存
```

# 前端浏览器日志采集开发文档（Kafka + Fluentd + Elasticsearch 7.12.1）

## 1. 方案概述

本方案面向高并发 Web 场景，实现前端浏览器侧日志的全链路采集：前端 SDK 统一捕获异常与性能数据 → 通过 HTTP 接入层写入 Kafka 消息队列 → Fluentd 消费 Kafka 并完成日志清洗结构化 → 最终写入 Elasticsearch 7.12.1，在 Kibana 中实现按日志类型分类检索与可视化。

> 说明：浏览器无法直接使用 Kafka 原生 TCP 协议，因此通过**HTTP 接入层（后端接口 / Kafka REST Proxy）** 完成消息投递，实现前端到 Kafka 的安全接入。

## 2. 整体架构

```
前端浏览器 SDK
    ↓ （HTTP POST 上报）
Kafka 接入层（REST Proxy / 业务后端接口）
    ↓ （写入消息队列）
Kafka Cluster → Topic: frontend_logs_topic
    ↓ （Fluentd 消费）
Fluentd (in_kafka 输入 + filter 清洗 + out_elasticsearch 输出)
    ↓
Elasticsearch 7.12.1 → 索引: frontend-logs-YYYY.MM.DD
    ↓
Kibana → 按 log_type 字段区分各类日志，检索与仪表盘
```

## 3. 采集范围与字段规范

### 3.1 采集项清单

表格

| 日志类型 `log_type` | 说明                                        |
| ------------------- | ------------------------------------------- |
| `js_error`          | JS 运行时错误、未捕获异常、语法错误         |
| `promise_error`     | 未捕获的 Promise 拒绝异常                   |
| `api_exception`     | 接口请求异常：4xx/5xx、跨域、超时、网络错误 |
| `blank_screen`      | 页面白屏检测结果                            |
| `performance`       | 页面加载性能指标                            |

### 3.2 通用基础字段

所有日志统一携带以下字段，用于 Kibana 筛选与问题定位：

表格

| 字段名       | 类型   | 说明                          |
| ------------ | ------ | ----------------------------- |
| `log_type`   | string | 日志类型，用于 Kibana 分类    |
| `timestamp`  | string | 浏览器端发生时间 ISO8601 格式 |
| `page_url`   | string | 发生错误的页面 URL            |
| `user_agent` | string | 浏览器 UA 信息                |
| `browser`    | string | 浏览器名称                    |
| `os`         | string | 操作系统                      |
| `user_id`    | string | 可选，登录用户标识            |
| `trace_id`   | string | 可选，全链路追踪 ID           |

## 4. 前端 SDK 实现

### 4.1 SDK 设计原则

- 无框架依赖，原生 JS 实现，兼容主流浏览器
- 异步上报，不阻塞页面主流程
- 批量上报 + 本地缓存重试，避免网络波动丢数
- 错误自动去重，防止同错误刷屏打爆 Kafka

### 4.2 完整 SDK 代码

```
/**
 * 前端日志采集 SDK
 * 上报地址：Kafka REST Proxy / 后端接入接口
 */
(function (window) {
  const SDK_CONFIG = {
    // Kafka REST 代理地址 / 后端上报接口
    reportUrl: 'http://your-kafka-rest-proxy:8082/topics/frontend_logs_topic',
    // 批量上报最大条数
    maxBatchSize: 10,
    // 上报间隔 ms
    reportInterval: 3000,
    // 采样率 0-1，性能日志建议采样
    performanceSampleRate: 0.3,
    // 用户标识，可从业务注入
    userId: '',
    traceId: generateTraceId()
  };

  let logQueue = [];
  let timer = null;

  // 生成traceId
  function generateTraceId() {
    return 'web-' + Date.now() + '-' + Math.random().toString(36).slice(2, 10);
  }

  // 获取浏览器与系统信息
  function getEnvInfo() {
    const ua = navigator.userAgent;
    let browser = 'Unknown';
    let os = 'Unknown';

    if (/Chrome/.test(ua)) browser = 'Chrome';
    else if (/Firefox/.test(ua)) browser = 'Firefox';
    else if (/Safari/.test(ua)) browser = 'Safari';
    else if (/Edg/.test(ua)) browser = 'Edge';

    if (/Windows/.test(ua)) os = 'Windows';
    else if (/Mac OS/.test(ua)) os = 'MacOS';
    else if (/Android/.test(ua)) os = 'Android';
    else if (/iOS/.test(ua)) os = 'iOS';

    return { browser, os, user_agent: ua };
  }

  // 组装通用字段
  function buildBaseLog(logType) {
    const env = getEnvInfo();
    return {
      log_type: logType,
      timestamp: new Date().toISOString(),
      page_url: window.location.href,
      user_id: SDK_CONFIG.userId,
      trace_id: SDK_CONFIG.traceId,
      ...env
    };
  }

  // 加入队列
  function pushLog(log) {
    logQueue.push(log);
    if (logQueue.length >= SDK_CONFIG.maxBatchSize) {
      reportLogs();
    }
  }

  // 批量上报
  function reportLogs() {
    if (logQueue.length === 0) return;
    const batch = logQueue.splice(0, SDK_CONFIG.maxBatchSize);

    // Kafka REST Proxy 要求的格式
    const payload = {
      records: batch.map(item => ({ value: item }))
    };

    // 使用 navigator.sendBeacon 优先，页面关闭也能上报
    if (navigator.sendBeacon) {
      const blob = new Blob([JSON.stringify(payload)], { type: 'application/vnd.kafka.json.v2+json' });
      navigator.sendBeacon(SDK_CONFIG.reportUrl, blob);
    } else {
      fetch(SDK_CONFIG.reportUrl, {
        method: 'POST',
        headers: { 'Content-Type': 'application/vnd.kafka.json.v2+json' },
        body: JSON.stringify(payload),
        keepalive: true
      }).catch(() => {
        // 上报失败回塞队列，重试
        logQueue = logQueue.concat(batch);
      });
    }
  }

  // 定时上报
  function startTimer() {
    timer = setInterval(reportLogs, SDK_CONFIG.reportInterval);
    // 页面卸载前上报
    window.addEventListener('beforeunload', reportLogs);
  }

  // ========== 1. JS 全局错误捕获 ==========
  function initJsError() {
    window.onerror = function (message, source, lineno, colno, error) {
      const log = buildBaseLog('js_error');
      log.message = message;
      log.source = source;
      log.line = lineno;
      log.column = colno;
      log.stack = error ? error.stack : '';
      pushLog(log);
      return false;
    };
  }

  // ========== 2. 未捕获 Promise 异常 ==========
  function initPromiseError() {
    window.addEventListener('unhandledrejection', function (event) {
      const log = buildBaseLog('promise_error');
      log.message = event.reason ? String(event.reason) : 'Unhandled Promise Rejection';
      log.stack = event.reason?.stack || '';
      pushLog(log);
    });
  }

  // ========== 3. 接口异常拦截 ==========
  function initApiMonitor() {
    // 拦截 fetch
    const originFetch = window.fetch;
    window.fetch = function (...args) {
      return originFetch.apply(this, args)
        .then(response => {
          if (response.status >= 400) {
            const log = buildBaseLog('api_exception');
            log.url = args[0];
            log.status = response.status;
            log.status_text = response.statusText;
            log.method = args[1]?.method || 'GET';
            pushLog(log);
          }
          return response;
        })
        .catch(err => {
          const log = buildBaseLog('api_exception');
          log.url = args[0];
          log.method = args[1]?.method || 'GET';
          log.error_type = 'network_error'; // 网络错误/跨域/超时
          log.message = err.message;
          pushLog(log);
          throw err;
        });
    };

    // 拦截 XMLHttpRequest
    const originXhrOpen = XMLHttpRequest.prototype.open;
    const originXhrSend = XMLHttpRequest.prototype.send;
    XMLHttpRequest.prototype.open = function (method, url) {
      this._url = url;
      this._method = method;
      return originXhrOpen.apply(this, arguments);
    };
    XMLHttpRequest.prototype.send = function () {
      this.addEventListener('loadend', () => {
        if (this.status >= 400) {
          const log = buildBaseLog('api_exception');
          log.url = this._url;
          log.method = this._method;
          log.status = this.status;
          log.status_text = this.statusText;
          pushLog(log);
        }
      });
      this.addEventListener('error', () => {
        const log = buildBaseLog('api_exception');
        log.url = this._url;
        log.method = this._method;
        log.error_type = 'network_error';
        log.message = 'XHR request failed (CORS / network / timeout)';
        pushLog(log);
      });
      return originXhrSend.apply(this, arguments);
    };
  }

  // ========== 4. 页面白屏检测 ==========
  function initBlankScreenCheck() {
    // 页面加载完成后检测
    window.addEventListener('load', () => {
      setTimeout(() => {
        const rootElements = document.body.children;
        let emptyCount = 0;
        // 检测根节点是否为空
        for (let el of rootElements) {
          if (el.offsetHeight === 0) emptyCount++;
        }
        const isBlank = emptyCount / rootElements.length > 0.8;
        if (isBlank) {
          const log = buildBaseLog('blank_screen');
          log.message = '页面白屏检测触发';
          log.dom_depth = document.body.children.length;
          pushLog(log);
        }
      }, 2000);
    });
  }

  // ========== 5. 页面性能指标 ==========
  function initPerformance() {
    // 采样控制
    if (Math.random() > SDK_CONFIG.performanceSampleRate) return;

    window.addEventListener('load', () => {
      if (!window.performance) return;
      const timing = performance.timing;
      const log = buildBaseLog('performance');

      // 关键性能指标
      log.white_screen_time = timing.domLoading - timing.navigationStart; // 白屏时间
      log.dom_ready_time = timing.domContentLoadedEventEnd - timing.navigationStart; // DOM就绪时间
      log.page_load_time = timing.loadEventEnd - timing.navigationStart; // 页面完全加载时间
      log.dns_time = timing.domainLookupEnd - timing.domainLookupStart; // DNS解析耗时
      log.tcp_time = timing.connectEnd - timing.connectStart; // TCP连接耗时
      log.response_time = timing.responseEnd - timing.requestStart; // 后端响应耗时

      // 首屏最大内容绘制 LCP
      new PerformanceObserver((entryList) => {
        const entries = entryList.getEntries();
        const lastEntry = entries[entries.length - 1];
        log.lcp_time = lastEntry.startTime;
        pushLog(log);
      }).observe({ type: 'largest-contentful-paint', buffered: true });
    });
  }

  // 初始化SDK
  function init(options = {}) {
    Object.assign(SDK_CONFIG, options);
    initJsError();
    initPromiseError();
    initApiMonitor();
    initBlankScreenCheck();
    initPerformance();
    startTimer();
  }

  window.FrontLogSDK = { init };
})(window);
```

### 4.3 SDK 接入方式

在项目入口 HTML 的`<head>`中引入并初始化：

```
<script src="/path/to/front-log-sdk.js"></script>

```

## 5. Kafka 配置

### 5.1 Topic 规划

表格

| 配置项       | 值                    | 说明                          |
| ------------ | --------------------- | ----------------------------- |
| Topic 名称   | `frontend_logs_topic` | 前端日志专用主题              |
| 分区数       | 3~6                   | 按并发量调整，开发环境 3 分区 |
| 副本数       | 2                     | 生产环境建议 2 副本以上       |
| 消息保留时间 | 7 天                  | 可按存储调整                  |

### 5.2 接入层说明

- **开发测试**：部署 `Kafka REST Proxy`，前端直接通过 HTTP 上报到 REST 代理，自动写入 Kafka。
- **生产环境**：通过业务后端 / API 网关提供上报接口，做鉴权、限流、校验后再写入 Kafka，禁止 Kafka 端口直接暴露公网。

## 6. Fluentd 消费与清洗配置

### 6.1 安装 Kafka 输入插件

Windows td-agent 执行安装：

```
td-agent-gem install fluent-plugin-kafka
```

### 6.2 完整 td-agent.conf 配置

```
# ========== 输入：消费Kafka前端日志 ==========
<source>
  @type kafka
  brokers localhost:9092
  topics frontend_logs_topic
  consumer_group fluentd-frontend-group
  format json
  tag frontend.logs
  # 从最新位置开始消费
  start_from_beginning false
</source>

# ========== 日志清洗 Filter ==========
<filter frontend.logs>
  @type record_transformer
  enable_ruby true
  <record>
    # 追加Fluentd接收时间，作为ES时间戳基准
    "@timestamp" ${Time.now.utc.iso8601}
    # 追加环境标识
    env "dev"
    # 统一日志来源
    log_source "browser"
  </record>
  # 删除冗余字段，按需保留
  # remove_keys raw_message
</filter>

# 可选：按日志级别过滤，只保留错误，丢弃无效日志
<filter frontend.logs>
  @type grep
  <exclude>
    log_type debug
  </exclude>
</filter>

# ========== 输出：写入 Elasticsearch 7.12.1 ==========
<match frontend.logs>
  @type elasticsearch
  host 127.0.0.1
  port 9200
  # 按天滚动索引，Kibana可通过前缀匹配
  index_name frontend-logs-%{+%Y.%m.%d}
  logstash_format false

  # ES7 兼容配置，消除type废弃警告
  include_template false
  suppress_type_name true
  reload_connections false

  # 批量写入配置
  flush_interval 1s
  retry_max_times 5
  request_timeout 15s
</match>
```

### 6.3 配置说明

1. `in_kafka` 插件订阅 `frontend_logs_topic`，以 JSON 格式解析消息体。
2. 通过 `record_transformer` 补充统一元数据，保证 ES 字段规范。
3. 输出按天生成索引 `frontend-logs-YYYY.MM.DD`，与后端业务日志物理隔离。
4. 核心字段 `log_type` 完整保留，用于 Kibana 分类检索。

## 7. Elasticsearch 索引规范

### 7.1 索引命名

- 索引前缀：`frontend-logs-`
- 按天滚动：`frontend-logs-2026.08.17`
- 生命周期：默认保留 15 天，可通过 ILM 策略自动删除

### 7.2 核心映射（建议）

ES 7.12.1 动态映射可自动识别字段类型，建议对关键字段手动指定：

```
PUT _template/frontend-logs-template
{
  "index_patterns": ["frontend-logs-*"],
  "mappings": {
    "properties": {
      "@timestamp": { "type": "date" },
      "log_type": { "type": "keyword" },
      "browser": { "type": "keyword" },
      "os": { "type": "keyword" },
      "status": { "type": "integer" },
      "page_load_time": { "type": "integer" }
    }
  }
}
```

## 8. Kibana 日志区分与查询

### 8.1 创建索引模式

1. 进入 Kibana → Stack Management → Index Patterns → Create index pattern
2. 索引模式名称填写：`frontend-logs-*`
3. 时间字段选择：`@timestamp`
4. 点击创建，完成索引模式配置。

### 8.2 按日志类型区分查看

进入 **Discover** 页面，选择 `frontend-logs-*` 索引模式，在搜索框输入 KQL 语句即可分类筛选：

表格

| 筛选目标              | KQL 查询语句                                |
| --------------------- | ------------------------------------------- |
| 只看 JS 错误          | `log_type: js_error`                        |
| 只看接口异常          | `log_type: api_exception`                   |
| 白屏检测日志          | `log_type: blank_screen`                    |
| 性能指标日志          | `log_type: performance`                     |
| Chrome 浏览器的错误   | `log_type: js_error AND browser: Chrome`    |
| 状态码 500 的接口异常 | `log_type: api_exception AND status >= 500` |

### 8.3 可视化仪表盘建议

可基于该索引创建仪表盘：

- 每日 JS 错误数趋势图
- 各类型错误占比饼图
- 页面平均加载耗时趋势
- 浏览器维度错误分布

## 9. 联调验证步骤

1. **验证 Kafka 消息**：启动 Kafka 控制台消费者，前端触发错误，确认消息正常写入 Topic。
2. **验证 Fluentd 消费**：查看 td-agent 日志，无报错，且无 buffer 堆积。
3. **验证 ES 索引**：执行 `curl "http://127.0.0.1:9200/_cat/indices?v"`，确认 `frontend-logs-当天日期` 索引存在且文档数增长。
4. **验证 Kibana**：Discover 页面选择对应索引，调整时间范围，可检索到分类日志。

## 10. 生产注意事项

1. **安全防护**：禁止直接暴露 Kafka REST 端口到公网，必须经过业务后端鉴权与限流。
2. **采样策略**：性能日志开启采样，JS 错误 100% 上报，避免日志量暴涨。
3. **SourceMap**：生产 JS 代码压缩后，需配套 source-map 还原报错堆栈，提升排查效率。
4. **去重降噪**：SDK 侧增加错误去重逻辑，同页面同错误短时间内只上报一次。
5. **告警配置**：在 Kibana 中配置 JS 错误数阈值告警，异常暴涨及时通知。

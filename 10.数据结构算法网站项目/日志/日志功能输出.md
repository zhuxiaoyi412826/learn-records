# LogBack

SLF4J：统一日志接口，不做实际输出；Logback 真正干活的日志实现。

| 级别    | 使用场景                                     |
| ------- | -------------------------------------------- |
| `TRACE` | 跟踪细节，生产关闭                           |
| `DEBUG` | 开发调试，生产关闭                           |
| `INFO`  | 正常业务流程：启动成功、接口调用、任务执行   |
| `WARN`  | 不影响业务的警告：参数非预期、重试、配置缺省 |
| `ERROR` | 异常报错：接口异常、数据库报错、业务失败     |

**不用 yml，单独放日志配置文件**

文件位置：`src/main/resources/logback‑spring.xml` 文件名必须叫 `logback‑spring.xml`，带 spring 前缀，才能识别 `<springProfile>` 标签；

> 为什么不用 yml？滚动策略、保留天数、异步日志、自定义 pattern，yml 写起来很笨拙，企业几乎都用 xml。

## 实际开发

### 1.日志核心要点

1. **控制台输出（开发环境）**

2. **文件滚动输出（生产）**

   文件大小 + 时间双滚动

   - 例如：单个日志文件到达 100MB 拆分
   - 按天生成日志 `app‑2026‑08‑15‑0.log`

3. **日志保留周期**：保留 7‑30 天，自动删除旧日志，防止占满磁盘

4. **异步日志**：日志不阻塞业务线程（高并发必开）

5. **区分日志文件**：业务日志、错误日志单独拆分，error.log 只存 ERROR 级别，排查问题不用翻海量 info

6. **日志格式 Pattern**日志输出模板格式

### 2.标准日志模板

```
%d{yyyy‑MM‑dd HH:mm:ss.SSS} [%thread] %‑5level %logger{50} ‑ %msg%n
```

| 占位符                        | 含义                                                         | 示例                                    |
| ----------------------------- | ------------------------------------------------------------ | --------------------------------------- |
| `%d{yyyy‑MM‑dd HH:mm:ss.SSS}` | 输出日期时间，`SSS` 代表**毫秒**                             | `2026‑08‑15 22:10:33.456`               |
| `[%thread]`                   | 输出当前执行这条日志的**线程名称**                           | `[http‑nio‑8080‑exec‑1]`                |
| `%-5level`                    | 日志级别，**左对齐，占 5 个字符宽度**，用来对齐排版          | `INFO `、`DEBUG`、`ERROR`               |
| `%logger{50}`                 | 打印输出日志的**类全限定名**；`{50}` = 最多显示 50 个字符，太长会缩写包名 | `com.algoviz.controller.UserController` |
| `%msg`                        | 业务代码打印的**日志消息内容**                               | `用户登录成功`                          |
| `%n`                          | 平台兼容换行符（等价 `\n`，Windows/Linux 自动适配）          |                                         |

### 3.代码中怎么打日志（企业规范）

禁止使用 `System.out.println`！禁止 `e.printStackTrace()`！

`System.out` 和 `printStackTrace` 只输出控制台，线上环境丢失日志，没有元数据，不可配置；业务代码必须使用日志框架输出，保证日志落盘、可检索、可配置。

1. 使用占位符 `{}`，不要 `log.info("id:"+id)`，避免字符串无谓拼接。
2. 捕获异常，**一定要把 exception 对象传给 log.error**，否则没有堆栈。
3. 不要打印密码、token、手机号明文（敏感数据脱敏）。

```
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

//方式1
private static final Logger log = LoggerFactory.getLogger(OrderService.class);

//方式2 Lombok @Slf4j（项目最常用）
@Slf4j
@Service
public class OrderService {

    public void createOrder(){
        log.info("创建订单，orderId={},userId={}", orderId, userId); //占位符，不要字符串拼接
        log.warn("订单状态异常 orderId={}",orderId);
        try {
        }catch (Exception e){
            // 打印异常：第二个参数传入异常对象e，才能打印完整堆栈
            log.error("创建订单失败 orderId={}", orderId, e);
        }
    }
}

```

### 4.生成环境如何打印日志

> SpringBoot jar 包部署，**生产不打印控制台，全部输出到磁盘日志文件**。

**方式 A：直接输出到磁盘文件（传统服务器部署）**

程序输出到服务器磁盘 `/data/logs/app/*.log` 运维使用：`tail‑f`、`grep`排查。

**方式 B：容器 Docker / K8s（现在主流）**

> 容器最佳实践：**程序不要写本地磁盘文件，直接输出日志到标准输出 stdout（控制台）** Docker/K8s 捕获容器控制台输出，交给日志收集组件。

容器环境 logback 配置：只保留 ConsoleAppender，关闭文件输出。

**日志链路搜集**

```
SpringBoot应用 → stdout输出日志 → Filebeat采集日志 → 存入Elasticsearch → Kibana页面查询
```

- 应用本身只管输出原始日志，**不负责存储、不负责查询**。
- 开发人员在 Kibana 页面根据 traceId 搜索日志，不再登录服务器 grep 日志。

### 5.链路追踪

微服务多个服务调用，日志分散，需要把一次请求全链路串起来。 使用 `Sleuth / SkyWalking / MDC`，在日志 pattern 输出 `traceId`。 日志里面带上 traceId，直接搜索整条请求所有服务日志。

MDC 使用示例：拦截器拿到 traceId 放入 MDC，logback 配置打印 `%X{traceId}`。

### 6.生成实践

1. **不要把日志打数据库**：性能差，极少这么干。
2. 日志文件一定要配置自动清理，否则磁盘爆满宕机。
3. 生产禁止开启 `DEBUG`，日志量爆炸，磁盘飞快打满。
4. 敏感信息：手机号、身份证、密码不能明文输出，需要脱敏。
5. 异步日志注意：MDC 信息需要线程池传递配置，否则 traceId 丢失。

## 实践

这是 **SpringBoot 项目 Logback 日志配置文件（logback‑spring.xml）**，用来控制日志输出到控制台、本地文件，区分开发 / 生产环境，分割 info、error 日志，按文件大小滚动归档。

```
<?xml version="1.0" encoding="UTF-8"?>
<configuration>

    <property name="LOG_PATH" value="D:/rizi"/>
    <property name="LOG_PATTERN" value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"/>

    <!-- 控制台输出 Appender -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- INFO 日志 Appender -->
    <appender name="INFO_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH}/info.log</file>
        <createDirs>true</createDirs>
        <filter class="ch.qos.logback.classic.filter.ThresholdFilter">
            <level>INFO</level>
        </filter>
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
        <rollingPolicy class="ch.qos.logback.core.rolling.FixedWindowRollingPolicy">
            <fileNamePattern>${LOG_PATH}/info-%i.log</fileNamePattern>
            <minIndex>1</minIndex>
            <maxIndex>99999</maxIndex>
        </rollingPolicy>
        <triggeringPolicy class="ch.qos.logback.core.rolling.SizeBasedTriggeringPolicy">
            <maxFileSize>1MB</maxFileSize>
        </triggeringPolicy>
    </appender>

    <!-- ERROR 日志 Appender -->
    <appender name="ERROR_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH}/error.log</file>
        <createDirs>true</createDirs>
        <filter class="ch.qos.logback.classic.filter.LevelFilter">
            <level>ERROR</level>
            <onMatch>ACCEPT</onMatch>
            <onMismatch>DENY</onMismatch>
        </filter>
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
        <rollingPolicy class="ch.qos.logback.core.rolling.FixedWindowRollingPolicy">
            <fileNamePattern>${LOG_PATH}/error-%i.log</fileNamePattern>
            <minIndex>1</minIndex>
            <maxIndex>99999</maxIndex>
        </rollingPolicy>
        <triggeringPolicy class="ch.qos.logback.core.rolling.SizeBasedTriggeringPolicy">
            <maxFileSize>1MB</maxFileSize>
        </triggeringPolicy>
    </appender>

    <!-- Spring Profile 配置 -->
    <springProfile name="!prod">
        <logger name="com.algoviz" level="DEBUG" additivity="false">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="INFO_FILE"/>
            <appender-ref ref="ERROR_FILE"/>
        </logger>
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="INFO_FILE"/>
            <appender-ref ref="ERROR_FILE"/>
        </root>
    </springProfile>

    <springProfile name="prod">
        <logger name="com.algoviz" level="DEBUG" additivity="false">
            <appender-ref ref="INFO_FILE"/>
            <appender-ref ref="ERROR_FILE"/>
        </logger>
        <root level="INFO">
            <appender-ref ref="INFO_FILE"/>
            <appender-ref ref="ERROR_FILE"/>
        </root>
    </springProfile>

</configuration>

```

<?xml version="1.0" encoding="UTF-8"?>
<configuration>
```

### **2.全局变量定义 `LOG_PATH`：日志存放目录  `LOG_PATTERN`：日志打印格式**

```
<property name="LOG_PATH" value="D:/rizi"/>
<property name="LOG_PATTERN" value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n"/>
```

### **3.Appender = 日志要输出到哪里：控制台、文件、远程服务器等。**

**①控制台输出开发** 

```
<appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder>
        <pattern>${LOG_PATTERN}</pattern>
        <charset>UTF-8</charset>
    </encoder>
</appender>
```

- `ConsoleAppender`：输出日志到 IDEA / 终端控制台
- 编码强制 UTF‑8，防止中文乱码。

**② INFO_FILE 文件输出**（滚动文件）生成环境

```
<appender name="INFO_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${LOG_PATH}/info.log</file>
    <createDirs>true</createDirs>
    <filter class="ch.qos.logback.classic.filter.ThresholdFilter">
        <level>INFO</level>
    </filter>
    <encoder>
        <pattern>${LOG_PATTERN}</pattern>
        <charset>UTF-8</charset>
    </encoder>
    <rollingPolicy class="ch.qos.logback.core.rolling.FixedWindowRollingPolicy">
        <fileNamePattern>${LOG_PATH}/info-%i.log</fileNamePattern>
        <minIndex>1</minIndex>
        <maxIndex>99999</maxIndex>
    </rollingPolicy>
    <triggeringPolicy class="ch.qos.logback.core.rolling.SizeBasedTriggeringPolicy">
        <maxFileSize>1MB</maxFileSize>
    </triggeringPolicy>
</appender>
```

- `RollingFileAppender`：滚动文件，文件满了自动新建文件

- `<file>${LOG_PATH}/info.log</file>`：当前正在写的日志文件名

- `<createDirs>true</createDirs>`：目录 D:/rizi 不存在就自动创建

- `ThresholdFilter`：**大于等于 INFO 级别日志放行**（INFO、WARN、ERROR 都会进来，DEBUG 会被过滤）

- `triggeringPolicy`：触发滚动条件：**单个文件到 1MB 就切割**

- ```
  FixedWindowRollingPolicy
  ```

  ：固定索引滚动策略

  - 当前写：`info.log`
  - 满 1MB → 重命名为 `info‑1.log`，再新建 info.log 继续写；最多保留 99999 个文件。

> ⚠️注意：`ThresholdFilter` 是阈值过滤器，INFO_FILE 会同时记录 INFO/WARN/ERROR，不是只存 INFO。

**③ ERROR_FILE 只保存 ERROR 级别日志**

```
<appender name="ERROR_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <file>${LOG_PATH}/error.log</file>
    <createDirs>true</createDirs>
    <filter class="ch.qos.logback.classic.filter.LevelFilter">
        <level>ERROR</level>
        <onMatch>ACCEPT</onMatch>
        <onMismatch>DENY</onMismatch>
    </filter>
    <encoder>
        <pattern>${LOG_PATTERN}</pattern>
        <charset>UTF-8</charset>
    </encoder>
    <rollingPolicy class="ch.qos.logback.core.rolling.FixedWindowRollingPolicy">
        <fileNamePattern>${LOG_PATH}/error-%i.log</fileNamePattern>
        <minIndex>1</minIndex>
        <maxIndex>99999</maxIndex>
    </rollingPolicy>
    <triggeringPolicy class="ch.qos.logback.core.rolling.SizeBasedTriggeringPolicy">
        <maxFileSize>1MB</maxFileSize>
    </triggeringPolicy>
</appender>
```

- `LevelFilter` 精确匹配：**只接收 ERROR 级别日志，其他全部丢弃**
- 文件到 1MB 切割，生成 `error‑1.log、error‑2.log...`



### 4.springProfile：区分开发、生产环境

**非生产环境 `!prod`（dev/test 本地开发）**

```
<springProfile name="!prod">
    <logger name="com.algoviz" level="DEBUG" additivity="false">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="INFO_FILE"/>
        <appender-ref ref="ERROR_FILE"/>
    </logger>
    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="INFO_FILE"/>
        <appender-ref ref="ERROR_FILE"/>
    </root>
</springProfile>
```

- ```
  <logger name="com.algoviz" level="DEBUG" additivity="false">
  ```

  - `com.algoviz` 是你的项目包名，**自己项目代码打印 DEBUG 日志**
  - `additivity="false"`：日志不再向上传递给 root，避免重复打印
  - 输出到：控制台、info 文件、error 文件

- `root`：根日志，控制第三方包日志，级别 INFO；同样输出控制台 + 两个文件。

> 开发环境：日志同时打印控制台 + 磁盘文件。

**生产环境 `prod`**

```
<springProfile name="prod">
    <logger name="com.algoviz" level="DEBUG" additivity="false">
        <appender-ref ref="INFO_FILE"/>
        <appender-ref ref="ERROR_FILE"/>
    </logger>
    <root level="INFO">
        <appender-ref ref="INFO_FILE"/>
        <appender-ref ref="ERROR_FILE"/>
    </root>
</springProfile>
```

- 生产环境**关闭控制台输出**，只写磁盘文件；
- 业务包依然打印 DEBUG 日志到文件，第三方包 INFO 级别。

## 业务代码打印日志

1手动

```
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

@RestController
public class TestController {
    // 当前类的logger
    private static final Logger log = LoggerFactory.getLogger(TestController.class);

    public void test(){
        log.debug("调试信息");
        log.info("普通信息");
        log.warn("警告");
        log.error("异常", new Exception("出错啦"));
    }
}

```

**Lombok @Slf4j（最常用）**

pom 加入 lombok 依赖，类上加注解，直接用变量 `log`，不用手写 LoggerFactory。

```
import lombok.extern.slf4j.Slf4j;

@Slf4j
@RestController
public class TestController {
    public void hello(){
        log.info("hello algoviz");
        log.error("发生错误");
    }
}

```

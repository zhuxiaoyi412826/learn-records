## 一、文档总结

**项目画像**：AlgOJ/面试题学习平台（Spring Boot + MySQL + Redis + ES + Fluentd + Docker），本轮新开发了**审核系统**（敏感词 DFA 检测 + 审核任务队列 + ES 回写）。

**文档实际包含四块内容**：

| 板块                   | 条目数               | 性质                           |
| :--------------------- | :------------------- | :----------------------------- |
| 审核系统未闭环项       | 8 项（#1-8）         | 功能没做完，含最大安全漏洞     |
| 审核系统已实现但有缺陷 | 5 项（#9-13）        | 数据正确性/稳定性风险          |
| 项目级未完成项         | 7 项（#14-20）       | UGC 防护、部署、测试、文档     |
| 功能增强建议           | 22 项 + 三阶段路线图 | 工程质量、性能、安全、前台体验 |

**两个关键发现**：

1. **文档底部“推荐落地顺序”与正文脱节**——它只排了 22 项功能增强（异常处理、DTO/VO 等），完全没纳入审核系统的 20 个待办项。而审核系统是本轮刚做的，**带着“检测可被变体绕过”的漏洞，属于半成品**，优先级应高于任何重构类工作。

# 项目功能增加3

### 1. DTO / VO 严格分离（你刚才提的）

当前 `dto/interview/` 下混有出参 VO 类（如 `InterviewUserListVO`、`InterviewTagVO`），后续新建功能时：

- **入参 DTO** → `dto/` 统一后缀 `Request`（如 `InterviewSearchRequest`）
- **出参 VO** → `vo/` 统一后缀 `Response` 或 `VO`（如 `InterviewDetailVO`）

### 2. 全局统一异常处理 + 自定义异常体系

目前看到有零散的 try/catch，建议补齐：

- `common/exception/` 下创建 `BusinessException`（业务异常）、`UnauthorizedException`、`ForbiddenException`
- 加 `@RestControllerAdvice` 全局捕获，统一返回 `InterviewResponse<T>` 格式，避免前端看到 500 堆栈

### 3. 参数校验（JSR-303）

Controller 入参加 `@Valid` + `@NotBlank/@Size/@Min` 等注解，例如登录、注册、修改密码接口目前是手写校验，可以替换为统一注解校验 + 全局异常处理返回 400。

## 三、性能优化

### 11. 数据库索引 & SQL 慢查询监控

之前已经为几千条数据的评论做了优化，但随着数据增长：

- 打开 MySQL `slow_query_log`（阈值 1s），每周 review 一次
- 对高频接口的 SQL 做 EXPLAIN，特别是：
  - `user_solution` 按 `user_id + status` 查 → 复合索引
  - `interview_problem` 按 `category + difficulty` 筛选

### 12. Caffeine 本地缓存 + Redis 二级缓存

热点数据（面试题详情、标签、分类）加一层 JVM 本地缓存 Caffeine（10s 过期），减少 Redis 网络 IO。

### 13. 接口限流（保护后端）

对高频接口加限流：

- 登录/发送验证码接口 → 同 IP 5 次/分钟
- 提交代码 → 同用户 1 次/3 秒（避免恶意刷判题机）
- 搜索接口 → 同 IP 30 次/分钟

可以用 `Bucket4j` 或 Redis + Lua 脚本实现。

### 18. 告警

- 支付回调失败率 > 1%
- 磁盘占用 > 80%

### 19. Docker 部署补充

- `docker-compose.override.yml` 区分开发/生产环境

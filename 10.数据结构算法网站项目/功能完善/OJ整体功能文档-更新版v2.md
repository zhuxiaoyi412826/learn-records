# 第一部分：前台用户功能

## 1. 用户中心模块

1. **登录注册**
   - 账号密码、手机号/邮箱验证码、第三方（企业 SSO/LDAP/OAuth）登录、SSO单点登录
   - 个人信息：昵称、头像、岗位、部门、求职意向、编程语言偏好
   - 修改密码、邮箱/短信验证码找回
2. **个人主页**
   - 刷题总览：总题量、AC 数、通过率、提交次数、总耗时、打卡天数
   - 个人题解、提交记录公开 / 私有设置
   - 个人刷题统计图表：日 / 周 / 月刷题量，难度分布，语言分布
3. **我的收藏**：收藏题目、收藏题解
4. **错题本**：做错题目汇总，按错误类型筛选，一键重新刷题
5. **我的笔记**：针对每道题写笔记，支持 markdown，私有 / 公开
6. **账号设置**：主题切换（深色 / 浅色）、代码编辑器配置、默认语言、代码字体字号
7. **我的提交记录**：历史提交、状态筛选、按题目/语言/结果筛选【新增：筛选维度补充】

## 2. 题库模块（核心）

1. 题目列表页

   - 分页、搜索：题目名称、ID、标签搜索
   - 多维度筛选：难度（简单 / 中等 / 困难）、标签（数组、DP、二叉树、SQL、Java、Go 等）、专题分类、岗位专项（后端、测试、算法、前端）
   - 题目卡片展示：题号、标题、难度、通过率、AC 状态、标签
   - 排序：通过率、热度、题目 ID、最近更新

2. 题目详情页

   - 题干展示：描述、输入输出样例、数据范围、提示、图片
   - 多语言切换题目（可选）
   - 标签、所属专题、参考用时

3. 标签体系

   算法标签（动态规划、图论等）、企业标签、热度

4. 代码编辑器（OJ 核心交互）

   - 多编程语言切换：Java、Python、Go、C++、JS、SQL 等
   - 语法高亮、行号、自动缩进、代码补全
   - 代码模板：每个语言内置默认模板代码
   - 自定义代码片段保存
   - **代码 Diff**【新增】：与上次提交 / 历史某次提交对比，高亮差异行，方便定位改动
   - **自测用例**：自定义输入，本地运行看输出（不提交判题）
   - **提交代码**，发送到判题机
   - 提交结果弹窗：AC / WA / TLE / MLE / RE / CE，显示错误样例，输出信息
   - 历史提交记录列表：每一次提交的代码、得分、运行时间、内存消耗

5. 题解模块

   - 官方题解、用户公开题解
   - 题解点赞、收藏、评论
   - 用户可以发布自己的题解
   - 官方题解、算法提示、来源标注（支持隐藏答案模式）

6. 分类专题

   按专题/知识图谱组织，如 LeetCode 式题单

## 3. 练习模式

1. **专题练习**：按专题刷题（动态规划、链表、数据库等）
2. **专项岗位题库**：后端专项、测试专项、大数据专项
3. **闯关模式**：按关卡顺序做题，完成一关解锁下一关
4. **随机刷题**：按难度 / 标签随机抽题
5. **周打卡 / 学习计划**：企业下发学习任务，每日任务清单

## 4. 做题在线提交

| 功能 | 说明 |
| :--- | :--- |
| 在线编辑器 | 多语言支持（C/C++/Java/Python/Go 等）、代码高亮、自动补全 |
| 代码提交 | 提交、运行（Run）、提交评测（Submit） |
| 实时判题结果 | Accepted / Wrong Answer / TLE / MLE / RE / CE 等状态展示 |
| 编译错误详情 | 展示编译器错误信息、错误行定位 |
| 样例自测 | 自定义输入运行单个测试用例 |
| 草稿保存 | 云端保存未提交代码 |
| 调试辅助 | 断点/输出调试信息（可选，视企业需求） |
| 提交排队展示【新增】 | 高峰期显示「前方排队 N 个任务 / 预计等待 Xs」，由前端轮询或 WebSocket 推送 |
| 提交限流提示【新增】 | 触发提交频率限制时给出明确提示与冷却倒计时 |
| 判题进度展示【新增】 | 逐测试点显示运行状态（通过/失败/进行中），而非只给最终结果 |

## 5. 竞赛 & 考试模块（可选）

| 功能 | 说明 |
| :--- | :--- |
| 比赛列表 | 进行中、即将开始、已结束 |
| 报名参赛 | 报名、密码赛（私密赛）、团队赛 |
| 排名看板 | 实时榜单（Ranklist）、封榜机制 |
| 赛题提交 | 比赛内独立评测、罚时计算（ACM 制 / IOI 制） |
| 个人训练模式 | 模拟赛、限时训练、错题重练 |
| 成绩单/证书 | 赛后成绩、排名、电子证书 |
| 比赛倒计时【新增】 | 页面顶栏实时倒计时；最后 5 分钟醒目变色提醒 |
| 最后提交确认【新增】 | 比赛结束前 X 分钟提交需二次确认，防止误操作占用最后提交窗口 |
| 考试模式【新增】 | 定时开考、限时交卷、自动判分、成绩单；支持固定卷 / 随机组卷 |
| 考试防作弊【新增】 | 切屏检测记录、禁止复制粘贴、强制全屏、异常行为上报 |

> 考试模式与竞赛共用判题链路与榜单基础设施，差异在于：考试有及格线/总分概念、成绩对外可见性可控、需防作弊监控。

## 6. 排行榜 & 统计

1. **全局排行榜**：AC 数量、总得分、近 7 天刷题排行
2. **部门排行榜**（企业特色）：按部门维度排行，只看本企业内部人员
3. 个人统计大盘
   - 按标签统计：哪些知识点正确率低
   - 提交统计：WA/TLE 错误占比
   - 刷题日历打卡视图

## 7. 讨论社区（可选）

- 题目评论区：针对本题提问讨论
- 提问发帖，回复点赞
- 可以关闭社区（企业内网 OJ 常关闭，只允许刷题）

## 8. 消息通知

- 系统消息：考试提醒、任务通知
- 题解评论回复通知
- 站内信
- 判题完成推送【新增】：提交后无需手动刷新，判题完成主动推送结果（WebSocket / 轮询降级）

## 9. 权限隔离（企业特有）

- 用户只能看到分配给自己的题库、考试
- 外部公开题目 + 企业私有题目混合
- 部分考试仅指定部门可见

**企业版部署要点**（原散落内容整理）：

1. SSO 企业账号登录，对接企业内部组织架构
2. 部门排行榜、企业私有题库、岗位定向题库
3. 企业内部考试，权限管控，限制谁可以参加考试
4. 学习任务，管理员下发刷题任务，用户看任务清单
5. 考试防作弊相关提示（切屏检测、禁止复制）
6. 没有公开社区，大多对内，不对外暴露

## 10. 其他辅助功能

1. 导出：导出自己提交代码、导出错题
2. 草稿保存：代码自动保存，刷新页面不丢失
3. 帮助文档：判题状态说明、输入输出说明
4. 移动端适配：手机简单刷题看题

# 第二部分：后台管理功能

> 面向在线判题系统，包含：系统权限、用户管理、题目题库管理、比赛管理、提交判题管理、测评机管理、内容公告、数据统计大盘、系统配置、审计日志。适配业务：学生刷题、算法竞赛、校园 OJ / 企业内训，对接判题服务、Judge 判题机集群。

## 1. 权限账号模块（RBAC）

### 1.1 后台管理员账号

- 管理员列表：账号、姓名、角色、邮箱、手机号、状态、最后登录时间
- 操作：新增、编辑、启用 / 禁用、重置密码
- 个人中心：修改密码、个人资料

### 1.2 角色管理

预置角色：超级管理员、题库管理员、竞赛管理员、普通运营、只读审计

- 角色新增编辑，分配菜单权限、按钮权限、接口权限
- 权限粒度：题目增删改、比赛创建、数据导出、判题机配置

### 1.3 安全策略

- 登录失败锁定、密码复杂度策略
- IP 白名单，限制后台访问来源
- 操作审计日志（所有管理员操作留痕不可删除）

## 2. OJ 用户管理（C 端刷题用户）

管理所有参赛 / 刷题学生账号

1. 用户列表
   - 字段：用户 ID、用户名、昵称、邮箱、学号/工号、学院班级/部门、注册时间、总 AC 数、总提交数、状态
   - 筛选：学号/工号、用户名、时间范围、账号状态；支持导出
2. 用户详情页
   - 用户基础信息、提交记录、AC 题目列表、参与过的比赛、个人签名
3. 账号操作
   - 启用 / 封禁账号（作弊用户封禁）、重置密码、修改个人信息
   - 用户标签：标记作弊、VIP、新生等标签
4. 用户批量操作
   - 批量导入账号（校园 OJ 批量导入学生学号 / 企业批量导入工号）、批量导出用户

## 3. 题库题目管理（OJ 核心模块）

### 3.1 题目列表

字段：题目 ID、标题、难度、时间限制、内存限制、AC 数、提交数、通过率、状态、标签
筛选：难度、标签、状态、是否公开
状态：草稿、待审核【新增】、公开、私有、比赛专用（仅比赛内可见）

### 3.2 题目编辑

- 基础信息：标题、题目编号、难度、时间限制 (ms)、内存限制 (MB)、是否 SPJ 特殊判题、是否公开
- 题目内容：题干、输入描述、输出描述、样例输入输出、提示（Markdown 富文本编辑器，支持 LaTeX 数学公式）
- 标签管理：算法标签（DFS、DP、二分）、难度标签
- 测试用例管理
  - 上传 in 输入文件、out 输出答案文件
  - 批量上传测试用例、单条增删测试点
  - 设置每个测试点分值、时间 / 内存单独限制
- SPJ 特殊判题配置：上传 spj 判题程序
- 题目附件：题目素材、下载文件
- 预览：预览题目学生端页面效果

### 3.3 题目分类 & 标签库

- 分类管理：题库分类（入门、提高、竞赛真题）
- 算法标签维护，统一管理标签库

### 3.4 题目批量管理

- 批量导入题目（导入 OJ 标准数据包）、批量导出题目
- 批量修改状态、难度、标签

### 3.5 题目版本管理

- 题目修改历史记录，可回滚历史版本；记录修改管理员

### 3.6 题目审核工作流【新增】

- 流程：草稿 → 提交审核 → 审核通过发布 / 驳回（附驳回原因）
- 审核人：具备题库审核权限的管理员，与出题人分离（出题人不能审核自己的题）
- 审核要点清单：题干完整性、数据范围与测试数据强度匹配、时限内存设置合理性、样例正确性
- 修改已发布题目：默认重新走审核；紧急修复支持「热修」并强制记录审计日志
- 价值：防止低质量/错误题目直接上线引发大规模重判

## 4. 比赛 / 竞赛管理

### 4.1 比赛列表

字段：比赛 ID、比赛名称、开始时间、结束时间、报名截止、比赛状态、参赛人数、公开状态
状态：未开始、进行中、已结束

### 4.2 比赛创建 & 编辑

- 基础信息：比赛名称、简介、开始 / 结束时间、报名模式
- 报名模式：公开报名、密码参赛、白名单参赛（指定学号 / 用户才能参加）
- 比赛权限：公开比赛 / 私有内部比赛
- 排行榜配置：是否实时榜单、是否封榜时间、榜单显示规则
- 选择本场比赛题目：从题库挑选题目，设置每题分值

### 4.3 参赛人员管理

- 参赛名单列表
- 白名单导入导出；手动添加参赛选手；移除选手
- 查看选手提交记录

### 4.4 比赛榜单管理

- 实时排行榜查看
- 封榜控制：手动开启 / 关闭封榜
- 导出最终比赛榜单（成绩、排名、AC 情况，用于评奖）

### 4.5 比赛回放与数据

- 比赛提交总览，赛后可查看所有提交记录

### 4.6 考试管理【新增】

> 复用比赛模块基础设施，扩展考试特有能力

- 组卷管理：从题库选题组卷（固定卷 / 随机卷 / 分层抽题），配置总分与及格线
- 考试安排：定时开考、限时交卷、允许迟到进入与否、补考设置
- 防作弊配置：切屏次数上限、是否禁止复制粘贴、是否强制全屏、异常行为日志
- 成绩管理：自动判分、成绩单导出、成绩复议（人工复核重判）

## 5. 提交记录 & 判题管理

> 对接 Judge 判题集群，管理所有用户代码提交

### 5.1 全局提交列表

每条提交记录：提交 ID、用户、题目、语言、提交时间、判题结果、用时、内存、代码预览
判题结果：AC 正确、WA 答案错误、TLE 超时、MLE 内存超限、RE 运行错误、CE 编译错误

- 筛选：用户、题目、判题结果、语言、时间范围
- 查看源代码：预览用户提交代码
- 查看判题详情：每个测试点得分、运行时间、内存、错误信息

### 5.2 异常提交处理

- 重判功能：**单条重判、整题批量重判、比赛全部提交重判**（修改测试数据后必须重跑）
- 取消提交记录（作弊标记）

### 5.3 作弊检测模块（OJ 高频需求）

- 代码相似度检测：对提交代码查重，输出相似度报告，标记疑似抄袭提交
- 作弊标记：标记用户 / 提交为作弊，计入用户档案
- **赛中实时反作弊**【新增】：
  - 比赛进行中周期性增量查重（只对比赛内提交，滑动窗口执行，不占用正常判题队列）
  - IP / 设备聚集告警：多个账号同 IP 同设备登录答题，实时告警给管理员
  - 提交行为异常检测：短时间大量粘贴式提交、代码相似度突增
  - 告警处理：管理员可实时查看、警告、封禁选手
  - 价值：赛后查重只能追责，赛中拦截才能维护比赛公平

## 6. 测评机 (Judge) 集群管理

> OJ 特有后台，管理判题工作节点

1. 判题机节点列表
   - 节点名称、IP、状态（在线 / 离线）、当前任务数、队列积压数量、CPU / 内存负载
2. 队列监控
   - 待判题队列长度，排队任务统计
3. 节点操作
   - 启用 / 禁用判题节点；查看节点运行日志
4. 全局判题配置
   - 全局默认时间、内存限制；支持语言配置（C/C++/Java/Python 编译参数）
   - 判题安全沙箱参数配置

## 7. 公告 & 站内消息

1. 公告管理
   - 公告列表、新增编辑公告、置顶、发布 / 下线；设置生效时间
2. 站内消息
   - 给用户批量发送站内通知；消息模板管理
   - 消息发送记录

## 8. 数据大盘与统计分析

### 8.1 全局统计面板

- 总用户数、总题目数、总提交量、AC 数量
- 日提交趋势图、每日新增用户
- 判题队列积压监控、判题机负载概览

### 8.2 题库统计

- 题目通过率排行，高 WA 错题统计，分析难点题目

### 8.3 用户统计

- 用户刷题统计，活跃度统计

### 8.4 比赛统计

- 每场比赛参赛数据，得分分布

## 9. 系统配置

1. 站点配置：OJ 网站名称、页脚、注册开关、是否开放注册
2. 全局参数配置

# 第三部分：判题核心链路设计【新增】

> 判题链路是 OJ 的心脏，初版文档只描述了「提交 → 结果展示」两端，本部分补齐中间过程，是开发排期与技术选型的依据。

## 1. 判题状态机

```
PENDING（排队中）
   │ 判题机领取任务
   ▼
COMPILING（编译中）──编译失败──► CE（编译错误，终态）
   │ 编译成功（或命中编译缓存）
   ▼
JUDGING（逐测试点运行中）
   │ 测试点 1..N 依次/并发执行，每个测试点产生独立结果：
   │ AC / WA / TLE / MLE / RE / OLE（输出超限）
   ▼
FINISHED（完成，终态）
   汇总每个测试点得分 → 计算总分 → 生成提交结果

异常分支：
SE（系统错误）：判题机故障/沙箱异常，任务自动重试 1~2 次，
   仍失败则标 SE 并触发告警，用户侧提示「判题异常，可重新提交」
```

**各阶段超时阈值（兜底，防任务卡死）**：

| 阶段 | 超时阈值（参考） | 超时后处理 |
| :-- | :-- | :-- |
| 排队 | 可配置，如 10 分钟 | 通知用户稍后重试，任务废弃 |
| 编译 | 60s（可按语言配置） | 判 CE |
| 单测试点运行 | 题目时限（软超时）+ 2~3 倍硬超时 | 软超时判 TLE，硬超时强杀进程 |
| 整任务兜底 | 如 300s | 强杀并标 SE |

## 2. 输出比对策略（按题目可配置）

| 策略 | 说明 | 适用场景 |
| :-- | :-- | :-- |
| 精确比对 | 逐字节完全一致 | 严格题 |
| 忽略行尾空格 | 行尾空白不参与比对 | **默认策略**（OJ 常用） |
| 忽略行尾空格 + 文末空行 | 在上者基础上忽略文末多余空行 | 宽松默认 |
| 逐 token 比对 | 按空白切分 token 逐一比对 | 输出格式多变的题 |
| 浮点比对 | 有效数字位数 / eps 容差可配 | 计算几何、数值题 |
| SPJ 特殊判题 | 调用管理员上传的 checker 程序 | 多解、构造题 |
| 交互题（可选） | 选手程序与 interactor 程序双向通信 | 交互式题目，P2 再考虑 |

## 3. 编译缓存

- 缓存 key：`hash(语言 + 编译器版本 + 编译参数 + 源代码)`
- 命中缓存直接复用二进制产物，跳过编译阶段
- 淘汰策略：LRU + 磁盘容量上限（如单节点 20GB）
- 价值：重复提交相同代码、同模板代码（只改几行仍需重编译，但完全相同的重交很常见）、判题机重启后热身
- 注意：编译器版本升级必须失效全部缓存

## 4. 判题机调度策略

- **任务分发**：消息队列解耦（RabbitMQ / Redis Stream），Web 端只投递任务，判题机主动消费，禁止 Web 直连判题机
- **分发策略**：
  - 基础：按节点消费能力（并发槽位数）自然负载均衡
  - 进阶：同题任务亲和（同一道题路由到同一节点，复用测试数据本地缓存）
- **任务重试**：执行失败自动重试 1~2 次（换节点），仍失败标 SE + 告警
- **心跳与摘除**：判题机每 5~10s 上报心跳（含负载、队列长度）；心跳超时（如 30s）自动从调度池摘除，其未完成任务重新入队
- **队列优先级**：比赛提交 > 普通提交 > 运行自测 > 重判
  - 重判必须走独立低优先级队列并限速（如每秒最多 N 条），防止打满集群
- **数据一致性**：题目测试用例更新后版本号 +1，判题机领取任务时校验本地数据版本，不一致先拉取再判，防止新旧用例混判

# 第四部分：非功能性需求【新增】

## 1. 性能指标

| 指标 | 目标值（参考，需按实际用户量校准） |
| :--- | :--- |
| 判题响应（不含排队） | P95 ≤ 3s（不含大模拟题） |
| 排队等待 | 日常 P95 ≤ 10s |
| 提交吞吐 | 日常 50 QPS；比赛结束前 5 分钟峰值 500 QPS |
| 页面加载 | 题库列表 / 题目详情 ≤ 1s（首屏） |
| 榜单刷新 | 比赛实时榜单延迟 ≤ 5s |

> **提交洪峰专项**：比赛结束前必然出现提交尖刺，队列设计需按峰值的 3 倍冗余；榜单计算与判题解耦（榜单异步聚合，不实时全表扫描）。

## 2. 容量规划

- **代码存储**：每提交平均 2KB，10 万用户 × 人均 200 次提交 ≈ 40GB（不含索引），放对象存储/文件系统，数据库只存元数据与代码地址
- **测试用例**：单题平均 10 组用例，5000 题 ≈ 数十 GB~百 GB 级，同样对象存储 + 判题机本地缓存
- **数据库**：提交记录表为最大表，按时间分区（月分区），热数据保留 6 个月在线，冷数据归档；统计类查询走预聚合表，不做实时大表聚合
- **队列**：按峰值 3 倍冗余评估消息堆积能力

## 3. 可用性与降级

- 判题机单节点宕机：心跳摘除 + 任务自动重入队，用户无感知
- 判题集群整体故障：Web 端不受影响，可继续浏览题目、写代码、保存草稿；提交入口显示「判题服务维护中」
- 队列积压告警阈值：积压 > 1000 或预计等待 > 60s 触发告警；> 5000 自动熔断「运行自测」功能只保留正式提交
- Web 端与判题端**必须独立部署、独立扩缩容**

# 第五部分：安全专项设计【新增】

## 1. 判题沙箱规格（通用语言）

| 层面 | 措施 |
| :--- | :-- |
| 系统调用 | seccomp-bpf 白名单：禁网络（socket/connect 等）、禁写工作目录以外文件、禁加载内核模块等危险调用 |
| 进程防护 | 禁止或严格限制 fork/clone（防 fork 炸弹），子进程数上限（如 5） |
| 资源限制 | cgroup 控制：CPU 时间、内存上限、进程数、磁盘写入量 |
| 输出限制 | 输出重定向截断，超过 output limit（如 64MB）判 OLE，防止磁盘写爆 |
| 文件系统 | 每任务独立 tmpfs 工作目录，判题完成即销毁 |
| 运行身份 | 低权限专用系统用户执行（非 root） |
| 时钟防护 | 限制时间相关系统调用，防检测判题时间绕过超时 |

## 2. SQL 判题沙箱（专项）

SQL 题型无法用上述文件级沙箱，需独立方案：

- **隔离粒度**：每次判题使用独立临时数据库/schema，判完销毁；或 Docker 容器级隔离（每次判题起一次性容器）
- **权限收敛**：判题用 DB 账户仅授予目标 schema 的 DML 权限，天然禁 DROP/GRANT/TRUNCATE
- **初始化数据**：题目自带建表 + 初始数据脚本，判题前快速导入（预打快照恢复，避免每次全量执行）
- **超时控制**：语句级超时 kill（如 5s），防慢查询拖垮
- **比对方式**：比对查询结果集（排序后逐行 / 集合比对），而非比对文本

## 3. 判题机与 Web 端通信鉴权

- 判题机领取任务携带预注册 token（判题机在后台先注册，拿到唯一凭证）
- 结果回报接口验签（HMAC 或 mTLS），防伪造判题机注入虚假结果
- 判题机注册/摘除全部记入审计日志

## 4. 用户侧防护

- 提交接口限流：账号维度（如 10 次/分钟）+ IP 维度双层
- 代码长度/字符集校验，防超大 payload
- 自测运行与正式提交共享限流配额

## 5. SPJ 程序安全

- 仅题库管理员可上传，限制文件类型（源码或受信格式）与大小
- SPJ 与用户代码同样在沙箱内运行，超时同样受控
- SPJ 版本与题目版本绑定，更新走题目审核流

## 6. 工程注意事项（原踩坑扩展）

1. **重判是高危操作**：批量重判会大量打满判题机队列——走独立低优先级队列、分批执行（每批 N 条，批间隔限速）、操作二次确认、记入审计日志
2. **存储规划**：代码、测试用例文件量大，放对象存储/文件系统，不要全部塞数据库；数据库只存元数据
3. **后台不能直接操作判题机**：一律通过消息队列下发判题任务
4. **导出异步化**：导出榜单、大量提交记录走异步任务（完成后通知下载），避免大查询拖垮数据库；统计大查询走只读副本
5. **SPJ 沙箱隔离**：特殊判题程序与用户代码同等隔离（见上文 5）
6. **测试用例多节点一致性**：题目更新后版本号校验，防止新旧用例混判（见第三部分调度策略）
7. **时钟同步**：判题机全部 NTP 对时，比赛罚时/封榜/限时依赖准确时间
8. **时区处理**：比赛时间统一 UTC 存储，前端按用户本地时区展示，避免跨时区赛事事故

# 第八部分：待确认问题【新增】

开发启动前需与业务方确认：

1. **部署形态**：校园 OJ 还是企业内训 OJ 为主？两者用户模型（学号/班级 vs 工号/部门）与功能取舍（社区开关、SSO）差异较大
2. **并发规模**：目标用户量、预期同时在线、单场最大比赛人数——直接决定判题机数量与队列冗余设计
3. **部署环境**：内网私有化还是云部署？对象存储选型、是否允许 Docker（影响 SQL 判题沙箱方案）
4. **语言范围**：P0 支持哪几门语言？SQL 题是否 P0 必须（影响判题架构复杂度）
5. **比赛赛制**：ACM 罚时制还是 IOI 分数制？是否需要团队赛？

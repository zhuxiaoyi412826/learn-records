## 一、网页游戏总览

### 什么是网页游戏

**网页游戏 = 浏览器直接打开就能玩**，不用下载客户端，底层用 **HTML + CSS + JavaScript** 开发。

主流两类：

1. **2D 网页小游戏**：像素闯关、回合制、塔防、经营、横版动作
2. **3D 网页游戏**：3D 场景、角色、建模交互

### 网页游戏的优势与局限

| 维度 | 优势 | 局限 |
|------|------|------|
| 分发 | 无需安装，链接即玩 | 依赖浏览器兼容性 |
| 开发 | 技术栈统一（JS/TS），迭代快 | 无法调用底层硬件（如独占 GPU） |
| 性能 | WebGL/WebGPU 已接近原生 | 大型 3D 场景仍逊于原生引擎 |
| 商业 | H5 小游戏生态成熟（微信/抖音） | 付费转化低于原生 App |

### 网页游戏常见核心功能

1. **序列帧精灵动画**：角色行走、待机、攻击
2. **Spine 骨骼动画**：高品质角色、换装、动作混合
3. **瓦片地图**：草地、地牢、城镇地图拼接、碰撞地图
4. **角色控制**：键盘上下左右、跳跃、物理落地
5. **碰撞检测**：人物撞墙、怪物碰撞、道具拾取
6. **场景切换**：开始界面、游戏界面、结束界面
7. **音效 / 背景音乐**
8. **本地存档**：进度、金币、关卡记录

## 二、2D 网页游戏技术栈

### 1. 前端基础（必学）

- HTML、CSS
- **JavaScript ES6+**（核心）
- 异步、定时器、requestAnimationFrame、面向对象

### 2. 三大开发方案

#### 方案① 原生 JS + Canvas（零基础理解原理）

不用任何引擎，纯手写：

- 绘制图片、人物移动、碰撞检测
- 序列帧精灵动画、DOM/CSS 动画、瓦片地图

适合：练底层原理、做简单小游戏

#### 方案② PixiJS（行业首选 2D 渲染引擎）

**做商业级 2D 页游标配**

- 高性能 Canvas/WebGL 渲染
- 原生支持：**序列帧动画、Spine 骨骼动画、瓦片地图、精灵图集**
- 适配所有浏览器、性能比原生 Canvas 强很多
- 注意：PixiJS 是渲染库，物理、场景管理需自行封装或搭配 matter.js 等

#### 方案③ Phaser.js（最适合做完整游戏）

封装更完整，自带：

- 物理引擎（Arcade/Matter）、碰撞、场景管理、输入控制、音频、存档
- 直接能做：闯关、射击、RPG、塔防
- 社区活跃，插件丰富，文档完善

### 3. Phaser + TypeScript + Vite（推荐工程化方案）

**Phaser 3**：主流 2D HTML5 游戏引擎，基于 Canvas/WebGL，适合网页小游戏、像素游戏、休闲游戏

**TypeScript**：提供类型约束、智能提示，大型游戏项目更易维护

**Vite**：现代构建工具，热更新极快，替代老旧 Webpack，开发体验流畅

```bash
# 快速初始化 Phaser + TS + Vite 项目
npm create vite@latest my-game -- --template vanilla-ts
cd my-game
npm install phaser
```

项目结构建议：

```
src/
├── scenes/          # 场景（Boot, Preload, Game, UI）
├── entities/        # 游戏实体（Player, Enemy, Item）
├── systems/         # 系统（Physics, Input, Audio）
├── config/          # 游戏配置、常量
├── assets/          # 静态资源（图片、音频、地图JSON）
└── main.ts          # 入口，初始化 Phaser.Game
```

| 框架 | 定位 | 适合场景 | 特点 |

| Kaboom.js | 轻量入门 | 快速原型、教学 | API 极简，TS 友好 |
| Cocos Creator | 全能引擎 | 微信小游戏、商业 H5 | 可视化编辑器，国内生态强 |

## 四、2D 核心技术详解

### 4.1 Canvas 2D 渲染

人物和敌人的绘制用 Canvas 2D + 离屏"像素贴图"(SpriteAtlas) + 像素化渲染管线(PixelRenderer)，流程：

**1. 生成贴图（代码画出来，不是加载图片）**

- 在 render.js 里有 class SpriteAtlas
  - makePlayer()：创建 32x32 离屏 canvas，用 pxRect() 逐块画像素方块组成角色
  - makeEnemy()：同样 32x32 离屏 canvas 画敌人（不同 type 颜色/形状不同）
  - makeBoss()：64x64 离屏 canvas 画 BOSS
- 离屏 canvas 相当于"程序生成的 sprite 图片"，缓存到 renderer.atlas 复用

**2. 每帧把贴图画到游戏世界**

- 角色绘制：drawPlayer(ctx, atlas, cam, player) — 相机偏移、按瞄准方向旋转、ctx.drawImage
- 敌人绘制：drawEnemy(ctx, atlas, cam, enemy) — 选 sprite、受击闪白、血条、精英外圈特效

**3. 像素化效果（决定像素风）**

- 先画到高分辨率 hi，再缩到低分辨率 lo，最后放大回主 canvas
- PixelRenderer.render：hiCtx 画完整游戏 → loCtx.drawImage 降采样 → ctx.drawImage 放大且关闭 smoothing

### 4.2 SVG 矢量图形

SVG 不是直接画在游戏画布上，而是**先画到离屏 Canvas 上，转成位图，再当普通 Sprite 使用**。

```
SVG 文件/代码 → 离屏 Canvas 绘制 → 生成位图纹理 → 进入 SpriteAtlas → 交给 PixelRenderer 像素化渲染
```

**SVG = 无限清晰、可修改颜色、可缩放的"矢量精灵图源文件"**

代码示例：

```javascript
// 1. 创建离屏画布
const offscreen = document.createElement('canvas');
offscreen.width = 64;
offscreen.height = 64;
const osCtx = offscreen.getContext('2d');

// 2. 加载 SVG 图像
const img = new Image();
img.onload = function() {
  // 3. 把 SVG 画到离屏画布 → 变成像素图
  osCtx.drawImage(img, 0, 0, 64, 64);
  // 4. 这张 offscreen 就是像素精灵，直接进 SpriteAtlas
  ctx.drawImage(offscreen, x, y);
};
img.src = 'data:image/svg+xml;base64,...';
```

| 特性 | PNG / 像素精灵 | SVG 矢量精灵 |
|------|---------------|-------------|
| 放大 | 模糊、锯齿 | 永远清晰 |
| 修改颜色 | 要重新做图 | 代码实时改 |
| 文件体积 | 较大 | 极小（文本格式） |
| 旋转 | 画质下降 | 无损 |
| 像素化 | 本身就是像素 | 可转成像素 |
| 适合 | 人物、敌人、场景、像素风 | 武器、UI、图标、可换色部件 |

### 4.3 序列帧精灵动画

**序列帧精灵动画（Sprite Animation）** 是把多帧连续画面合并到一张精灵图集（Sprite Sheet），按时间切换显示帧，利用视觉暂留形成动画的 2D 技术。

#### 核心原理

1. **精灵图集（Sprite Sheet）**：所有帧按行列排列在一张大图，减少渲染批次与内存占用
2. **帧索引计算**：

```
frameIndex = floor(时间 × 速度) % 总帧数
col = frameIndex % 列数
row = frameIndex / 列数
```

3. **UV 采样偏移**：把纹理坐标限制在当前帧的 UV 区域，实现帧切换

#### 制作流程

1. **美术准备**：逐帧绘制动作，统一尺寸与对齐点，用 TexturePacker 打包成图集（.png + .json）
2. **代码实现**：

**方案 1：原生 Canvas 2D 版（游戏最常用）**

```html
<!DOCTYPE html>
<html lang="zh">
<head><meta charset="UTF-8"><title>序列帧精灵动画</title></head>
<body>
<canvas id="canvas" width="400" height="400"></canvas>
<script>
const canvas = document.getElementById('canvas');
const ctx = canvas.getContext('2d');

const config = {
    imgUrl: "sprite.png",
    frameW: 64, frameH: 64,
    cols: 4, rows: 4,
    fps: 10, loop: true
};

let img = new Image();
let frameIndex = 0, timer = 0;
const frameInterval = 1000 / config.fps;

img.onload = () => animate();
img.src = config.imgUrl;

function animate(timestamp = 0){
    ctx.clearRect(0, 0, canvas.width, canvas.height);
    let col = frameIndex % config.cols;
    let row = Math.floor(frameIndex / config.cols);

    ctx.drawImage(img,
        col * config.frameW, row * config.frameH,
        config.frameW, config.frameH,
        100, 100, config.frameW, config.frameH
    );

    timer += 16;
    if(timer >= frameInterval){
        timer = 0;
        frameIndex++;
        const totalFrame = config.cols * config.rows;
        if(frameIndex >= totalFrame){
            frameIndex = config.loop ? 0 : totalFrame - 1;
        }
    }
    requestAnimationFrame(animate);
}
</script>
</body>
</html>
```

**方案 2：DOM + CSS 背景图版（简单 UI / 小精灵）**

```html
<div id="sprite" style="width:64px;height:64px;background:url('sprite.png') no-repeat;"></div>
<script>
const sprite = document.getElementById('sprite');
const config = { frameW: 64, cols: 4, fps: 10 };
let frame = 0;
setInterval(() => {
    sprite.style.backgroundPosition = `-${(frame % config.cols) * config.frameW}px 0px`;
    frame++;
}, 1000 / config.fps);
</script>
```

#### 关键参数与优化

- **帧率（FPS）**：常用 10–30，动作越快帧率越高
- **图集尺寸**：2 的幂次（1024×1024 / 2048×2048），适配 GPU
- 优化：合并小图减少批次；用压缩纹理（ETC2/PVRTC）；闲置时暂停动画

#### 对比骨骼动画

- 序列帧：制作简单、性能好，适合短循环
- 骨骼：更省资源、易混合动作，适合复杂角色

### 4.4 Spine 2D 骨骼动画

Spine 是 Esoteric Software 公司开发的**专业 2D 骨骼动画编辑器**，核心是用「骨骼 + 蒙皮」替代传统序列帧，主打极小体积、极高复用、流畅动态，是手游/页游 2D 动画的工业标准。

#### 核心原理：骨骼驱动蒙皮

把角色拆成头部、躯干、四肢等独立图片（部件），创建父子层级骨骼，把部件绑定到骨骼上（蒙皮）。动画时只动骨骼，骨骼带动图片旋转/位移/变形，自动插值生成流畅中间帧。

- **骨骼（Bones）**：有父子关系，可旋转/平移/缩放
- **插槽（Slots）**：挂图片的容器，控制显示/隐藏/顺序
- **蒙皮（Skin）**：图片与骨骼的绑定关系，支持换皮肤/装备
- **关键帧（Keyframe）**：记录骨骼在某时间点的姿态，自动插值补中间帧

#### 对比序列帧

| 维度 | Spine 骨骼动画 | 序列帧动画 |
|------|---------------|-----------|
| 资源体积 | 极小（骨骼数据 + 1 张图集） | 大（每帧 1 张图） |
| 流畅度 | 极高（插值补帧，60fps） | 一般（固定帧率） |
| 复用性 | 极强（1 套骨骼做所有动作，换皮肤秒变新角色） | 极低 |
| 灵活性 | 可代码控骨骼（转头、倾斜） | 只能整帧切换 |
| 制作效率 | 高（调姿态，不用重绘） | 低（逐帧绘制） |
| 适用场景 | 手游/页游角色、动态立绘 | 简单小动画、特效 |

#### 标准制作流程（5 步）

1. **原画拆分**：按部位拆成透明底 PNG
2. **创建骨骼**：以骨盆为根骨骼，逐级建脊柱→颈→头、肩→上臂→前臂→手、髋→大腿→小腿→脚
3. **绑定蒙皮**：图片挂到对应插槽，简单部件单骨骼，复杂部件用网格+多骨骼权重
4. **制作动画**：动画模式打关键帧，曲线调节奏
5. **导出集成**：导出 JSON（骨骼数据）+ PNG（图集），导入引擎用运行时播放

#### JS 集成（PixiJS）

```javascript
import * as PIXI from 'pixi.js';
import { Spine } from 'pixi-spine';

const app = new PIXI.Application();
document.body.appendChild(app.view);

PIXI.Assets.load({
    spineData: 'character.json',
    atlas: 'character.atlas'
}).then(res => {
    const spine = new Spine(res.spineData);
    spine.position.set(400, 300);
    spine.scale.set(0.5);
    app.stage.addChild(spine);

    spine.state.setAnimation(0, 'run', true);       // 循环跑步
    spine.state.setAnimation(1, 'shoot', true, 0);  // 叠加射击
});
```

关键 API：

- `setAnimation(trackIndex, animName, loop)`：播放动画，支持多层叠加
- `mix(from, to, duration)`：动画平滑过渡
- `findBone(boneName)`：获取骨骼，代码控旋转/位移

### 4.5 图片集（SpriteAtlas）

**图片集 = 把零散小图打包成大图，减少渲染开销，让游戏更流畅、加载更快、内存更省。**

#### 组成（2 个文件）

1. **大图（.png/.jpg）**：所有小图挤在一张图上
2. **索引文件（.plist/.json/.atlas）**：记录每张小图的坐标、宽高、名字

```
火箭筒 → x:20, y:30, w:80, h:30
```

#### 为什么必须用图集

- 不用图集：100 张小图 → GPU 切换 100 次贴图 → 卡顿
- 用图集：100 张拼成 1 张 → GPU 只切换 1 次 → 流畅 60fps

#### SVG 融入图集流程

```
SVG矢量图 → 离屏Canvas → 转成1帧像素图 → 打进SpriteAtlas图集 → 交给PixelRenderer渲染
```

### 4.6 瓦片地图（TileMap）

**瓦片地图 = 用固定大小的小地形方块，重复拼接成整个游戏场景。**

#### 核心结构

1. **瓦片集（Tileset）**：一张精灵图集，放满所有地形小方块（草地、沙地、墙、水……）
2. **地图数据（二维数组）**：

```
0=空  1=草地  2=土墙  3=石头墙
[1,1,1,2,2,1]
[1,1,3,3,2,1]
[1,1,1,1,1,1]
```

#### 为什么游戏都用瓦片地图

- **省美术**：只画几十块小瓦片，拼无限大地图
- **省性能**：整张地图只用一张瓦片图集，一次贴图
- **方便碰撞**：按格子判断，不用逐像素检测
- **支持超大地图**：无限拼接，横版/俯视角/RPG 都适配

#### 制作流程

1. **制作瓦片素材**：用 Piskel / Aseprite 画 32×32 像素瓦片，或下载免费素材
2. **用 Tiled 编辑器拼地图**：新建地图 → 导入瓦片图集 → 画笔拼地图 → 设碰撞属性 → 导出 JSON
3. **Canvas 代码渲染**：

```javascript
const TILE_SIZE = 32;
const mapData = [/* 二维数组 */];

function drawTileMap(){
  for(let row = 0; row < MAP_ROWS; row++){
    for(let col = 0; col < MAP_COLS; col++){
      let tileId = mapData[row][col];
      let sx = tileId * TILE_SIZE;
      ctx.drawImage(tileset, sx, 0, TILE_SIZE, TILE_SIZE,
                    col * TILE_SIZE, row * TILE_SIZE, TILE_SIZE, TILE_SIZE);
    }
  }
}

// 碰撞检测：判断某格是不是墙
function isWall(col, row){
  if(col<0||row<0||col>=MAP_COLS||row>=MAP_ROWS) return true;
  return mapData[row][col] === 3;
}
```

### 4.7 2D 物理与碰撞

#### 常见碰撞检测方案

| 方案 | 原理 | 适用 |
|------|------|------|
| AABB 矩形碰撞 | 两矩形 x/y/w/h 重叠判断 | 最常用，适合大多数 2D 游戏 |
| 圆形碰撞 | 两圆心距离 < 半径之和 | 球类、子弹 |
| 像素级碰撞 | 逐像素 alpha 判断 | 精确但性能差，少用 |
| 格子碰撞（瓦片地图） | 按地图数组判断 | 地形碰撞，最简单高效 |
| 分离轴定理（SAT） | 多边形投影无间隙则碰撞 | 不规则多边形 |

#### Phaser 内置物理

- **Arcade Physics**：轻量，适合平台跳跃、俯视角
- **Matter.js**：完整刚体物理，适合需要真实物理效果的游戏

## 五、3D 核心技术详解

### 5.1 3D 模型在网页里的完整运行流程

1. **加载模型文件**：JS 下载 .glb → 解析顶点、三角面、纹理、材质
2. **传给显卡（GPU）**：数据传到显存
3. **3D 数学计算（每帧）**：模型位置、旋转、缩放、相机视角、光照
4. **GPU 渲染**：顶点变换 → 贴图映射 → 光照计算 → 阴影 → 像素着色
5. **输出到 canvas**：最终画到 `<canvas>` 标签

### 5.2 Three.js 极简示例

```javascript
import * as THREE from 'three';
import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth/window.innerHeight, 0.1, 1000);
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);
document.body.appendChild(renderer.domElement);

// 加载 GLB 模型
const loader = new GLTFLoader();
loader.load('model.glb', (gltf) => {
  scene.add(gltf.scene);
});

// 光照
scene.add(new THREE.AmbientLight(0xffffff, 0.5));
const dirLight = new THREE.DirectionalLight(0xffffff, 1);
dirLight.position.set(5, 10, 7);
scene.add(dirLight);

camera.position.z = 5;

function animate(){
  requestAnimationFrame(animate);
  renderer.render(scene, camera);
}
animate();
```

### 5.3 OpenGL 概念

**OpenGL 是一套「显卡绘图标准」**，让程序员可以直接指挥显卡画图、画动画、画游戏画面。

**OpenGL ES** 是 OpenGL 的精简版，给手机、平板、嵌入式、游戏框架用的。

网页端的 WebGL 就是 OpenGL ES 的 JavaScript 绑定，Three.js/Babylon.js 底层都是调 WebGL。
